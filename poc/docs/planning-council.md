# 기획 협의체 플레이북 — 기획 리부트를 위한 Fable 프롬프트 8종

> 목적: 기능이 기획을 끌고 온 지금까지(상향식)를 뒤집어, **콘셉트가 기능을 정렬하는**
> 하향식 기획을 다시 세운다. 코드는 이미 충분히 있다 — 이번엔 생각을 만든다.
>
> 사용법: 프롬프트 블록을 통째로 복사해 Claude Code 새 세션에 붙여넣는다.
> 모든 산출물은 docs/plan/ 아래 문서. **코드 수정은 전원 금지.**
> 모든 문서는 마지막에 "팀이 결정해야 할 질문" 목록을 반드시 포함한다 —
> 기획은 문서가 아니라 결정의 연속이고, 결정은 팀의 몫이다.

---

## 0. 실행 지도

```
1일차   ⓪ 기획 진단관 (단독 선행 — 모두가 이 진단서를 읽고 시작한다)
        │
2일차   ① 콘셉트 리드 (단독 — 헌장이 나와야 나머지가 정렬된다)
        │
3~4일차 ② 체험 여정 설계자 ∥ ③ 서사·세계관 감독 ∥ ④ 학습 설계가
        │
5일차   ⑤ 전시 연출가 ∥ ⑥ 제품 전략가
        │
6일차   ⑦ 통합 편집장 (전 산출물 통합 — 마스터 기획서 v2)
```

- ⓪①은 순차 필수. ②③④는 서로 다른 문서를 쓰므로 병렬 가능. ⑦은 반드시 마지막.
- 각 단계 사이에 **팀 토론 1회**를 끼운다 — 문서 끝의 "결정 질문"에 답한 뒤 다음 단계로.
- 사람의 역할: 결정. Fable의 역할: 결정을 위한 선택지·근거·초안.

## ① 콘셉트 리드 (Concept Lead) — ⓪ 정독 후 단독
**산출물**: `docs/plan/01-concept-charter.md`

```
[공통 컨텍스트]

너의 역할: 콘셉트 리드. ⓪ 진단서가 찾아낸 흔들림을 끝내는 사람. 이 제품이
무엇인지 한 문장으로 고정하고, 모든 팀원이 기능·문구·연출을 판단할 때 쓸

임무 (docs/plan/01-concept-charter.md):
1. 콘셉트 후보 3안: 각각 한 문장 정의 + 그 문장이 참이 되려면 무엇을 강화/

   구현과의 거리(무엇을 버려야 하는가)를 비교표로.
3. 권장안 하나를 고르고 그 이유를 한 단락으로 — 결정은 팀이 하지만, 기획자는

   원칙(검정=투명, 감점 아닌 관찰, 과잉 지적 금지, 폴백 우선 등)을 발굴해
   승격시키고, 부족한 원칙을 보완하라.
5. 이름·문구 감사: "4-Fit 미러팅"이라는 이름, "미러 모드" 등 핵심 용어가
   권장 콘셉트와 정렬되는지. 바꿀 필요가 있다면 후보와 함께 (리브랜딩 비용도 명시).

## ② 체험 여정 설계자 (Journey Designer) — ①과 병렬 불가, ③④와 병렬 가능
**산출물**: `docs/plan/02-visitor-journey.md`

```
[공통 컨텍스트]

너의 역할: 체험 여정 설계자. 01-concept-charter.md의 콘셉트를 기준으로,
관람객의 여정을 "부스가 보이는 순간"부터 "집에 가서 리포트를 다시 여는 순간"
까지 분 단위로 재설계한다. 화면 설계가 아니라 감정 설계다.

임무 (docs/plan/02-visitor-journey.md):
1. 여정 지도: 발견 → 대기(줄) → 진입 → 체험(5분) → 리포트 → 퇴장 → 사후(폰).
   각 구간에 [목표 감정 / 지금 제공되는 것 / 간극 / 처방]의 4행.
2. 대기줄 기획 (지금 완전히 비어 있는 구간): 기다리는 3~10분을 체험의 일부로.
   앞사람의 체험을 구경하는 것이 스포일러가 아니라 예고편이 되게 하는 방법,
   대기 중 할 수 있는 마이크로 인터랙션(종이·QR·구경 각도) 제안.
3. 감정 피크 설계: 5분 체험에서 피크는 언제이며(리액션? 결말? 점수?), 피크가
   더 높아지려면 어느 순간을 어떻게 증폭해야 하는가. 피크-엔드 법칙 기준으로
   엔드(마지막 15초)의 현재 상태 평가와 개선안.
4. 이탈 지점 설계: 중도 포기(부끄러움·바쁨)가 일어날 지점과, 포기자도 뭔가
   가져가게 하는 설계 (반쪽 리포트? 한 줄 코칭?).
5. 동반자 설계: 혼자 온 사람 vs 친구와 온 2~3인 그룹의 여정 차이. 구경꾼을
   다음 체험자로 전환하는 장치.
```

## ③ 서사·세계관 감독 (Narrative Director) — ②④와 병렬 가능
**산출물**: `docs/plan/03-world-bible.md`

```
[공통 컨텍스트]

너의 역할: 서사·세계관 감독. 현재 시드(seed_data.py)의 "클라우드밋 장애 대응의
하루"는 잘 작동하는 1편이다. 이것을 우연한 1편이 아니라 세계관의 첫 에피소드로

   (예: 비개발 직군의 하루 — 관람객 다수가 비개발자다 / 압박 면접의 날 /
   고객사 방문의 날). 각 팩의 체크리스트 축·캐릭터 재사용·제작 비용 추정.
4. 리액션·변주 대본의 확장 원칙: 케이스 5종×3변형이 반복 체험에서 소진되는
   시점 추정과, 대본 라이브러리를 몇 배로 늘릴지의 기준. LLM 개인화가 켜졌을
   때와 꺼졌을 때의 서사 품질 차이를 어떻게 관리할지.
5. 세계관의 전시 확장: 부스 자체를 클라우드밋 사무실로 만드는 아트 디렉션
   힌트(사원증 목걸이, 입사 안내문, 부스 사인) — 예산 소품 수준에서.
```

## ④ 학습 설계가 (Learning Designer) — ②③과 병렬 가능
**산출물**: `docs/plan/04-learning-design.md`

```
[공통 컨텍스트]

너의 역할: 학습 설계가 (교육공학). 이 제품의 궁극 주장은 "재미있다"가 아니라
"이걸 하면 실제로 는다"이다. 그 주장을 지탱할 학습 설계를 만든다. 심사위원
중 교육 전문가가 있다고 가정하고, 그 사람의 질문을 견디는 문서를.

임무 (docs/plan/04-learning-design.md):
1. 학습 목표 정의: 이 체험이 기르는 역량을 관찰 가능한 행동 문장으로 5개 이내
   (예: "지적을 받으면 변명 대신 사실 확인부터 말한다"). 현재 측정 35개가
   이 목표들과 어떻게 대응되는지 매핑 — 대응 없는 지표는 '관찰용'으로 격리.
2. 피드백 루프의 이론적 근거: 경험학습 사이클(Kolb), 즉시 피드백 vs 지연
   피드백, 재도전(10초 재도전)의 학습 효과를 근거로 현재 설계(체험→리포트→
   재도전)를 평가하고 보강안 제시. 근거는 교과서 수준의 정설만 사용.
3. 5분 체험의 학습적 한계 인정과 대응: 5분으로 무엇이 늘고 무엇은 늘지 않는가
   — 정직한 경계 설정. "늘지 않는 것"을 웹 모드 반복 학습이 어떻게 받는지.
4. 성장 가시화 설계: 체험 코드로 이어지는 재방문 시나리오에서 무엇을 비교해
   보여줘야 "늘었다"가 체감되는가 (총점? 압박 내성 프로파일 변화? 습관 소멸?).
5. 윤리 경계: 표정·습관 피드백이 외모 지적으로 오독되지 않게 하는 문구 원칙,
   저성과 체험자의 감정 보호 장치(현재 '아쉬움' 결말과 리포트 톤 평가 포함).
```

## ⑤ 전시 연출가 (Exhibition Producer) — ⑥과 병렬 가능
**산출물**: `docs/plan/05-booth-production.md`

```
[공통 컨텍스트]

## 부록 — 협의체 운영 수칙

1. **문서보다 결정**: 각 단계 후 팀 토론에서 "결정 질문"에 답하고 기록한다.
   답이 없는 문서는 다음 단계 입력이 될 수 없다.
2. **현물 기반**: 모든 기획자는 실제 체험(로컬 실행) 후에 쓰는 것이 이상적.
   최소한 시드 서사와 리포트 문구는 읽고 쓴다 — 상상 속 제품 기획 금지.
3. **⓪①의 권위**: 진단서와 헌장이 나온 뒤의 모든 문서는 그것을 인용하며 쓴다.
   헌장과 싸우고 싶으면 헌장 개정을 제안하지, 조용히 다른 방향으로 쓰지 않는다.
4. **구현 팀과의 경계**: 기획 리부트 중에도 8/1 데모는 지금 구현으로 간다.
   기획서가 구현을 바꾸는 것은 마스터 기획서 확정 후 — 중간에 코드를 흔들지 않는다.
```
