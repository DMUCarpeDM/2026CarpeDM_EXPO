# Response-Fit 개선 가이드 (Colab용)

## 이 문서에서 하는 일

업무 대화 답변을 0~100점으로 평가하는 Response-Fit을 더 일정하게 만드는 실험임. 전시 참가자 데이터는 쓰지 않음. AI 합성 답변과 팀이 직접 만든 답변만 사용함.

## 먼저 알아둘 점

- 지금 PoC의 기본 분석기는 `poc/backend/app/ai/response_fit.py`에 있음.
- 기본 분석기는 체크리스트 충족, 답변 길이, 존댓말, 권장 표현, 위험 표현을 봄.
- 의미가 비슷한 표현은 `semantic_match.py`에서 임베딩으로 보완함.
- 이번 실험의 목적은 기존 분석기를 버리는 것이 아니라, 기존 점수보다 덜 흔들리는 보정 방법을 찾는 것임.

## 준비할 데이터

처음에는 200개로 흐름을 확인하고, 가능하면 500개 이상 준비하면 좋음. 한 줄이 답변 하나가 되게 JSONL 또는 CSV로 정리함.

필수 칸은 아래와 같음.

| 칸 | 뜻 |
| --- | --- |
| `sample_id` | 데이터 번호 |
| `source` | `synthetic` 또는 `internal` |
| `scenario_id` | 상황 번호 |
| `prompt` | AI가 한 질문 |
| `response` | 평가할 답변 |
| `target_score` | 팀 기준 정답 점수, 0~100 |
| `reason` | 왜 이 점수인지 한 줄 설명 |
| `covered_items` | 들어간 핵심 내용 목록 |
| `missing_items` | 빠진 핵심 내용 목록 |
| `risk_labels` | 위험 표현 목록, 없으면 빈 목록 |

## 데이터 만드는 순서

1. 현재 시드의 상황을 고름. 자기소개, 장애 대응, 팀장 보고, 거절·조율처럼 서로 다른 상황을 골고루 넣음.
2. 상황마다 좋은 답변, 보통 답변, 부족한 답변을 만듦.
3. 같은 뜻이라도 말투와 길이를 바꿔 만듦. 예를 들어 결론이 앞에 있는 답변, 결론이 뒤에 있는 답변, 너무 짧은 답변을 함께 만듦.
4. 위험 표현, 지나친 사과, 반말, 핵심 누락 사례도 일부 넣음.
5. 팀이 합의한 기준으로 0~100점을 줌. 점수만 적지 말고 이유도 한 줄 적음.
6. 같은 시나리오·같은 문장이 학습과 최종 테스트에 같이 들어가지 않게 나눔.

## Colab에서 할 실험 순서

1. 데이터를 학습 70%, 보정 15%, 최종 테스트 15%로 나눔.
2. 현재 PoC 분석기를 돌려 기본 점수를 만듦.
3. 답변에서 뽑을 특징을 준비함. 기본 점수, 체크리스트 충족률, 위험 표현 수, 존댓말 비율, 답변 길이, 문장 임베딩 등을 사용함.
4. 단순 회귀 모델부터 학습함. Ridge 회귀와 트리 기반 회귀 모델을 각각 비교하면 됨.
5. 보정 데이터로 모델과 설정을 고름.
6. 최종 테스트 데이터에서 기존 분석기와 새 보정 모델의 MAE를 비교함.
7. 점수만 보지 말고 낮은 점수 사례 10개, 높은 점수 사례 10개를 직접 읽어 근거가 맞는지 확인함.

## 모델 고르는 기준

- 새 모델 MAE가 기존 분석기보다 낮아야 함.
- 위험 표현이 있는 답변을 높은 점수로 주는 사례가 늘면 안 됨.
- 특정 상황만 잘 맞고 다른 상황에서 망가지면 안 됨.
- 답변 이유를 설명할 수 있어야 함. 점수만 나오는 복잡한 모델은 나중에 검토함.

## 이번 단계에서 하지 않는 것

- 대형 언어 모델 LoRA 파인튜닝 바로 시작하지 않음.
- 전시 참가자 답변을 저장하거나 학습에 쓰지 않음.
- Eye-Fit, Voice-Fit 점수는 건드리지 않음.
