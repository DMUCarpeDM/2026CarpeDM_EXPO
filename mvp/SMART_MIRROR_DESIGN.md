# Mirror-Ting Design System — Smart Mirror / Silver Glass

## 0. 적용 범위

이 문서는 **현재 Mirror-Ting 스마트미러의 구현 기준**을 정의한다. 기준일은 2026-10-13이며, 로컬 작업본의 최신 화면을 포함한다. 문서의 모든 내용이 원격 배포되었다는 의미는 아니다.

- 형식은 웹 서비스의 [DESIGN.md](./DESIGN.md)를 따라 적용 범위 → 원칙 → 색상 → 타이포그래피 → 간격 → 레이아웃 → 컴포넌트 → 자산 → 사용 규칙 → CSS → 시뮬레이션 순서로 구성한다.
- 대상은 `?mirror=1&service=workplace`의 NFC 대기, 요약, 음성 확인, 장면 안내, 직장 대화 시뮬레이션, 결과 화면이다.
- 웹 서비스의 흰 배경·Apple Blue 기준과 구분한다. 이 문서의 수정만으로 제품 CSS나 동작을 변경하지 않는다.
- 색상·간격 중 CSS 변수로 존재하는 값과 선택자에 직접 선언된 값을 구분한다. 아직 없는 토큰을 구현된 것으로 기재하지 않는다.
- 분석 모델과 점수 산식은 별도 영역이다. 이 문서는 측정 상태·참고 점수의 표시 방식만 다룬다.

## 1. 디자인 원칙

Mirror-Ting 스마트미러는 검정 캔버스와 실버 글래스 위에 안내를 배치하고, 대화 중에는 영상과 자막을 중심으로 보여준다.

1. 대기·안내 화면에서는 하나의 메시지와 다음 행동을 명확하게 보여준다.
2. 글래스는 안내 카드·모달·상태바에 사용한다. 자막을 카드로 감싸지 않는다.
3. 시뮬레이션 영상은 화면 전체를 채운다. 양옆에 다른 장면이나 검정 띠를 덧붙이지 않는다.
4. 자막은 중간 굵기와 자연스러운 행간을 사용한다. 입체적인 외곽선이나 강한 다중 그림자를 피한다.
5. 상태는 색상과 문구로 함께 전달한다. 녹음·카메라 동작 상태를 사용자에게 숨기지 않는다.
6. 타이틀, 대화 자막, 상태 표시의 위치를 독립적으로 관리한다.
7. 측정 불가와 검증 전 참고 결과를 확정된 평가처럼 표현하지 않는다.

## 2. 색상

### 2.1 핵심 토큰과 적용 값

8자리 HEX의 마지막 두 자리는 알파값이다.

| 역할 | 현재 선언 | 값 | 사용 |
|---|---|---|---|
| 기본 캔버스 | `background` | `#000000` | NFC·요약, 미러 바깥 영역 |
| 기본 텍스트 | `--ink` | `#f5f7fc` | 어두운 표면의 제목·본문 |
| 보조 텍스트 | `--muted` | `#c6cdd8` | NFC·요약·결과 설명 |
| 시뮬레이션 보조 텍스트 | 해당 화면의 `--muted` | `#e0e5ef` | 영상 위 상태·보조 안내 |
| 기본 표면 변수 | `--surface` | `#070b1205` | 화면 범위의 표면 기준값 |
| 구분선 | `--divider` | `#ffffff24` | 카드 안 정보 구분 |
| 자막 | `color` | `#ffffff` | 현재 발화 문장 |
| 진행선 | `background` | `#d8edff` | 자막 발화 진행 표시 |

| 음성 확인 오류 | `color` | `#ffcfb8` | 어두운 모달의 오류 설명 |

### 2.2 강조색 역할 구분

- 은백색은 제목, 글래스 반사, 결과 그래프 등 공통 시각 요소에 사용한다.
- 옅은 파란색 `#c5dfff`는 어두운 표면의 안내 배지·마이크 아이콘에 사용한다.
- 짙은 파란색 `#075985`는 밝은 상태바 안의 활성 상태에 사용한다.
- 빨간 점은 녹음 동작을 나타낸다. 오류 여부는 별도 문구로 알린다.
- 밝은 영상 위에 옅은 글자만 올리지 않는다. 상태바는 밝은 표면과 짙은 콘텐츠를 함께 사용한다.

## 3. 타이포그래피

### 3.1 글꼴

현재 미러 화면은 다음 스택을 직접 선언한다.

```css
font-family: 'Apple SD Gothic Neo', 'Noto Sans KR', Arial, sans-serif;
```

기기에서 사용 가능한 글꼴에 따라 대체된다. SF Pro·Pretendard가 미러의 기본 글꼴로 선언되어 있다고 가정하지 않는다.

### 3.2 타입 스케일

아래 `u`는 `var(--u)`를 뜻하는 문서 표기다. 실제 CSS에서는 `calc()`와 함께 사용한다. 기본 rem이 16px일 때만 표의 px 환산이 성립한다.

| 역할 | 크기 | 줄 높이 | 굵기·자간 |
|---|---|---|---|
| 브랜드 | `max(1rem, 1.7u)` | 상속 | 500 / −.035em |
| NFC 제목 | `max(1.5rem, 2.7u)` | 1.45 | 제목 기본 굵기 / −.04em |
| NFC 설명 | `max(1rem, 1.6u)` | 1.75 | 본문 기본 굵기 |
| NFC 동의 안내 | `max(.875rem, 1.25u)` | 1.7 | 본문 기본 굵기 |
| 요약 카드 제목 | `max(1.25rem, 2u)` | 1.5 | 600 / −.025em |
| 음성 확인 제목 | `max(1.375rem, 2.35u)` | 1.4 | 공통 카드 제목 굵기 |
| 시뮬레이션 자막 | `max(1.375rem, 2.3u) + 16px` | 1.65 | 500 / −.02em |
| 시뮬레이션 보조 안내 | `max(.8125rem, 1.2u)` | 1.6 | 기본 굵기 |
| 상태바 | `max(.875rem, 1.1u)` | 1.5 | 600 |
| 결과 제목 | `max(1.5rem, 2.8u)` | 1.4 | 제목 기본 굵기 / −.04em |
| 결과 점수 | `max(1.5rem, 3.5u)` | 1.2 | strong 기본 굵기 |

- 한국어는 `word-break: keep-all`을 우선한다. 자막의 긴 단어는 `overflow-wrap: anywhere`로 처리한다.
- 자막의 `+16px`는 확대 비율이 아니라 기존 반응형 크기에 더하는 고정 증분이다.
- 자막 최소 크기는 기본 rem 16px 기준 38px이다. 1080×1920 화면에서는 약 60.16px이다.
- 자막 그림자는 `0 1px 2px #000a, 0 0 6px #0005`이며 글자 외곽선은 사용하지 않는다.

## 4. 간격과 형태

### 4.1 간격

```css
--u: min(1dvh, 1.77778vw);
```

세로 화면을 기준으로 화면 높이와 폭 중 작은 쪽에 맞춰 크기를 정한다. 1080×1920에서는 1u가 약 19.2px이다.

| 위치·역할 | 현재 값 |
|---|---|
| NFC·요약·결과 바깥 여백 | 세로 `3.3u`, 가로 `3.6u` |
| NFC 본문 위·아래 패딩 | 위 `2u`, 아래 `5u` |
| NFC 아이콘 폭 | `27.72u` |
| NFC 아이콘과 설명 카드 사이 | `7u` |
| NFC 카드 내부 패딩 | `3u` |
| 음성 확인 카드 내부 패딩 | `3u` |
| 결과 카드 내부 패딩 | `2u` |
| 상태바 내부 패딩 | 세로 `.65u`, 가로 `1.2u` |
| 상태바 항목 간격 | `.9u` |
| 자막 문장 아래 여백 | 패딩 `.15em`, 마진 `.2em` |

### 4.2 모서리와 그림자

| 역할 | 값 |
|---|---|
| 공통 글래스 카드 | `1.8u` |
| 상태바 | `2u` |
| 사용자 영상 | `1.8u` |
| 배지·진행 막대 | `999px` |
| 자막 | 배경 카드·모서리 없음 |
| 글래스 블러 | `16px`, 채도 `105%` |
| 모달 바깥 배경 | `#03060b99`, 블러 `8px` |

글래스의 얇은 반사 테두리와 내부 그림자는 공통 카드 CSS를 재사용한다. 상태바만의 불투명한 검정 카드로 바꾸거나 흰색 글자를 밝은 표면 위에 그대로 놓지 않는다.

## 5. 레이아웃

### 5.1 페이지 구조

- NFC·요약·결과는 `min(100%, 56.25dvh)` 폭의 세로 화면을 기본으로 한다. 화면별 반응형 규칙이 우선한다.
- NFC 브랜드 타이틀은 상단에 유지한다. 본문과 모달의 `−3u` 이동 규칙에 브랜드를 포함하지 않는다.
- NFC 본문은 수직 자동 여백을 사용한다. 도시 이미지는 대기·안내 화면의 배경 자산으로 사용한다.
- 시뮬레이션은 폭 `100%`, 높이 `100dvh`로 표시한다.
- 영상은 `object-fit: cover; object-position: center top`으로 화면을 채운다. 비율 차이는 크롭으로 처리하며 얼굴이 있는 상단을 우선 보존한다.
- 시뮬레이션 뒤의 별도 장면 이미지는 제거된 상태다. 전환 중에도 같은 영상 계층 안에서 처리한다.

### 5.2 표면과 깊이

1. 검정 캔버스 또는 전체 화면 영상
2. 안내·결과를 담는 실버 글래스 카드
3. 영상 위 독립 자막과 사용자 영상
4. 우하단 밝은 글래스 상태바
5. 준비 단계에서 사용하는 공통 글래스 모달

자막 뒤에 넓은 사각형 패널을 추가하지 않는다. 자막과 상태바는 서로 다른 목적의 요소로 분리한다.

## 6. 공통 컴포넌트

### 6.1 NFC 시작 아이콘

- `WorkplaceMirrorNfcWaitingPage`의 실버 글래스 PNG 버튼을 사용한다.
- 이미지 자체는 장식 이미지이며 버튼에 시작 행동의 접근성 이름을 제공한다.
- 분석·저장 안내는 설명 카드에 표시한다.
- 키보드 포커스는 `2px` 밝은 외곽선, 오프셋 `8px`로 표시한다.

### 6.2 공통 실버 글래스 카드

- `WorkplaceOverviewCard`와 `.overview-summary-card`를 기준으로 한다.
- 다층 방사형·선형 그라데이션, 블러, 반사 테두리, 내부 그림자를 결합한다.
- NFC·요약·결과·모달에서 같은 표면을 공유하고 내부 간격만 화면별로 조정한다.

### 6.3 상태 배지

- `.overview-scene-badge`: 패딩 `.25u .8u`, 반지름 `999px`, 얇은 구분선.
- NFC 대기, 대화 준비 등 짧은 상태만 담는다.

### 6.4 화면 진행 표시

- 요약 화면은 단계 라벨과 진행선을 사용한다.
- 음성 확인은 시간이 지났다는 이유로 성공 처리하지 않는다.
- 진행 중·완료·실패를 실제 처리 상태와 일치시킨다.

### 6.5 공통 글래스 모달

- `MirrorGlassModal`을 사용한다.
- 장면 안내와 음성 확인은 공통 표면을 사용한다.
- 모달이 열렸을 때 뒤쪽 대화 자막을 숨겨 안내가 겹치지 않게 한다.

### 6.6 사전 음성 확인

- 주변 소음 2초, 안내 문장 읽기 4초를 순서대로 녹음한다.
- 서버의 발화·녹음 품질 확인 성공 후에만 시뮬레이션으로 진행한다.
- 실패하면 이유와 “마이크 다시 확인” 버튼을 표시한다.
- 이는 녹음 품질·발화 확인이며, 안내 문장을 정확히 받아썼다는 보장은 아니다.

### 6.7 대화 자막

- `MirrorSubtitles`를 사용한다.
- 현재 문장은 선명하게, 이전 문장은 불투명도 `.45`로 표시한다. 아직 말하지 않은 문장은 숨긴다.
- 발화 진행선과 문장 포커스는 전달된 재생 상태·문자 위치를 따른다.
- 카드 없이 텍스트와 얇은 그림자만 사용한다.

### 6.8 녹음·카메라 상태바

- `MirrorCaptureStatus`를 사용하며 `role="status"`, `aria-live="polite"`로 상태를 전달한다.
- 녹음 중, 녹음 대기, 녹음 오류, 카메라 분석 중, 준비 중, 꺼짐, 오류를 문구로 구분한다.
- 미리보기는 “미리보기 · 녹음 안 함”을 표시한다. 실제 동작을 가장하지 않는다.
- 밝은 실버 글래스 바탕, 짙은 글자, 빨간 녹음 점, 짙은 파란 활성 아이콘을 사용한다.

### 6.9 사용자 영상·추적

- `.simulation-user-preview` 안에 실제 카메라 영상과 추적 캔버스를 겹친다.
- 영상과 캔버스에 같은 좌우 반전을 적용한다.
- 입력이 없으면 카메라 꺼짐 상태를 표시한다.

### 6.10 오류 안내

- 시뮬레이션 중 음성 인식 실패는 “음성 인식에 실패했어요. 다시 실행해 주세요.” 문구로 안내한다.
- 이 위치의 재연결 카드, 직접 입력창, 전송 버튼은 제거된 상태다.
- 사전 음성 확인 모달의 재시도 버튼과 구분한다.

### 6.11 결과 카드

- 총점 요약, 영역별 기록, 피드백, 표현 개선을 글래스 표면 안에 계층화한다.
- 측정 자료가 없는 영역을 임의의 0점이나 기본 점수로 표시하지 않는다.
- 검증 전 표정 기반 점수는 참고 결과임을 구분한다. 목소리 측정값과 확정 점수를 혼동하지 않는다.

## 7. 이미지와 아이콘

- NFC는 `src/assets/nfc-silver-glass.png`를 사용한다.
- 안내 화면은 `features/smart-mirror/assets`의 실버 글래스 자산을 사용한다.
- 대화 영상은 `src/data/characterMedia.js`의 캐릭터·장면 매핑을 따른다.
- 영상에 포함된 배경과 별도 배경 이미지를 양옆에 혼합하지 않는다.
- 상태 아이콘은 현재 색상을 따르는 선형 SVG와 CSS 점·파형을 사용한다.
- 녹음·카메라·준비 같은 기능 설명 없이 장식 아이콘을 추가하지 않는다.

## 8. 사용 규칙

### Do

- 제품 컴포넌트와 공통 글래스 CSS를 재사용한다.
- 밝은 상태바에는 짙은 텍스트, 어두운 카드에는 밝은 텍스트를 사용한다.
- 짧은 문장과 단계별 안내로 서 있는 사용자의 읽기 부담을 줄인다.
- 긴 자막, 밝은 영상, 실제 디스플레이 비율에서 가독성과 크롭을 확인한다.
- 녹음·카메라·오류를 문구와 시각 신호로 함께 표현한다.
- 모션 감소 설정과 키보드 포커스를 유지한다.

### Don't

- 웹 서비스의 흰 캔버스·파란 기본 버튼 규칙을 미러 전체에 일괄 적용하지 않는다.
- 자막을 두꺼운 외곽선·과한 굵기·큰 문장 간격으로 덩어리처럼 만들지 않는다.
- 글래스 카드에 또 다른 글래스 카드를 중첩하지 않는다.
- 영상의 빈 부분을 다른 장면이나 검정 띠로 채우지 않는다.
- 시간이 지났다는 이유로 음성 확인을 건너뛰지 않는다.
- 참고 결과나 미리보기 상태를 실제 측정 완료처럼 표현하지 않는다.

## 9. CSS 기준 토큰

### 9.1 현재 화면 범위 변수

--u: min(1dvh, 1.77778vw);

--muted: #c6cdd8; /* 시뮬레이션에서는 #e0e5ef */

## 10. 시뮬레이션 화면 — 현재 적용 기준

### 10.1 상태와 적용 범위

직장 대화 스마트미러의 `WorkplaceMirrorSceneSimulation`에 적용한다. 일반 웹 연습 화면과 면접·카페 전체가 동일한 미러 레이아웃이라는 의미는 아니다.

### 10.2 시각적 방향과 배치

| 요소 | 현재 배치 |
|---|---|
| 화면 | 폭 100%, 높이 100dvh |
| 상대 영상 | 전체 화면 cover, 상단 중앙 기준 |
| 자막 영역 | 왼쪽 5%, 위 30%, 폭 54%, 최대 높이 56% |
| 작은 화면 자막 | 폭 ≤700px 또는 높이 ≤700px에서 위 28%, 폭 59% |
| 사용자 영상 | 오른쪽 4%, 아래 11%, 폭 26%, 높이 26% |
| 상태바 | 오른쪽 3.6u, 아래 3.3u |

자막 영역은 내용이 높이를 넘으면 세로 스크롤된다. 글자 크기 확대 이후에는 실제 화면에서 긴 대사의 잘림·스크롤 필요 여부를 확인한다. 영상 전체를 채우는 조건과 전신이 모두 보이는 조건은 화면 비율에 따라 동시에 성립하지 않을 수 있다.

### 10.3 모션·가독성·접근성

- 자막 등장: 160ms. 숨김·종료 전환: 240ms.
- 문장 포커스: 180ms, 최대 4px의 작은 수직 이동.
- 진행선: 180ms 선형 전환. 기준 이징은 `cubic-bezier(.23, 1, .32, 1)`이다.
- 모달 등장: 220ms, 12px 수직 이동과 페이드.
- 모션 감소 설정: 자막 이동 제거, 120ms 페이드. 모달은 150ms 페이드.
- 텍스트만 표시하는 재생 불가 상태에서는 자막을 보이게 유지한다.
- 대비 수치 인증이나 투명도 감소·블러 미지원 환경의 완전한 대응이 검증된 것으로 간주하지 않는다. 현재 CSS와 별개로 해당 환경에서 확인해야 한다.

### 10.4 구현과 검증 기준

- 화면 전용 CSS는 `features/smart-mirror/styles`에 둔다. 웹 공통 스타일을 바꿔 미러 문제를 해결하지 않는다.
- 출근·업무·퇴근 영상에서 빈 띠, 얼굴 크롭, 자막 대비를 확인한다.
- 실제 세로 디스플레이와 폭이 다른 미리보기 창을 모두 확인한다.
- 현재·이전·대기 문장, TTS 종료, 재생 불가 상태를 각각 확인한다.
- 녹음·대기·오류·카메라 꺼짐을 실제 입력 상태와 맞춰 확인한다.
- 음성 확인 실패·지연 때 진입이 차단되고, 성공 후 진행되는지 확인한다.
