# Mirror-Ting 프론트엔드 QA — 2026-10-01

## 판정과 범위

**검증한 프론트엔드 수정 범위는 승인. 실제 서비스 전체의 출시 승인은 아님.**

React/Vite `mvp`의 모든 페이지 컴포넌트를 조사하고 사용자 진입 화면을 브라우저에서 확인했다. 실제 백엔드가 실행되지 않아 실제 연습 생성·AI 분석·저장·공유·NFC 발급 성공까지 검증하지는 못했다. 정적 데모, 모의 API 테스트, 실제 API 연결 실패를 분리했다. `poc/frontend`와 운영 대시보드는 이번 수정 대상이 아니다.

기존 로고, 3컬럼 이미지, 직무·난이도·시나리오·4-Fit 이미지, Hero 도트/포인터 그라데이션, 푸터와 디자인 토큰을 유지했다. API 계약과 평가 로직은 변경하지 않았다. 사용자 작업 중인 문서 삭제와 중복 파일은 커밋 대상에서 제외한다.

## 사용한 기준과 레퍼런스

- `better-interface`와 accessibility/layout/writing/typography/colors/ui 하위 스킬: 시각적 취향보다 접근성, 행동의 의미, 정보 위계, 재현 가능한 근거를 우선했다.
- [Awwwards](https://www.awwwards.com/): 메인 페이지의 큰 제목과 대표 콘텐츠 중심 위계를 참고했다. 작품별 디자인을 복제하지 않았다.
- [Minimal Gallery](https://minimal.gallery/): 메인 갤러리의 규칙적인 그리드, 간결한 캡션, 정보 간 여백을 참고했다.
- 레퍼런스의 수상 여부나 외관을 접근성 검증 근거로 사용하지 않았다.
- Lazyweb 도구는 현재 세션에 없어 검색/리포트 URL을 생성하지 못했다. 외부 설치 스크립트를 실행하지 않고 직접 사이트 확인과 로컬 QA로 대체했다.

## 자동 검증

- `npm run build`: 통과. 500kB 초과 번들 경고는 남음; 이번 QA에서 추측으로 성능 최적화를 하지 않았다.
- `npm test`: 실행했으나 동시 브라우저 실행 중 시간 초과/정리 대기 발생. 권한 없는 첫 실행의 로컬 포트 오류와도 구분했다.
- 같은 전체 테스트를 `node --test --test-concurrency=1 src/lib/*.test.js`로 재실행: **160개 중 158 통과, 2 실패**.
- 실패 2개는 `src/lib/kioskLayout.test.js`의 오래된 소스 계약 검사다. `HEAD` 원본을 별도 임시 폴더에 export해서도 동일 실패를 재현했다.
  - 삭제/교체 전 `setup-icons/job-developer.webp` import를 요구함.
  - 이전 홈의 `ProductStage` 함수 선언을 요구함.
- 해당 두 검사의 오래된 계약은 이번 화면 수정과 관계없어 임의로 통과시키지 않았다. 실제 페이지 이미지 로드와 빌드는 정상이다.
- 서비스 선택 테스트는 숨긴 h1과 navigation button의 의미에 맞춰 갱신했다. 서비스 경로 테스트의 이전 `.hero-actions` 선택자는 현재 `.studio-hero__actions`로 갱신했다.
- 새 `interfaceQa.browser.test.js`: 모바일 문서 폭, 단일 main/h1, 종료창 키보드 순환/포커스 복귀, reduced-motion 자동 전환 정지 검증. 통과.
- 기존 서비스 선택/뒤로 이동/리셋/데모/세션 복원, 음성 보정, 음성 보고서, 직장대화 브리핑, 전사 수명주기, 연습 종료 테스트 통과. API와 입력 장치는 테스트용 모의 응답/합성 입력이며 실제 백엔드 통과를 뜻하지 않는다.

## 미검증·남은 위험

- 실제 AI 서버, 녹음 장치, MediaPipe/Kinect 정확도, NFC 카드 발급 성공, 실제 저장·공유/PDF와 장시간 운영.
- 실제 모바일 기기의 터치·가상 키보드, Safari/Firefox, 스크린리더 낭독, 200% 브라우저 확대, RTL. 반응형 폭 검사만으로 이 항목들을 통과했다고 판단하지 않았다.
- 투명도·이미지·그라데이션 위 모든 색 조합, 모든 hover/focus/disabled 조합의 완전한 WCAG 인증은 아님.
- 전체 테스트를 기본 동시 실행 방식으로 안정적으로 완료하는 문제와 오래된 소스 계약 2개는 별도 정비 대상.
- 다음 단계는 백엔드와 장치를 연결한 세 서비스의 실제 연습→결과→저장 E2E 및 실기기 QA다.
