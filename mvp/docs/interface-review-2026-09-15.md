# 화면 간격·타이포그래피 검토 — 2026-09-15

## 범위

원격 main의 모션 개선 커밋 `64c9aa7` 반영 후 현재 화면 흐름을 검토했다. 모드 선택, 면접·직업훈련·직장대화 첫 화면, 사이트 소개, 사용방법과 FAQ 펼침, 결과 및 기록의 빈 상태, 모바일 메뉴가 대상이다. 이번 변경은 검토 문서만 추가한다. 아래 개선안은 아직 화면에 적용하지 않았다.

React/Vite, CSS 사용자 정의 속성, 로컬 shadcn/Radix 컴포넌트가 사용된다. `CLAUDE.md`, `mvp/DESIGN.md`, `mvp/design-qa.md`와 현재 CSS를 참고했다. DESIGN.md는 목표 규격이므로 문서와 수치가 다르다는 이유만으로 오류로 판정하지 않았다. better-interface의 접근성·레이아웃·문구·타이포그래피·색상·UI 기준을 적용했다.

## 검증 기록

- `http://127.0.0.1:5173/`에서 모드 선택 → 면접 → 사이트 소개 → 사용방법 → FAQ 펼침을 확인했다. 별도 도입 화면 없이 선택한 모드로 진입했다.
- 1280px와 320px 구간에서 소개·사용방법의 DOM 폭과 실제 줄바꿈을 측정했다. `document.documentElement.scrollWidth`가 `innerWidth`를 초과하지 않았다.
- 결과 빈 상태는 실제 약 355px, 직업훈련은 약 355px/1422px, 직장대화는 약 1422px에서 확인했다. 이 구간을 320px 통과로 간주하지 않았다.
- 모바일 메뉴 열기 → Escape: 열린 상태가 유지됐다. 메뉴의 사용방법 버튼 → Tab: `document.activeElement`가 배경의 “연습 시작하기”였으며 dialog 내부가 아니었다.
- 소개 본문 `#707070`과 흰 배경의 대비는 약 4.95:1로 일반 텍스트 4.5:1 기준을 충족한다. 제목·버튼·비활성 상태 전체를 대표하는 결과는 아니다.
- 브라우저의 임시 viewport 설정은 검토 후 해제했다.
- 이전 모션 작업에서 빌드와 143개 테스트가 통과했다. 이번에는 문서만 추가하므로 재실행하지 않았다. 이 테스트 결과가 시각적 품질이나 접근성 통과를 의미하지는 않는다.

## 판정

**Block** — 확인 범위에 HIGH 접근성 문제가 남아 있다. 전시 배포 전 모바일 메뉴 포커스 문제를 수정해야 한다. 이 판정은 현재 화면 검토에 대한 것으로, 이번에 푸시한 모션 커밋이 해당 문제를 새로 만들었다는 뜻은 아니다.

## 후속 수정 완료

사용자 요청에 따라 위 확정 항목 3건을 수정했다. 앞의 Before와 Block은 수정 전 기록이다.

- 안내 h1을 32~44px, 굵기 560으로 조정했다. 긴 소개 제목에는 1.4 행간을 적용했다. 320px 실제 화면에서 32px/44.8px로 표시되며 가로 넘침이 없다.
- 모바일 메뉴를 기본 HTML dialog의 showModal/close로 전환했다. 별도 의존성을 추가하지 않았다. 열 때 닫기 버튼으로 이동하고, Tab/Shift+Tab을 메뉴 안에서 순환시킨다. 배경은 브라우저의 모달 처리로 조작할 수 없으며 Escape와 메뉴 선택으로 닫힌다. Escape 후 메뉴 열기 버튼으로 포커스가 복귀하는 것을 브라우저에서 확인했다.
- 소개·기록·사용방법의 개발 진행 문구를 사용자 안내로 교체했다. 기록 조회를 이미 지원하는 것처럼 약속하지 않으며, 음성·대화의 서버 전송 가능성을 알린다. 전송 근거는 pocApi.js의 submitResponse 오디오 업로드 경로다.
- 기존 페이지 폭과 패딩은 유지했다. 데스크톱 드롭다운과 원래 Not verified 범위는 이번 수정 대상에 포함하지 않았다.

수정 범위 재검증: 모바일 메뉴 열기·Tab 순환·Escape·포커스 복귀·사이트 소개 이동 통과, 320px 소개 제목 및 가로 폭 통과, Vite 빌드 통과. 기존 번들 크기 경고는 남아 있다.

기존 `npm test`도 143개 모두 통과했다. 최초 제한 환경에서는 브라우저 테스트를 완료하지 못해 Chrome 실행이 가능한 환경에서 재실행했다. 확정 항목 3건의 수정 범위는 **Approve**이며, 전체 제품 접근성 승인을 의미하지 않는다.
