# Mirror-Ting 3개 Home 장문 랜딩 개편 설계

## 1. 목표

면접, 직업훈련, 직장대화 Home을 PLCO Coach의 장문 제품 소개 방식처럼 개편한다. 사용자가 스크롤하며 각 모드의 강점과 실제 사용 흐름을 이해하도록 `핵심 메시지 → 제품 화면 → 구체적 효과`를 반복한다.

이번 작업은 현재 Apple Light 디자인시스템과 Shadcn 기반 컴포넌트를 유지한다. 새로운 라우트나 실제 시뮬레이션 화면은 만들거나 변경하지 않는다.

## 2. 성공 기준

- 3개 Home이 각각 7개 안팎의 명확한 섹션으로 구성된다.
- 첫 화면 아래에서도 제품의 강점과 실제 사용 장면이 계속 이어진다.
- 각 주요 설명 섹션에 서비스 UI 또는 상황 이미지가 포함된다.
- 세 Home은 같은 디자인시스템을 사용하지만 섹션 순서와 레이아웃이 서로 다르다.
- 데스크톱과 모바일에서 콘텐츠가 잘리거나 겹치지 않는다.
- 현재 CTA와 모드별 다음 단계 이동이 그대로 동작한다.
- 기존 테스트와 빌드가 통과하고, 시각 QA 결과가 `passed`이다.

## 3. 범위

### 포함

- `HomePage.jsx`의 세 모드 Home 구조 재배치
- 장문 랜딩용 공통 섹션 프리미티브 추가
- 기존 서비스 UI 컴포넌트의 확대·재배치
- 모드별 실제 사용 장면 이미지 최대 1장 추가
- Home 전용 반응형 스타일과 레이아웃 테스트 보강

### 제외

- `PracticePage`와 실제 시뮬레이션 로직 변경
- 신규 페이지나 라우트 추가
- 인증, 저장, 결제 또는 백엔드 기능 추가
- 디자인 토큰, 브랜드 색상, 글꼴 체계 변경
- 장식용 아이콘 세트 또는 캐릭터 이미지 생성

## 4. 디자인 원칙

1. PLCO Coach에서 긴 스크롤, 넓은 제품 화면, 짧은 강점 메시지의 반복 구조만 가져온다.
2. 검은 테마를 복제하지 않고 White, Frost, Ice 표면을 교차 사용한다.
3. 제품 UI가 가장 강한 시각 요소가 되며, 사진은 맥락 설명에만 사용한다.
4. 섹션당 하나의 핵심 메시지와 하나의 시각 자료를 둔다.
5. 카드 내부에 다른 카드를 반복 중첩하지 않는다.
6. Apple Blue는 주요 행동과 선택 상태에만 사용한다.
7. 아이콘은 기존 `reicon-react`를 기능 설명에 필요한 만큼만 사용한다.

## 5. 공통 정보 구조

각 Home은 다음 공통 흐름을 공유한다.

1. Hero: 모드의 결과 약속, 짧은 설명, 주요·보조 CTA, 대표 제품 UI
2. Process: 사용자가 무엇을 하게 되는지 3~4단계로 설명
3. Product showcase: 실제 서비스 화면을 넓게 노출
4. Core benefit: 모드의 핵심 강점과 구체적인 결과 설명
5. Evidence: 점수, 리포트, 성장 기록 등 제품 근거
6. Context image: 실제 사용 맥락을 보여주는 한 장의 이미지와 짧은 메시지
7. Final CTA: 다음 단계로 이동하는 하나의 주요 행동

공통 구조를 사용하되 실제 섹션 순서와 정렬 방식은 모드별로 달리한다.

## 6. 모드별 레이아웃

### 6.1 면접 Home

면접은 긴장감과 즉각적인 질문 대응을 강조한다. 첫 화면부터 좌우 분할 구성을 사용한다.

1. 좌측 메시지와 CTA, 우측 `InterviewPracticeConsole`
2. 핵심·꼬리·압박·마무리 질문 흐름 4단계
3. 실제 질문 화면을 전체 폭 제품 스테이지로 확대
4. 응답·목소리·표정·자세 4-Fit 시각화
5. 잘한 점과 다음 행동을 보여주는 결과 보드
6. 면접 준비 환경 이미지와 신뢰 메시지
7. 직무 선택 CTA

### 6.2 직업훈련 Home

직업훈련은 순서와 완주 경험을 강조한다. Hero는 중앙 정렬하고 과업 보드를 그 아래 넓게 배치한다.

1. 중앙 메시지와 CTA, 전체 폭 `TrainingTaskBoard`
2. 과업 확인·단계별 수행·코칭 복습 3단계
3. 현장에서 자주 하는 과업 3종
4. 설명과 `TrainingCoachPanel`의 좌우 분할
5. 수행 시간·정확도·코칭 반영 성장 기록
6. 직업훈련 환경 이미지와 FAQ
7. 훈련 시작 CTA

### 6.3 직장대화 Home

직장대화는 관계와 반복 개선을 강조한다. 잡지형 좌우 교차 레이아웃을 사용한다.

1. 좌측 메시지와 CTA, 우측 `RecommendedConversation`
2. 보고·요청·조율·피드백 상황 선택
3. `WorkplaceWorkspace` 전체 폭 제품 스테이지
4. 대화 전후 표현 비교
5. 4-Fit 피드백과 구체적인 코칭 카드
6. 성장 추세와 협업 환경 이미지
7. 대화 연습 CTA

## 7. 컴포넌트 구조

현재 `InterviewHome`, `TrainingHome`, `WorkplaceHome`은 유지한다. `HomePage.jsx`가 지나치게 커지지 않도록 장문 랜딩에 필요한 프리미티브만 별도 컴포넌트로 분리한다.

- `HomeSection`: full-bleed 표면과 내부 레일을 담당한다.
- `ProductStage`: 제품 UI를 넓은 프레임 안에 배치한다.
- `BenefitStory`: 제목, 본문, 시각 자료의 좌우 또는 중앙 배치를 담당한다.
- `ContextVisual`: 실제 사용 장면 이미지와 짧은 메시지를 담당한다.
- `EvidenceStrip`: 모드별 수치와 제품 근거를 간결하게 표시한다.

기존 `SectionIntro`, `ProcessCard`, `FitMetric`, `FooterCta`, Shadcn `Button`, `Card`, `Badge`, `Progress`, `Accordion`은 재사용한다. 새로운 추상화는 두 곳 이상에서 실제로 재사용되는 경우에만 추가한다.

## 8. 데이터와 동작

- 모드 선택은 기존 `serviceMode.id` 흐름을 그대로 사용한다.
- 모든 주요 CTA는 기존 `onNext`를 호출한다.
- 보조 CTA는 해당 Home 내부 섹션으로 스크롤한다.
- 콘솔, 과업 보드, 추천 대화의 기존 클릭 상태는 유지한다.
- 새 시각 섹션은 읽기 중심이며 별도 API나 저장 상태를 만들지 않는다.
- 이미지 로딩 실패 시 레이아웃이 무너지지 않도록 고정 비율과 배경 표면을 유지한다.

## 9. 이미지 계획

### 서비스 UI

기존 React 제품 컴포넌트를 우선 사용한다. 화면처럼 보이게 만든 가짜 래스터 UI는 생성하지 않는다.

### 상황 이미지

서비스 UI만으로 설명하기 어려운 맥락에 한해 다음 이미지 3장을 생성한다.

- 면접: 정돈된 밝은 면접 연습 공간에서 카메라를 향해 답변하는 성인 학습자
- 직업훈련: 밝고 안전한 직업훈련 공간에서 과업을 순서대로 수행하는 성인 학습자
- 직장대화: 밝은 회의 공간에서 차분히 협업 대화를 나누는 두 명의 직장인

모든 이미지는 가로형 사진, 자연광, 실제 질감, 텍스트·로고·워터마크 없음으로 통일한다. 인물은 특정 실존 인물을 닮지 않게 하고, 화면의 핵심 텍스트와 경쟁하지 않도록 여백을 확보한다.

## 10. 반응형 동작

- 데스크톱: 최대 1180px 내부 레일을 기본으로 하되 제품 스테이지는 필요하면 더 넓게 사용한다.
- 태블릿: 좌우 분할을 단일 열로 전환하고 제품 화면을 텍스트 아래에 배치한다.
- 모바일: 강제 `<br>`을 해제하고, 제품 UI는 가로 스크롤 대신 전체 폭 축소 또는 세로 적층한다.
- 이미지에는 고정 `aspect-ratio`와 `object-fit: cover`를 사용한다.
- CTA 버튼은 모바일에서 전체 폭으로 확장한다.

## 11. 접근성과 오류 처리

- 모든 상황 이미지에 실제 내용을 설명하는 한국어 `alt`를 제공한다.
- 장식 이미지는 빈 `alt`를 사용한다.
- 현재 탭, 버튼, Accordion의 키보드 조작을 유지한다.
- 색상만으로 상태를 전달하지 않고 텍스트 라벨을 함께 둔다.
- `prefers-reduced-motion`에서 불필요한 전환을 제거한다.
- 이미지가 로드되지 않아도 텍스트와 CTA는 정상적으로 읽고 사용할 수 있어야 한다.

## 12. 검증 계획

1. 기존 Node 테스트 전체 실행
2. 프로덕션 빌드 실행
3. 3개 모드 진입과 주요 CTA 이동 확인
4. 데스크톱과 모바일에서 겹침·잘림·과도한 여백 확인
5. 동일 뷰포트에서 PLCO 참고 화면과 각 Home 캡처를 함께 비교
6. `design-qa.md`에 P0~P3 이슈 기록
7. P0~P2를 수정하고 `final result: passed`까지 반복

브라우저 기반 캡처와 상호작용 검증은 사용자가 선택한 브라우저에서만 수행한다.

## 13. 비목표와 유지보수 기준

- PLCO Coach의 문구, 로고, 고객 수치, 사진 또는 제품 화면을 복사하지 않는다.
- 각 Home에 같은 섹션을 같은 순서로 복제하지 않는다.
- 홈 화면만을 위해 새로운 상태 관리 계층을 만들지 않는다.
- 사용되지 않는 범용 컴포넌트나 미래 기능용 설정을 만들지 않는다.
- 이번 변경으로 생긴 미사용 import와 스타일만 정리한다.
