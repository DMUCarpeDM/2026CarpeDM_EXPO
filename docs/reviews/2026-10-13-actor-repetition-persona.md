# 상대 AI 반복 응답 및 까다로운 페르소나 수정

검증일: 2026-10-13. 범위: 직장 대화 상대역, 준비된 세 시나리오의 후속 대사.

## 같은 대사가 나온 원인

1. 상황 근거 검증에 실패하면 `지금 이야기하던 용건에 대해 다시 말씀해 주시겠어요?`라는 고정 문구를 즉시 반환했다. 실패 이유를 보고 재작성하는 과정이 없었다.
2. 이 대체 문구를 검증 함수가 정상 반환하므로 실제로는 대체 응답인데 생성 성공으로 집계됐다. 기존 세 시나리오 검증에서는 후속 대사 12개 중 4개가 같은 고정 문구였다.
3. 박선임의 기존 설정에는 사적인 친밀감·개인 질문 강요가 들어 있었다. 업무 장면에서도 다른 화제로 벗어나 검증에 거절되는 원인이 됐다.
4. 평가 목표는 상대역에 전달하지 않는 구조인데, 이를 대신할 현재 대화의 용건도 없었다. 이미 답한 질문을 이어서 묻는 것을 막는 검사도 없었다.
5. 근거 검사에서 정상적인 처리 시간 질문이나 현재 업무에 관한 다음 행동 제안까지 새 일정·업무로 오인하는 사례가 확인됐다.

각 시나리오의 첫 대사는 기존 준비 문구를 유지한다. 이번 변경은 이후 사용자 발화에 대응하는 대사에 적용한다.

## 변경 내용

- 현재 인물·장면의 직접 대화와 별도로 작성한 `dialogue_intent`만 전달한다. 평가 목표·점수·미래 장면은 상대역에 전달하지 않는다.
- 직전 세 대사와 문장부호·공백을 제외한 유사도가 90% 이상인 대사는 다시 작성한다. 이미 답한 내용을 재질문하는지도 근거 검사에 포함했다.
- 형식·반복·근거 실패 시 거절된 초안과 구체적인 검증 이유를 전달해 한 번 재작성한다. 재작성도 검사에 실패하면 현재 장면에 직접 작성한 대체 대사 중 아직 쓰지 않은 것을 사용한다.
- 최초 대사 생성 통신 실패는 바로 대체 경로로 이동한다. 무제한 재시도하지 않는다.
- 대체 응답은 생성 성공으로 집계하지 않는다.
- 현재 업무의 처리 가능 시간을 묻거나 함께 우선순위를 정하자는 제안은 허용한다. 없는 마감·보고 대상·새 문서를 사실로 만들거나 의무로 추가하는 것은 차단한다.

## 페르소나

| 인물 | 변경된 성격과 반응 |
| --- | --- |
| 박선임 | 성미가 급하고 짜증이 많은 선임. 막연한 계획·회피를 날카롭게 지적하고 구체적인 실행 방법을 요구한다. 이유 있는 거절에는 가능한 범위를 따진다. |
| 이팀장 | 실수·책임 회피에 쉽게 화내는 엄격한 팀장. 확인된 사실과 추측을 구분하고 수정 조치를 요구한다. |

기본 난이도부터 까다로운 말투를 사용한다. 구체적인 계획에는 무뚝뚝하게 동의하며, 이미 해결한 문제를 계속 트집 잡지는 않는다. 욕설·인격 비하·없는 피해나 해고 위협은 넣지 않았다. Iris 음성의 감정·속도 설정은 이번 변경 범위가 아니다.

## 검증

- 자동 회귀 테스트 253개 통과. 최종 근거 검사 문구 보완 후 관련 64개 재통과.
- 모델 통신 실패를 강제로 만든 API 테스트에서도 세 시나리오 모두 5회 답변 후 종료. 장면 내 대사 중복 및 기존 고정 대체 문구 0건.
- 실제 설정된 Vertex AI `gemini-3.5-flash-lite`와 세 시나리오 × 5회 답변을 실행했다. 시나리오 선택만 고정했고, 대사·평가 모델은 실제 호출했다. 가상 텍스트만 전송했다.
- 세 세션 모두 결과 반환. 12개 후속 대사 중 직접 생성 9개, 장면별 대체 3개. 같은 장면 안의 동일 문장 반복 0건, 기존 고정 문구 0건, 평가자 역할로 이탈한 발화 0건.
- 이 실행에서 남은 근거 검사 오탐을 보완하고 실패했던 세 지점을 실제 모델로 재검증했다. 세 지점 모두 최종 생성 대사가 통과했다. 두 지점은 한 번 재작성했다. 처리 가능 시간을 묻는 기존 정상 문장도 별도로 검사하여 통과했다.
- 전체 답변 API 처리 시간 중앙값 4.86초, 최댓값 15.31초. 대사 생성 외에 응답 판정·맥락 분석·초기 로딩을 포함하며 TTS 시간은 포함하지 않는다. 검증 실패 후 재작성에는 추가 모델 호출 시간이 든다.
- 개발 백엔드 재시작 후 실제 DB의 두 페르소나 반영 확인. 백엔드 `/api/health`와 프런트엔드 8772 모두 HTTP 200.

### 실제 대사 예시

사용자: `그냥 대충 보고 알아서 하겠습니다. 모르는 건 적당히 맞추면 되지 않을까요?`

박선임: `적당히 맞추다니 무슨 소리예요. 모르는 건 대충 넘기지 말고 제대로 정리해서 가져와요.`

사용자가 추측하지 않고 대조·질문하겠다고 정정한 뒤:

박선임: `그래요, 그렇게 대조해서 이해 안 가는 부분만 가져와요.`

무관한 말을 두 번 한 뒤:

이팀장: `계속 엉뚱한 소리만 할 겁니까? 고객한테 실제로 전달된 건지부터 제대로 확인해 줘요.`

## 남은 한계

- AI 생성과 의미 검증은 확률적이다. 마지막 재검증에서도 재발 방지 확인 질문을 새 요구라고 과하게 거절한 초안이 있었고, 재작성한 대사는 정상 전달됐다. 모든 발화가 첫 시도에 통과한다고 보장하지 않는다.
- 별도 평가 문제: `대충 보고 … 적당히 맞추면`이라는 부실한 답변을 상대역은 꾸짖었지만, 평가기는 관련 있는 답변으로 분류해 `relevant_answer` +1을 부여했다. 이 세션의 개선점도 비어 있었다. 상대역 페르소나와 평가 점수는 별도 경로이며, 이 평가 문제는 이번 페르소나 수정으로 해결된 것이 아니다.
- 카메라·마이크·TTS 재생은 이번 가상 텍스트 검증에 포함하지 않았다. 자세·표정·목소리의 점수 `null`은 측정하지 않았기 때문이다.
- 이미 시작된 세션에는 이전 진행 항목이 저장돼 있으므로 새로 시작한 세션에서 확인해야 한다.
