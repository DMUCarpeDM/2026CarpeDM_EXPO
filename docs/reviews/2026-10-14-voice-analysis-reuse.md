# 종료 후 음성 분석 재사용 검증

## 변경
- 녹음 SHA-256, 보정값, 입력 설정(마이크·제외 구간), 분석 엔진/기준 버전, Whisper 모델·프롬프트가 같고 STT가 성공한 결과만 재사용한다.
- 실시간 분석의 2초 대기 제한은 유지한다. 제한 이후 완료되는 Future를 보관하여 종료 분석에서 회수한다. 작업 스레드는 ORM 상태를 수정하지 않는다.
- 성공한 결과는 기존 voice_measurements/response_habits와 fingerprint를 세션에 저장한다. 미분석·입력 변경·실패한 STT만 다시 분석한다.
- 임시 Future는 최대 128개, 30분 유효기간으로 제한하며 조회 시 만료를 정리한다. 미저장 정책의 원문 삭제 시 해당 세션 Future와 재사용 키도 제거한다.
- 모델, beam_size=5, CPU int8, 음성 측정/점수 계산 방식은 변경하지 않았다.
- 음성 턴 처리 완료마다 실제 진행률을 갱신한다. 스마트미러 결과 대기 화면은 서버 진행률을 흰색 선으로 부드럽게 표시하고 단계 설명과 약한 빛 이동 효과를 제공한다. 시간에 따라 가짜 진행률을 올리지 않으며 reduced-motion에서는 효과를 끈다.

## 실제 모델 성능 비교
동일한 한국어 합성 음성을 5개 턴 ID에 사용. 수정 전 코드 사본과 수정 후 코드를 동일한 모델 설정으로 실행. 워밍업 후 3회 반복. 실제 사용자 녹음과 외부 API를 사용하지 않았다.

| 반복 | 수정 전 5개 재분석 | 5개 재사용 | 4개 재사용 + 1개 분석 |
|---|---:|---:|---:|
| 1 | 14,598.39 ms | 1.12 ms | 2,460.05 ms |
| 2 | 12,522.43 ms | 1.08 ms | 2,324.80 ms |
| 3 | 11,819.05 ms | 1.09 ms | 2,516.12 ms |
| 중앙값 | 12,522.43 ms | 1.09 ms | 2,460.05 ms |

1개가 남은 경우 약 80.35% 단축. 각 반복의 전체 음성 측정 객체와 간투어 객체가 수정 전후 정확히 일치함을 assert로 검사했다. 보정 없는 합성 데이터라 상대 음량은 미측정이며, 보정된 API 흐름은 별도 회귀 테스트로 검사했다. 이 수치는 **종료 단계의 음성 분석 시간**이며 전체 결과 페이지의 대기시간/새로운 정확도 벤치마크가 아니다. 미분석 녹음이 많으면 단축 폭은 줄어든다.

실제 live_turn 경로도 추가 확인: 5회 모두 2초 대기 제한을 넘겼지만 작업 완료 후 finish_turn이 결과를 회수하는 데 총 2.52ms, 5개 말속도 측정 완료, 잔여 Future 0개. 다음 대화 동안 분석이 끝난 상황을 재현하기 위해 각 Future 완료 후 다음 턴을 호출했다.

증거: `.omo/evidence/voice-reuse/benchmark.py`, `benchmark.json`, `live-path.py`, `live-path.json`.
