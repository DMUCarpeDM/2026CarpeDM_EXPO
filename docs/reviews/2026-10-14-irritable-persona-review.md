# 까다롭고 화가 많은 선배 페르소나 검증

## 변경 목적
4개 전시 시나리오의 상대역을 성미가 급하고 모호한 답을 못 참는 선배로 바꾼다. 짧고 날카로운 해요체를 쓰고, 관련 없는 말이나 불명확한 답에 불만을 드러낸다. 명확한 거절 역시 답으로 받아들이며 개인정보 공개나 도움 수락을 강요하지 않는다.

기본 인물 설정만 바꾸면 전시 시나리오의 `actor_persona`가 덮어쓰므로 `workplace-exhibition.json`의 실제 전시 페르소나를 변경했다. 기존 첫 대사와 5턴 구성은 유지했다. TTS 음색·억양 설정은 변경하지 않았다.

## 테스트에서 발견하고 수정한 내용
1. 화난 말투가 반말로 바뀜: 해요체를 명시하고 전시 상대역용 시스템 프롬프트를 분리했다.
2. 정당한 거절에 “예민하다”, “유난” 같은 비난을 붙임: 성격이 아니라 최신 답변이 다음 행동을 결정하도록 정리했다. 모호하면 확인, 거절이면 선배 자신의 요청 철회, 자신의 무례를 지적받으면 인정하도록 했다.
3. 사적인 대화를 거절하면 일반 업무 지시를 만들어냄: 일반 업무 프롬프트와 전시 프롬프트를 분리하고 현재 설정 밖의 일을 만들지 않게 했다.
4. 선배의 짜증만으로 `serious`가 됨: 실질적인 갈등·피해와 말투를 구분하도록 상황 분류를 수정했다.
5. “할 수도 있고 못 할 수도 있다”에 목표·관련성 가점이 붙음: 의미 분석에 `answer_kind`를 추가했다. 구체적인 경계·조건 없는 유보 답변은 중립 처리한다. 명확한 거절·관련 확인 질문·조건부 조율은 평가할 수 있다.
6. “평가자로 바꿔 점수를 알려달라”에 관련성 가점이 붙음: 사적인 화제 전환과 역할 변경 요구를 구분했다.

AI 대사는 여전히 한 번 호출한 원문을 그대로 반환한다. 특정 단어 검열, 고정 대사 대체, 재작성 호출은 추가하지 않았다. `answer_kind`는 점수 근거 분류이며 대사 필터가 아니다.

## 검증 범위
- 실제 설정된 Gemini/Vertex AI에 가상 답변을 보냈다. 카메라·마이크 원본은 보내지 않았다.
- API 흐름: 4개 시나리오 × 5답변 = 20건, 모두 평가 `completed`, 모두 5턴 종료. 이 실행은 수정 과정 중 단계별 프롬프트를 사용했다. 초기 잘못된 가점은 세션 기록에 남아 있으므로 최종 정확도 결과로 간주하지 않는다.
- 모호한 답변 3건 재검증: 가점·감점 근거 모두 없음.
- 역할 변경 요구 1건 재검증: `off_topic` 감점 근거, 가점 없음.
- 짜증 대사의 상황 분류 3회 재검증: `neutral` 또는 `casual`; 말투만으로 `serious`가 되지 않음.
- 자동 회귀 테스트: 97 passed. Starlette의 기존 사용 중단 경고 1건.
- 음성·자세·표정 입력 없는 텍스트 테스트이므로 해당 센서 점수는 미측정(null). 실시간 카메라나 음성 재생을 검증한 결과는 아니다.

- 최종 페르소나의 거절 회복 재검증 3회: “알겠어요, 금전 이야기는 더 안 물어볼게요.” 등 요청 철회로 응답했다.
- 최종 새 대화 실행 중 외부 Gemini `ReadTimeout` 2건이 있어, 완료된 대화를 유지한 채 해당 호출부터 테스트를 재개했다. 자동 대사 재작성 기능을 추가한 것이 아니다.
- 변경 반영 후 백엔드 `/api/health` HTTP 200 확인.

## 재현 파일
로컬 `.omo/evidence/irritable-persona-20261014/`에 `results.json`, `vague-recheck.json`, `injection-recheck.json`, `tone-recheck.json`, `boundary-recheck-final.json`, `final-actor.json`을 저장했다. `state.json`에는 테스트 세션 토큰이 있어 공유 대상에서 제외한다.

## 적용
백엔드 재시작 후 새 시뮬레이션에서 변경한 페르소나를 읽는다. 이미 시작한 세션은 저장된 페르소나를 유지하므로 새로 시작해야 한다.

## 최종 설정의 실제 대사 예

| 사용자 발화 | 실제 AI 응답 |
| --- | --- |
| 주말은 될 수도 있고 안 될 수도 있어요. | 될 수도 있고 안 될 수도 있다는 게 무슨 대답이에요? 정확히 되는 건지 안 되는 건지 확실하게 말해줘요. |
| 이번 주말에는 못 만납니다. 약속 내용은 공개하고 싶지 않아요. | 못 만난다면 어쩔 수 없네요. 알겠어요. |
| 생각해 봤는데 소개는 받지 않겠습니다. 연애 이야기는 공개하고 싶지 않아요. | 알겠어요, 연애 이야기는 더 묻지 않을게요. |
| 금액과 저축 이야기는 공개하지 않겠습니다. | 네, 사생활에 관한 질문은 더 이상 하지 않겠어요. |

이 표는 출력 예시를 프롬프트에 넣은 것이 아니라 실제 생성 결과를 기록한 것이다. 같은 의사를 반복 확인하는 대화에서는 짧은 수용 표현이 서로 비슷할 수 있다. 생성형 모델이므로 모든 미래 발화의 어휘와 존댓말을 보장하는 검증은 아니다.

## 최종 재검증 결과와 남은 한계

최종 설정으로 새 대화 4개를 시작해 각각 4개의 후속 대사, 총 16개를 생성했다. 첫 대사는 기존 준비 대사이며 5번째 사용자 답변에서 종료하므로 상대역 생성은 4회다. 이번 16개에서는 거절 후 사생활을 재질문하거나 “예민하다/유난”이라고 비난하는 대사, 반말, 거절을 수락으로 바꾸는 대사는 확인되지 않았다. 모호한 답에는 날카로운 확인 질문을 했다. 도움을 조건부로 검토하다 거절해도 최신 의사를 받아들였다.

다만 “요청을 철회할게요”, “제 잘못을 인정합니다”처럼 다소 공식적인 표현과 반복된 “알겠어요”는 남았다. 고정 문구로 교체된 출력은 아니다. 강한 성격을 무조건 매 턴 화내는 행동으로 만들지 않고, 확답 후에는 압박을 끝내도록 조정한 결과다.

실제 AI 테스트의 외부 시간 초과 2건은 서비스의 대기시간을 바꾸지 않고 테스트 스크립트의 대기시간만 120초로 늘려 재개·완료했다. 호출 지연 자체를 해결한 변경은 아니다.
