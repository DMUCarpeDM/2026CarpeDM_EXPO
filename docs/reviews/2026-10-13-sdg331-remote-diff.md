## 결론: 고정 대사가 명시적으로 들어 있다

사용자가 말씀한 문구와 정확한 글자는 다르지만, 같은 의미의 문장이 코드에 직접 작성돼 있다.

```python
return "지금 이야기하던 용건에 대해 다시 말씀해 주시겠어요?"
```

위치: [`workplace.py:195–200`](https://github.com/DMUCarpeDM/2026CarpeDM_EXPO/blob/a6349876af696e07a15fc676100ca0f9f9f0d813/poc/backend/app/services/workplace.py#L195-L200)의 `continuous_fallback_line()`.

현재 장면의 첫 대사가 아직 사용되지 않았고 유효하면 그 첫 대사를 반환한다. 이미 사용했거나 유효하지 않으면 위 고정 문구를 반환한다. 고정 문구 자체의 반복 여부는 검사하지 않으므로 오류가 반복되면 계속 같은 말을 할 수 있다. 함수의 `case` 인자는 반환 문구 선택에 사용되지 않는다.

이 문구는 sdg331의 이번 커밋에서 추가한 것이 아니다. `git blame`과 문자열 추가 이력을 확인하면 기존 `87a3fdfaa413c79e37bdb5cbff698ff924d1981b` 커밋에서 들어왔으며, 이번 브랜치가 main의 해당 코드를 그대로 물려받았다.

## 어떤 때 이 문구가 나오는가

1. 상대 AI의 대사를 생성한다.
2. 별도의 AI 검증기가 상황에 없는 사실을 추가했는지 검사한다.
3. 검증이 실패하거나 검증 결과를 읽지 못하면 `continuous_fallback_line()`을 호출한다.
4. 첫 대사를 이미 사용했다면 위 고정 문구를 반환한다.

검증 실패 경로는 [`openai_provider.py:113–147`](https://github.com/DMUCarpeDM/2026CarpeDM_EXPO/blob/a6349876af696e07a15fc676100ca0f9f9f0d813/poc/backend/app/services/dialogue/openai_provider.py#L113-L147)에 있다. Gemini도 이 검증 함수를 사용하고, 자체 생성 실패에서도 같은 대체 대사를 호출한다: [`gemini_provider.py:274–305`](https://github.com/DMUCarpeDM/2026CarpeDM_EXPO/blob/a6349876af696e07a15fc676100ca0f9f9f0d813/poc/backend/app/services/dialogue/gemini_provider.py#L274-L305).

| 입력 또는 오류 | 원격 브랜치의 처리 |
| --- | --- |
| 요청의 `text`가 실제 JSON `null` | 문자열 스키마에 맞지 않아 거절된다. 고정 문구를 직접 선택하는 조건이 아니다. |
| 빈 문자열이며 서버 STT 결과도 없음 | HTTP 422로 거절한다. |
| 문자열 `"null"`, `"undefined"` | 비어 있지 않은 문자열이므로 이 제출 단계에서 차단되지 않는다. |
| 목소리·응답 점수가 `null` | 점수 누락 자체를 조건으로 이 문구를 반환하는 코드는 확인되지 않았다. |
| AI 검증 결과가 JSON `null` | 파싱 후 객체 접근에 실패하고 대체 대사로 이동한다. |
| 검증 결과 `supported=false`, 잘못된 JSON, 검증 호출 오류 | 대체 대사로 이동한다. |
| 맥락과 무관한 발언 | 프롬프트는 지적 후 원래 용건으로 돌아오도록 요구한다. 다만 생성·검증 실패 시 위 고정 문구로 바뀔 수 있다. |

입력 근거: [`ResponseIn` 스키마](https://github.com/DMUCarpeDM/2026CarpeDM_EXPO/blob/a6349876af696e07a15fc676100ca0f9f9f0d813/poc/backend/app/schemas/schemas.py#L447-L451), [응답 제출 처리](https://github.com/DMUCarpeDM/2026CarpeDM_EXPO/blob/a6349876af696e07a15fc676100ca0f9f9f0d813/poc/backend/app/api/sessions.py#L549-L555).

프롬프트에는 인식이 불분명하면 뜻을 확인하라는 지시는 있으나, 위 고정 문장을 반드시 말하라는 지시는 없다. 고정 문장은 실패 처리 코드에서 나온다. 해당 사용 세션의 실제 로그는 이번 비교에서 확인하지 않았으므로, 사용자가 들은 모든 반복의 원인이 이 경로였다고 단정하지는 않는다.

## 재현 결과와 비교 파일

원격 커밋에서 필요한 함수만 추출하고 검증 결과를 제어해 실행했다. 외부 AI 호출이나 세션 DB 쓰기는 하지 않았다. 장면의 첫 대사가 이미 사용된 조건에서 다음 네 경우가 모두 같은 고정 문구를 반환했다.

- `supported=false`
- 검증 JSON `null`
- 잘못된 JSON
- 검증 호출 오류

앞서 반환된 고정 문구를 대화 이력에 추가한 뒤에도 다시 같은 문구가 나왔다. 이는 실패 처리의 반복을 재현한 결과이며, 실제 AI의 실패 빈도를 측정한 결과는 아니다.
