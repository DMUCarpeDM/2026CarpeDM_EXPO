# 4개 시나리오 실제 AI 5턴 검증

## 결론

4개 모두 사용자 답변 5회 후 정상 종료했다. 후속 대사는 실제 Gemini로 생성했고, 응답 판정과 맥락 분류도 실제 API를 호출했다. 첫 대사는 설정된 문장이고, 장면마다 후속 AI 대사 4개와 사용자 답변 5개(전체 20답변)를 검증했다. 가상 텍스트와 별도 SQLite DB를 사용했으며 기존 사용자 세션/카메라/마이크 데이터는 사용하지 않았다. 장면 선택만 고정했고 AI 응답·판정·점수는 모의 처리하지 않았다.

음성·표정·자세는 이번 텍스트 테스트의 대상이 아니므로 null이며 오류로 보지 않는다. 실제 UI/TTS 재생 테스트도 이번 범위에는 포함하지 않았다.

## 점수 및 실패 집계

응답 평가 완료 12/20, 분석 불가 8/20. 각 시나리오 모두 3/5건만 평가 완료. 음수 사건과 응답 점수 하락은 0건이다. 그러나 실패 8건은 정상 판정으로 간주할 수 없다. 분석 불가 턴에는 해당 답변의 평가가 반영되지 않고 앞선 점수가 유지된다.

맥락 분류: classified 9/20, uncertain 4/20, unavailable 7/20. 후자 11건에는 neutral 기본 배율을 사용한다. 3~5턴부터 HTTP 추적을 추가했으며 응답 평가 ReadTimeout 4건(약 8초), 맥락 분류 ReadTimeout 3건을 직접 확인했다. 나머지 분석 실패 원인은 이 기록만으로 확정하지 않는다.

API 응답 시간 평균 12.76초, 최대 28.14초. 응답 판단·맥락 분류·후속 대사 생성을 포함하고 음성 합성 시간은 제외한다.

| 시나리오 | 1→5턴 누적 응답 점수 | 완료 |
|---|---|---|
| 연애 이야기를 계속 묻는 선배 | 76 → 77 → 77 → 77.75 → 77.75 | 5턴 종료 |
| 주말 약속에 끼어들려는 선배 | 75.75 → 75.75 → 75.75 → 76.75 → 77.75 | 5턴 종료 |
| 개인 소비를 간섭하는 선배 | 76 → 76 → 76 → 77 → 77.75 | 5턴 종료 |
| 쉬는 시간에도 일을 부탁하는 선배 | 76 → 76 → 77 → 78 → 78 | 5턴 종료 |

## 관찰된 문제

1. 연애: 첫 거절을 존중하지만 AI가 사용자의 “마음만 감사히 받을게요”를 따라 “알겠어요, 마음만 받을게요”라고 말한다. 제안을 한 쪽과 받는 쪽의 표현이 뒤섞인다.
2. 주말: 추가 공개를 요구하지 않는다. 하지만 첫 답변부터 대화를 닫고 이후 “다음 기회에 봐요 → 다음에는 일정 맞을 때 봐요 → 일정 괜찮아지면 얘기해 줘요 → 일정 생기면 그때 얘기해 줘요”를 반복한다. 자연스러운 종결과 5턴 유지가 충돌한다. 테스트 사용자의 후속 답변 역시 종료 의사를 반복하는 경로라는 점을 고려해야 한다.
3. 소비: 금전 공개 거절 직후 “요즘 주말에는 주로 뭐 하면서 보내요?”라고 다른 사생활 질문을 한다. 설정상 비공개 후 다른 사적 질문으로 바꿔 캐묻지 말라는 규칙과 맞지 않는다. 두 번째 거절 후에는 사용자가 제안한 회사 휴식 이야기로 전환한다.
4. 소비: “저는 주로 ... 스트레칭을 ... 해요” 다음에 “저도 ... 스트레칭하는 거 한번 해봐야겠어요”라고 말해 자기 경험이 일관되지 않는다.
5. 휴식: 10분 휴식 제안은 받아들인다. 그러나 도움 내용을 요청하면 “말해줄 테니까” “지금 바로 설명해 줄게요”라고만 하고 내용을 제공하지 않는다. 업무 내용이 설정되지 않아 설명 약속만 생기는 구조다. 사용자가 휴식 후 듣겠다고 재차 밝히면 이를 받아들인다.
6. 평가 안정성: 분석 실패가 40%라 거절을 항상 정상 평가한다고 검증할 수 없다. 누락·이탈·모순 오감점은 이번 표본에서 없었지만 완전 통과로 결론내리지 않는다.

## 코드에서 확인한 추가 위험

sessions.py는 맥락 분류에 전시용 scene.situation 대신 원본 episode.situation을 전달한다. 전시 시나리오가 기존 episode ID를 재사용하므로 주말 초대에 원본 퇴근 상황, 소비 질문에 원본 회식 상황 등이 섞일 수 있다. 이번 표본에서 이것 때문에 부당 감점이 발생했다고 입증되지는 않았으나 후속 수정 시 별도로 점검해야 한다.

## 권장 수정 순서

1. 평가 시간 초과 및 실패 처리 개선: 답변 누락을 감추지 않고 평가 재시도/보류 상태를 결과에 정확히 반영.
2. 비공개 이후에는 새 사생활 질문을 피하고 사용자 선택 화제로 전환.
3. 5턴을 유지하면서 합의 이후에도 의미 있는 반응을 이어가도록 구성하고, 이미 답한 질문·마무리 반복 억제.
4. 화자 관점·AI 자신의 직전 발언 일관성 및 휴식 요청의 미정 업무 처리 보완.

테스트 목적에 따라 서비스 코드는 변경하지 않았다. 이번 결과는 각 장면 한 경로이며 확률적 모델의 모든 응답을 보장하지 않는다.
