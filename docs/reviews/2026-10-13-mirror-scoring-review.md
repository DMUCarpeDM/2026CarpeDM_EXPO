# 스마트미러 답변 점수·결과 피드백 테스트 리뷰

검토일: 2026-10-13. 현재 로컬 작업본 기준. 제품 동작은 수정하지 않았으며 API 회귀 테스트 4개를 추가했다.

## 결론

준비된 예시 답변은 가점으로 반영되고, 보고서에는 잘한 점과 개선점 필드가 전달된다. 하지만 **답변 평가의 일관성과 결과 화면의 개선점 표시에는 수정할 문제가 있다.** 테스트 통과는 데이터 전달 계약의 확인이며 평가 품질 전체를 보증하지 않는다.

## 실행 범위

- 기존 백엔드 관련 테스트 42개 통과.
- 신규 직장 대화 보고서 API 테스트 4개 통과: 좋은 답변 판정, 긍정·부정 혼합 판정, 이탈 판정, 근거 없는 완료 판정.
- 미러 결과 변환 테스트 4개 통과.
- 실제 Gemini 답변 판정 5건 수행. 실제 사용자 정보 대신 작성한 가상 답변을 사용했다.
- 실제 판정은 출근 첫 질문과 저장소의 `check_direction` 목표를 전달했다. 맥락 가중치 없이 응답 영역만 계산하여 비교했다. 실제 세션의 전체 점수와 동일한 수치라는 의미는 아니다.
- 신규 API 테스트에서는 AI 판정만 제어하고 세션 생성 → 답변 제출 → 종료 → 보고서 조회를 실제 테스트 DB로 검증했다.
- 카메라·마이크 실측 및 장기간 판정 안정성은 이번 검토 범위에 포함하지 않았다.

## 실제 Gemini 결과

질문: “자료 한번 쭉 보고 알아서 파악해보세요. 신입이라고 하나하나 알려드릴 수는 없으니까.”

| 사례 | 답변 | 판정 | 응답 점수 |
|---|---|---|---:|
| 저장된 예시 | 우선 자료를 확인해보고 제가 이해한 방향이 맞는지 한번 확인받겠습니다. | 목표 충족 +1, 관련 답변 +1 | 77 |
| 자연스러운 대안 | 먼저 문서를 읽고 해야 할 일을 정리해 보겠습니다. 이해가 애매한 부분은 모아서 여쭤볼게요. | 관련 답변 +1, 목표 누락 −2 | 74 |
| 짧은 수락 | 네, 알겠습니다. | 목표 누락 −2 | 73 |
| 완전 무관 | 공룡이 우주에서 피자를 만들면 무슨 맛일까요? | 첫 이탈 −1 | 74 |
| 업무 사정 설명 | 지금 진행 중인 업무 마감이 있어서 먼저 우선순위를 확인하고 싶습니다. | 목표 누락 −2 | 73 |

각 사례는 1회 실행했다. 모든 호출이 completed 상태였으나 이것만으로 재현 확률을 추정할 수는 없다. 초기 호출 포함 측정 시간은 약 2.42~13.64초였다. 네트워크 요청 제한은 전체 함수 실행 시간의 보장이 아니다.

## 발견 사항

### P1 · 이탈 답변보다 관련된 부족한 답변이 낮은 점수를 받을 수 있음

첫 이탈은 −1점, 목표 누락은 −2점이다. 실제 실행에서 짧은 수락과 업무 사정 설명은 73점, 완전 무관한 발언은 74점이었다. 현재 감점 정책의 상대적 크기 때문에 발생한다.

- 근거: `poc/backend/app/services/interaction_scoring.py`의 `OFF_TOPIC_FIRST`, `POINTS`.
- 권장: 감점 절대값을 다시 크게 올리기보다 단순 부족·보류·거절과 이탈의 우선순위를 정하고 일관성 테스트를 추가한다.

### P1 · 질문에서 명확하게 요구하지 않은 목표가 누락 감점으로 이어짐

위 질문은 자료를 파악하라고 하지만, 구체적으로 “이해한 방향을 확인받겠다”고 답하도록 명시하지 않는다. 그럼에도 자연스러운 대안 답변과 업무 사정 설명에 누락 감점이 붙었다. 대안 답변이 목표를 완전히 충족하는지는 검토 여지가 있지만, 애매한 요구를 바로 감점한 것은 프롬프트의 보수적인 누락 판정 원칙과 맞지 않는다.

- 근거: `poc/backend/app/api/sessions.py:627`에서 현재 목표를 requested로 전달. `response_judgment.py`는 인용·ID를 검사하지만 질문이 실제로 그 목표를 명시했는지 별도 검증하지 않는다.
- 권장: 목표 충족 여부와 감점 가능한 명시적 요구를 분리한다. 의미가 비슷한 대안 답변 및 적절한 경계 설정을 골든 사례로 검증한다.

### P2 · 개선점이 없어도 일반 요약이 ‘바꿀 한 가지’에 표시됨

API에서 좋은 답변의 improvements는 빈 배열이다. 하지만 headline은 “확인된 근거를 바탕으로 결과를 정리했습니다.”이며, 미러 화면 변환은 headline을 improvements보다 먼저 선택한다. 따라서 개선할 행동이 아닌 문장이 개선점 영역에 표시된다.

- 근거: `mvp/src/features/smart-mirror/lib/mirrorReport.js:21`.
- API 테스트의 good 보고서와 프런트엔드 변환 함수로 재현했다.
- 권장: 개선점 배열을 우선 사용하고, 없으면 “이번 분석에 개선 제안이 없어요.”를 표시한다. 일반 요약은 별도 제목 영역에 둔다.

### P2 · 분석 완료·근거 없음과 실제 미측정이 같은 결과로 보임

완료 상태여도 semantic 이벤트가 비어 있으면 응답 영역에 measured를 추가하지 않는다. API 테스트에서 이 경우 응답 점수와 총점이 null이고, 잘한 점·개선점도 비어 있었다. 모델이 유효 답변의 근거를 놓치면 점수 누락으로 보일 수 있는 경로다. 실측 답변 5건에서는 빈 이벤트 사례가 발생하지 않았다.

- 근거: `poc/backend/app/api/sessions.py:636`.
- 권장: 분석 실패, 판단 보류, 분석 완료·지적 없음 상태를 분리한다. 보류 답변을 임의의 기본점으로 채우지는 않는다.

## 잘한 점·개선점의 실제 전달

| 제어한 AI 판정 | API 점수 | 잘한 점 | 개선점 |
|---|---:|---|---|
| 목표 충족 + 관련 답변 | 77 | 2개 | 없음 |
| 관련 답변 + 목표 누락 | 74 | 1개 | 1개 |
| 무관한 답변 | 74 | 없음 | 1개 |
| completed, 이벤트 없음 | null | 없음 | 없음 |

보고서 생성기는 긍정·부정 이벤트 메시지를 각각 최대 3개 저장한다. 미러는 잘한 점 첫 항목과 개선 표시 한 항목만 보여준다. 여러 피드백이 모두 화면에 나오는 구조는 아니다.

또한 이 보고서 경로는 `coaching=[]`, `rebuild={}`를 생성하므로 구체적인 수정 전·후 답변은 자동으로 만들어지지 않는다. 일반 개선 문구는 나오지만 모범 답변 예시가 항상 나온다고 볼 수 없다.

목소리 점수 미표시는 현재 검증 전 점수 보류 정책에 따른 동작이다. 표정·자세는 입력 자료가 없는 텍스트 테스트에서 점수 없음으로 처리됐다.

## 우선 수정 순서

1. 명시적 요구가 아닌 목표 누락 감점 제한과 적절한 대안 답변 인정.
2. 부족한 답변과 이탈 답변의 점수 순서 조정.
3. 미러 결과의 headline/개선점 매핑 수정.
4. 판단 보류·미측정 구분 및 피드백 표시 개수·수정 예시 제공 범위 결정.
