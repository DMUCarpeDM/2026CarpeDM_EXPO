# 거절 이후 후속 질문을 이어가는 선배 프롬프트

## 요청과 원인
거절 뒤 바로 물러나던 동작은 exhibition 시스템 프롬프트, actor prompt 끝부분, 4개 seed의 actor_persona와 dialogue_intents에서 중복 지시한 결과였다. 이번 요청에 따라 이 지시를 불편함을 표현하며 이유·사정·조정 가능성을 묻는 방향으로 변경했다.

## 변경 범위
- `poc/backend/app/services/dialogue/openai_provider.py`: exhibition 상대역 지시와 마지막 행동 지시만 수정. 기존 후반 수용 지시 제거.
- `poc/backend/app/seed/workplace-exhibition.json`: 네 시나리오의 페르소나와 대화 의도만 수정.
- 입력 분류 조건, 고정 대사, 응답 치환, 재호출 로직을 추가하지 않았다. AI 출력은 기존대로 전달한다.
- 상황 설명, 평가 기준, 5회 응답 구조는 유지했다. 상대역의 불만이 거절에 대한 감점 규칙을 뜻하지 않는다.

## 검증
- 실제 설정된 Gemini 제공자로 합성 대화 4개 × 4개 후속 응답을 3차례 검사했다(총 48개 생성). 마지막 실행의 16개 응답 모두 후속 질문을 포함했다.
- 최종 결과: `.omo/evidence/probing-persona-verified-20261014/final-actor.json` (로컬 검증 자료).
- 첫 대사는 준비된 문장이고, 마지막 사용자 응답 뒤에는 결과로 넘어가므로 5회 사용자 응답 구조에서 생성할 후속 대사는 4개다. 이번 검증은 해당 생성 경로를 직접 호출했다.
- 자동 테스트: workplace_exhibition, actor_passthrough, role_boundary, judgment_regressions, context_scoring: **97 passed**.
- 개발 백엔드 재시작, `/api/health` HTTP 200 확인.
- 마이크 입력·자막·TTS 재생의 통합 검증은 이번 범위에 포함하지 않았다.

## 실제 응답과 남은 품질 한계
“시간을 바꿀 수 없어요. 이번에는 절대 못 갑니다.” 뒤:
> 아무리 바쁘다고 해도 그렇게 일방적으로 선을 긋고 안 된다고만 하시면 저도 참 당황스럽고 섭섭해요. 도대체 어떤 약속이기에 서로 시간 조율 한 번 해볼 여지도 없이 이렇게 절대 안 된다고 완강하게 나오시는 거예요?

요청한 집요한 질문은 확인됐다. 다만 생성형 응답이므로 모든 세부 지시를 항상 지키지는 않는다. 최종 샘플에서도 서운하다는 도입이 반복되거나, 주말 식사를 저녁 식사로 좁혀 말하거나, 한 응답에 수사적 질문과 실제 질문이 함께 나오는 사례가 있었다. 이를 완전히 해결했다고 보지 않는다. 응답 필터나 고정 문장으로 보정하지 않았다.

## 추가 요청: 맥락 이탈을 즉시 지적
상대역 시스템 프롬프트에 직전 질문과 전체 대화 맥락으로 관련성을 판단하고, 무관한 발언에는 불만을 표현하며 원래 질문으로 돌리도록 추가했다. 고정 문장·분류 조건문·출력 치환은 추가하지 않았다. 거절·비공개·관련 확인 질문은 이탈이 아니라는 지시를 포함했다.

실제 Gemini 4개 시나리오 × 4개 후속 응답(16개)을 추가 검사했다. 합성 입력의 이탈 8건 모두 지적 후 기존 용건으로 돌아왔다. 대조 입력인 거절·비공개·관련 질문 8건은 무관한 화제로 취급하지 않았다. 자동 테스트 97개도 재통과했다. 원자료는 `.omo/evidence/off-topic-persona-20261014/final-actor.json`에 로컬 보관한다.

다만 무관한 말만 했는데 거절했다고 추정하거나, 관련 확인 질문에도 과하게 짜증내는 사례는 남았다. 원하는 까다로운 성격과 이탈 대응은 확인했으나 모든 대화의 자연스러움이 보장되는 것은 아니다. 실제 음성 입출력은 이번 검사 대상이 아니다.
