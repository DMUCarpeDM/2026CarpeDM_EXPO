# 시뮬레이션 Enter 수동 전송

PracticePage의 자동 제출을 비활성화했다. 음성인식은 계속 받아쓰며 사용자가 Enter를 누르거나 기존 전송 버튼을 누를 때 화면의 확정+임시 전사 내용을 보낸다. 제출 시 브라우저 인식을 중단하므로 speechend/final을 기다리지 않는다. 아직 브라우저가 전혀 전사하지 않은 음성은 전송할 수 없으며 임시 전사에는 오류가 있을 수 있다.

키보드 처리: 미러 배경 및 답변 입력창에서 Enter 전송, Shift+Enter는 줄바꿈, 한글 조합 Enter·반복 키·수정키 제외. 버튼과 링크, 다른 입력, 대화상자에서 단축키 제외. AI 발화/일시정지/처리/준비 중 차단. 중복 제출 잠금 추가. 앱 무음 감지는 추가하지 않았다.

브라우저 인식 훅의 다른 사용처를 보호하기 위해 자동 제출 기본값은 유지하며 실제 PracticePage가 autoSubmit:false를 전달한다.

검증: Chrome 브라우저의 모의 SpeechRecognition 회귀 테스트 11개 통과. 10초간 speechend 미발생 상황에서도 자동 제출되지 않으며 Enter로 확정+임시 전사 전송을 검증했다. 이는 실제 소음/육성 정확도 시험이 아니다. 프로덕션 빌드 성공. 현재 사용자 브라우저는 시작 안내 화면이므로 실제 음성 답변을 요청했다.

잡음 판단: speechend는 엔진이 음성으로 판단한 소리가 멈췄을 때 발생한다. 따라서 주변 사람 목소리나 음성으로 오인한 잡음이 계속되면 종료 판단이 늦어질 가능성이 있다(문서상 이벤트 정의에 기반한 추론). 모든 잡음이 종료를 막는다는 뜻은 아니며 장치/환경 실측이 필요하다. 수동 Enter 전송은 이 이벤트를 기다리지 않는다.
