## 2. 반복 재질문으로 가는 현재 조건

대체 대사를 선택하기 전에 다음 중 하나가 발생해야 한다.

1. AI 호출 실패: API 설정·인증 오류, HTTP 오류·시간 초과, 응답 구조 오류 등.
2. AI 결과가 비어 있거나 잘림: Gemini 후보가 없거나 본문이 없음, 토큰 한도 종료, 차단·비정상 종료 등.
3. 대사 형식 검사 실패: 180자 초과, 2문장 초과, 역할 이탈 표현, 마크다운·JSON 형태, 한글 없음, 쉼표로 끝나는 미완성 문장 등.
4. 상황 근거 검사 실패: `supported=false`, 잘못된 근거 인용, 잘못된 JSON, 검증 JSON `null`, 검증 호출 오류 등.

그다음 `continuous_fallback_line()`은 아래와 같이 결정한다.

```text
item.text가 비어 있지 않음
  AND 180자 이하
  AND 역할 이탈 문구가 아님
  AND 이전 AI 대사와 중복되지 않음
    → item.text 반환
그 외
    → “지금 이야기하던 용건에 대해 다시 말씀해 주시겠어요?” 반환
```

이 함수는 사용자 원문, 감점, 목소리 점수, 표정 점수로 문구를 선택하지 않는다. `case` 인자를 받지만 현재 함수 본문에서 사용하지 않는다. 기본 재질문 문구 자체가 이미 사용됐는지도 검사하지 않는다. 따라서 API나 검증 오류가 반복되고 첫 대사를 이미 사용했다면 동일 문구가 계속 반환된다.

장면 전환 중 생성 실패이면서 `act_open`과 이어받을 문맥 `carry`가 있으면 `act_bridge_line()`을 먼저 사용한다. 이 함수는 유효한 장면 첫 대사를 그대로 반환하며 대화 이력 중복 검사는 하지 않는다. 유효한 첫 대사가 없으면 위 공통 함수로 간다.

사용자 입력 JSON의 실제 `null`은 문자열 스키마에서 거절하고, STT 결과도 없는 빈 문자열은 422로 거절한다. 다만 문자열 `"null"`·`"undefined"`는 원격 제출 코드에서 별도 차단하지 않는다. 이것과 AI 검증 JSON `null`, 측정 점수의 `null`은 서로 다른 경우다.

반복 공통 문구는 제거했지만, 모든 대체 대사를 제거한 것은 아니다. 미커밋 파일 `poc/backend/app/seed/workplace-exhibition.json`에 3개 장면 × 5개 `recovery_lines`, 총 15개가 있다.
