# 인식 확정 후 제출 및 대화 우선 처리

## 변경
- Chrome 인식 확정 후 자동 제출 대기를 3000ms에서 750ms로 줄였다. 중간 발화가 들어오면 예약을 취소한다.
- 텍스트 답변 제출은 녹음 종료·WAV 변환을 기다리지 않는다. 변환 결과는 Promise로 분리해 보존한다.
- 직장 연속 시뮬레이션은 다음 대사를 생성·반환한 뒤 TTS 재생 시작 또는 재생 불가 신호를 받아 녹음 업로드와 내부 분석을 시작한다.
- 음성 분석과 응답·맥락 판정은 백그라운드 작업으로 계산한다. 작업자는 대화 중인 세션 JSON을 수정하지 않으며, 응답·맥락 판정에는 해당 턴까지의 대화와 저장한 상황만 사용한다.
- 보고서 단계에서 완료된 계산을 재사용하고 미완료 항목을 처리한다. 피드백·점수는 턴 순서대로 확정해 중복과 미래 대화 참조를 막는다.
- 마지막 답변은 다음 TTS가 없으므로 결과 분석 시작 전에 남은 업로드를 해제·완료한다.
- 직장 대화의 실시간 평가 팁 폴링을 중단한다. MediaPipe 실시간 추적과 표본 수집은 유지한다. 면접·카페 등 평가 결과로 후속 질문을 정하는 흐름은 기존 방식이다.
- 지연된 녹음 업로드 설정은 턴 메타데이터에 저장해 다음 턴의 대화 JSON을 덮어쓰지 않게 한다. 녹음 청크도 녹음 인스턴스별로 분리한다.

## 검증
- 실제 Chrome 시계로 가상 인식 확정 이벤트 후 입력 반영 1.4ms, 답변 요청 시작 751.7ms를 측정했다. 기존 3002ms 대비 약 75% 감소했다. 실제 발화 종료부터 Chrome 확정까지의 시간이나 외부 LLM 생성 지연을 포함한 값은 아니다.
- 요청 순서: response → tts → playing → audio. 변환 Promise가 미완료여도 response와 tts를 먼저 진행했다.
- 판정 함수를 호출하면 실패하도록 설정해도 5턴 대화가 완료된다. 이후 각 턴을 판정해 최종 응답 점수·잘한 점이 반환된다.
- 완료된 음성 및 응답 판정 작업을 다시 호출하지 않고 보고서에 재사용한다.
