## 이번 요청으로 바꾼 방식

이전에는 AI가 답을 써도 검사기가 거절하면 다른 말을 들려줬다. 이제 상대 AI가 보내 준 문장을 그대로 사용한다.

```text
사용자 발언 → 상대 AI 한 번 호출 → 받은 본문을 저장 → 자막·음성으로 전달
```

삭제한 처리:

- 한국어 여부, 문장 수, 길이, 말투·역할 이탈, 문장 끝 모양으로 대사를 거절하는 검사.
- 직전 대사와 비슷한지 비교하는 검사 및 자동 재작성.
- 별도의 AI로 상황 근거를 검증하는 호출.
- AI 대사의 화자 표시·따옴표·줄바꿈을 지우는 후처리.
- 생성 실패 시 공통 재질문·장면 첫 대사·장면별 대체 대사를 반환하는 경로.
- 로컬 전시 파일의 대체 대사 15개와 이를 진행표에 넣는 코드.
- 직장 연속 시뮬레이션에서 코드가 모순 확인 질문을 끼워 넣어 상대 AI 호출을 건너뛰는 경로.
- 음성 재생 단계에서 “질문”, “질문 2” 같은 본문을 임의로 읽지 않던 필터.

현재 대화 기록도 실제 발언을 JSON으로 인용해 전달한다. 과거 AI 대사를 정해진 대체 문자열로 가리지 않는다. 현재 인물·장면의 대화만 전달하는 범위는 유지한다.

## 답변이 없는 경우

AI가 실제 문장을 반환하면 그 본문을 사용한다. 본문이 없거나 통신이 실패하면 보여 줄 AI 답변 자체가 없으므로 HTTP 503 오류로 처리한다. 프로그램이 상대 대사를 만들어 넣지 않으며 사용자 답변·점수·진행 순서를 되돌려 현재 턴을 유지한다.

Gemini가 토큰 제한으로 끝났더라도 받은 대사 본문이 있으면 전달한다. 반면 채점·상황 분석·진행표의 JSON은 데이터 계산용이므로 완결성 검사를 유지한다. 이 검사 결과로 상대역 대사를 거절하거나 교체하지 않는다.

준비된 첫 질문, 사용자 빈 입력 처리, 시나리오 프롬프트, 사용자 답변 채점은 계속 사용한다. 상사·선임의 말투와 맥락 이탈 지적은 프롬프트로 유도한다. 따라서 모델이 반복하거나 이상한 말을 생성해도 앱이 재작성·교체하지 않는다. 첫 질문 이후의 직장 대사는 실제 모델 응답이다.

## 검증

- 관련 백엔드 테스트 **130개 통과**: 세 제공자의 원문 전달, 한 번 호출, 검증·재작성 없음, 5회 시연 완료, DB 본문 일치, 오류 시 턴·점수 보존, 모순 채점 유지, 기존 빈 입력 처리 등.
- 음성 조합·재생 테스트 **14개 통과**.
- 앱 소스에서 제거 대상 검증·대체 함수와 `recovery_lines` 참조가 남아 있지 않음을 확인했다.
- 실제 Vertex AI `gemini-3.5-flash-lite`에 가상 발언 2개를 전송했다. 두 응답 모두 호출 1회이며 원문과 전달 결과가 일치했다. 세션 DB·카메라·음성 원본은 사용하지 않았다.

실제 응답 예시:

1. 사용자: “그런데 오늘 점심은 피자를 먹을까요?”
   AI: “지금 점심 얘기할 때가 아니에요. 오류 난 숫자부터 언제까지 바로잡을 건지 결론만 얘기해 줘요.”
2. 사용자: 오류 범위와 고객 전달 여부를 확인하겠다고 답함.
   AI: “고객 전달 여부는 이미 확인하기로 했고, 원본 대조와 수정은 언제까지 끝낼 거예요?”

호출 시간은 각각 7.36초, 1.19초였다. 두 번의 관측값이며 일반적인 속도를 보장하는 측정은 아니다.

처음 넓게 실행한 테스트에서는 기존 `test_iris_path_and_invalid_response` 1건도 실패했다. 이 테스트는 `RIFFaudio`라는 유효하지 않은 WAV 샘플을 사용해 현재 음성 파일 검사에 실패한다. 해당 테스트와 `iris_tts.py`는 HEAD와 같으며 이번 변경 대상이 아니다. 이를 제외한 관련 테스트 130개가 통과했다.
