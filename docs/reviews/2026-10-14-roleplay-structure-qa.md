# 역할극 프롬프트 구조 조사·QA 결과

날짜: 2026-10-14. 기준 커밋: `5f51a19`. 판단: **입력 구조 개선 및 회귀 검증 완료. 생성 대사의 자연스러움·사실성은 추가 개선 필요.**

공식 자료와 수정 방법은 [설계 가이드](../architecture/roleplay-prompting.md)에 정리했다. 비공개 서비스의 실제 프롬프트를 복제하지 않았다.

## 구조에 대한 피드백과 반영

1. 사용자용 `situation`에 숨은 일정과 연습 안내가 포함되어 있었다. 새 상대역 경로에는 보내지 않는다.
2. 정체성·말투와 목적·동기·사실이 긴 persona 한 문자열에 섞여 있었다. `actor_persona`와 `actor_brief`의 명시적 필드로 분리했다.
3. 매 턴 intent와 최신 답 재인용이 같은 규칙·발화를 중복했다. 새 경로는 원문 기록을 한 번만 전달하며 턴별 intent는 제외한다.
4. 화자를 관점 의존적인 ‘당신/사용자’ 대신 ‘박선임/후배’로 명시했다.
5. 정보 부재를 ‘기한이 없음/미정’으로 바꾸지 않도록 unknown을 구분하고 예시를 추가했다.
6. 기존 5턴 흐름과 실제 AI 출력 원문 전달을 유지했다. 새 생성 분류기, 상태 머신, 요약 모델, 고정 응답, 출력 교체, 자동 재시도는 없다.

## 검증 순서와 관찰

| 단계 | 실행 | 결과 |
|---|---|---|
| 기준/최초 구조 비교 | 동일 8개 입력 × 변경 전후 각 1회 = 16개 실제 생성 | 구조 분리만으로 품질이 보장되지 않았다. 새 구조에서 A4 분량·오늘 마감 발명, 비공개 재질문이 발생하여 완료로 판정하지 않았다. |
| 행동 예시·우선순위 보강 | 같은 8개 입력 1회 | 분량·기한을 모른다고 응답, 명시적으로 거절한 만남을 재권유하지 않는 결과 확인 |
| 취약 사례 반복 | 사실성·대안 반복·전체 비공개 각 2회 = 6개 | 분량·마감 숫자 발명은 없었으나 비공개 사례 1회에서 소비 기준 재요구가 재발했다. |
| 실제 API 흐름 | 4개 시나리오 × 사용자 답변 5회 = 20응답 요청 | 모두 5회째 종료. 후속 생성 16개가 API 출력과 일치, 호출당 1회 생성. 모든 요청에 최초 목적·누적 이력 존재, 사용자용 situation 부재 확인. |
| 동기 분리 후 최종 스크립트 | 경계 사례 8개 + 동기 질문 4개 = 12개 | 역할 밖 코드 요청 미수행, 수락 조건 유지, 거절한 대안 재권유 감소. 설명 누락·화자 혼동·과민 반응은 남았다. |
| 최종 자동 회귀 | 8개 테스트 파일 | **127 passed**, Starlette 기존 deprecation 경고 1개 |

API 20응답 검사는 동기 필드를 별도 분리하기 직전 구조로 실행했다. 그 후 동기 필드 전달은 자동 테스트와 최종 실제 AI 12개로 확인했다. 모든 단계를 한 버전의 성공률로 합산하지 않는다. 실제 카메라·마이크·자막·TTS 검증은 수행하지 않았다.

## 잘된 출력과 남은 실패

보강 후 같은 질문:
> 오탈자 확인 방법은 문서를 보면서 틀린 글자를 찾아내는 거예요. 세부적인 분량과 마감은 아직 확인하지 못했는데, 그 두 가지를 먼저 확인해서 알려드리면 검토해 주실 수 있어요?

최종 수락 사례:
> 토요일 점심에 한식으로 매운 거 빼고 먹으면 되겠네요. 혹시 식사 장소는 특별히 가고 싶은 곳이 있나요?

최종 주말 동기:
> 업무 얘기만 하는 관계에서 벗어나서 조금 더 편하게 지내고 싶어서 물어본 거예요.

다음은 통과 처리하지 않은 항목이다.

- 최종 작업 설명은 오탈자 방법만 간단히 말하고 사용자가 물은 분량·마감 답을 누락했다.
- 반복 검사에서 소비 전체와 이유까지 비공개라고 했는데 소비 기준을 다시 요구한 사례가 있었다.
- 최종 소비 동기에서 ‘후배 돈’ 대신 ‘내 돈 쓰는 방식’이라고 화자를 혼동했다.
- 관련 질문에도 ‘무슨 이유가 더 필요해요’처럼 과하게 반응하거나, 단순히 이유를 물었는데 ‘지금 바로 하기 어려울 것 같다’고 추정한 경우가 있었다.
- API 연애 장면에서 모르는 사람을 만나는 부담을 일대일 만남 부담으로 좁혀 오해했다.
- 일부 API 복귀 응답은 의문문 대신 아직 답하지 않았다는 지적으로 끝났다. 맥락 복귀는 됐지만 모든 응답의 질문 형식 준수는 아니다.
- 기존 평가 엔진은 도움 시나리오의 ‘오탈자 확인 말고 Python 코드를 짜달라’를 여전히 `relevant_answer`로 판정했다. 상대역은 코드를 생성하지 않았다. 평가 프롬프트의 의미 판정은 이번 변경 범위에서 수정하지 않았다.

짧은 반복 생성만으로 통계적인 품질 향상률을 주장할 수 없다. 확실히 확인한 개선은 **정보 분리·목표/동기 명시·화자별 원문 전달·재현 가능한 QA**다. 생성 품질에 대해서는 위 관찰과 한계만 주장한다.

## 다음 개선 우선순위

- 최초 목적·의사 주체·이미 닫힌 범위를 평가하는 동일 QA 세트를 유지한다. ‘질문이 있다’만으로 합격시키지 않는다.
- 현재 모델에서 남는 주체 혼동·사실성 문제는 동일 입력으로 모델별 비교가 필요하다. 이번에는 모델이나 비용 설정을 바꾸지 않았다.
- 평가의 관련성 오류는 상대역 품질과 별도 회귀 사례로 수정해야 한다.
- 5턴 내내 질문하는 요구는 답변 범위가 완전히 닫힌 상황과 긴장이 있다. 이번에는 같은 제안을 앞으로 어떻게 꺼낼지 묻도록 설계했지만 반복을 완전히 방지하지는 못한다.
