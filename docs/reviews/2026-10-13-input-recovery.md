# 빈 입력과 반복 대체 대사 수정

## 원인

- 이전 반복 방지 수정 뒤에도 `continuous_fallback_line()`의 마지막 예외 경로에는 공통 재발화 요청 문구가 남아 있었다. 모델 생성·형식·근거 검증 실패 후, 준비된 대체 대사가 없거나 모두 사용된 경우 이 문구를 계속 반환했다.
- 이전 세션에는 새 `recovery_lines`가 저장돼 있지 않다. 전시 외의 기존 연속 대화 경로도 이 마지막 대체 경로에 도달할 수 있었다.
- 실제 JSON `null`·빈 문자열은 원래 입력 검증에서 거부된다. 그러나 문자열 `"null"`, `"undefined"`, 명백한 잡음 전사는 후속 대사 생성까지 넘어갈 수 있었다. 잡음은 평가만 보류하고 턴은 진행하던 구조였다.
- 목소리/응답 **점수**의 `null`은 측정 자료 부족·판단 보류·분석 실패를 뜻한다. 그 값이 직접 해당 대사를 선택하는 조건은 아니다.

## 변경된 동작

1. 공통 재발화 요청 대사를 삭제했다. 모델이 같은 문구를 만들어도 전달하지 않고 재작성 대상으로 처리한다. 이전 대화 기록의 해당 문구도 상대역 프롬프트에서 가린다.
2. 직장 대화에서 빈 값, `null`/`undefined` 문자열, 명백한 잡음은 422로 반환한다. 사용자 답변·점수·진행 순서를 저장하지 않고 현재 턴에서 재입력한다. 짧은 수락이나 의미 있는 확인 질문은 허용한다.
3. 이전에 시작한 전시 세션도 장면 ID/상황이 일치하면 해당 장면에 직접 작성한 대체 대사를 사용한다. 다른 장면의 문구는 가져오지 않는다.
4. 검증된 대사가 더 없으면 503 오류 안내만 반환한다. 사용자에게 다시 말하라는 가짜 상대 대사를 생성하지 않고 현재 턴과 점수를 유지한다. 이 상황에서는 재입력이 필요하다.
5. 제출 실패 후 프런트엔드가 같은 턴에서 녹음과 음성 인식을 다시 시작한다. 실패한 초안은 지우고 새 발화를 받으며, 이전 AI 음성을 다시 재생하지 않는다.
6. 정상 맥락 이탈 판단과 상대역의 꾸짖는 응답은 유지한다. 평가 결과가 `unavailable`이더라도 대사 생성이 성공하면 정상 대화를 계속한다.

## 검증

- 백엔드 관련 테스트 141개 통과: 입력 거부, 점수/턴 보존, 모델의 삭제 문구 재생성 차단, 이전 전시 세션의 대체 대사 복구, 생성 실패 503 처리, 의미 있는 답변 및 맥락 이탈 처리.
- 실제 Chrome 자동 테스트 1개 통과: 422 → 503 → 정상 응답 순서에서 같은 턴으로 재제출, 새 녹음 시작, 중복 TTS 없음, 성공 후에만 다음 턴 이동. 가짜 카메라·마이크 사용.
- 프런트엔드 프로덕션 빌드 성공. 기존 번들 크기 경고는 남아 있다.
- 실제 Vertex AI `gemini-3.5-flash-lite`로 가상 발언 3회 실행: 무관한 발언 두 번 → 업무 답변 복귀. 세 후속 대사 모두 생성 성공, 대체 대사 0회, 삭제 문구 0회.

- 정상 복귀: “고객 전달 여부 확인부터 빨리 해줘요. 원본 대조는 그 다음에 어떻게 할 건데요?”
