# Expo 앱: 프롬프트 기반 실시간 시나리오

## 변경한 사용자 흐름

일반 앱의 면접·직업훈련·직장대화 홈 → 프롬프트 입력 → 난이도 → 동의·생성 시작 → 기존 대화 화면 → 기존 분석·리포트.

사용자가 작성한 상황을 `POST /api/sessions`의 `scenario_prompt`로 전달한다. 동일 요청에 준비된 `scenario_slug`, `selected_episode_id`, NFC 또는 전시 플래그를 섞으면 422로 거절한다. 하드웨어 경로는 기존 계약을 보존한다.

## 생성과 대화

- `app/services/prompt_scenario.py`가 현재 설정된 OpenAI·Gemini·Ollama 제공자를 사용한다. 키나 제공자 설정을 변경하지 않았다.
- 인물 이름·역할·배경·목표·사용자와의 관계·성격·말투, 장면 배경·갈등·사용자 역할·목표 3개·첫 대사를 JSON으로 생성한다. 면접에는 주요 질문 6개도 포함한다.
- Pydantic으로 구조·분량을 검증하고, 기존 Scenario/Episode 모델에 저장한다. 시작 대사는 같은 생성 응답에서 얻으므로 첫 대사만 다시 생성하는 추가 호출이 없다.
- 생성 Scenario는 `is_active=False`, UUID 기반 slug를 사용한다. 공용 `/scenarios` 및 slug 조회에 노출하지 않고, 세션 토큰을 통해서만 세션 응답에 포함한다. 새 테이블이나 DB 마이그레이션은 필요 없다.
- 후속 대사는 기존 제공자가 생성된 인물·배경과 실제 대화 이력을 받아 생성한다. 비면접은 목표 기반 대화, 면접은 새로 생성한 주요 질문을 따르는 기존 면접 진행 구조를 재사용한다.
- 생성 실패는 503을 반환하며 준비된 팩으로 넘어가지 않는다. 프론트 입력·난이도·동의 상태는 유지되어 사용자가 재시도할 수 있다.
- 생성된 목표는 학습용 분석 자료다. 분석의 정확성이나 객관적인 역량 평가를 이 변경으로 새롭게 입증한 것은 아니다.

## 실제 AI 검증

2026-10-18, 기존 OpenAI 설정으로 개인 정보 없는 개발 일정 협의 프롬프트를 사용했다. 별도 SQLite 테스트 DB(`/private/tmp/mirror-prompt-expo-20261018.db`)로 실행해 기존 운영 DB를 변경하지 않았다.

- 세션 생성: HTTP 200, `source=user_prompt`, 4.08초.
- 생성 제목: 신규 기능 출시 일정 협의.
- 생성 첫 대사: “신규 기능 출시 일정과 범위에 대해 이야기해볼까요? 현재 일정에 맞추기 위해서는 몇 가지 조정이 필요할 것 같은데, 어떻게 생각하시나요?”
- 사용자 샘플 답변: 핵심 기능부터 배포하고 추가 기능을 다음 배포로 분리해 테스트 시간을 확보한다는 제안.
- 후속 응답: HTTP 200. 해당 제안을 받아주고 핵심 기능 배포의 구체적인 일정과 계획을 요청했다.
- 공용 시나리오 목록에서 생성 장면이 보이지 않음을 확인했다.

이는 한 번의 실제 샘플 검증이다. 4.08초는 평균·p95 또는 지연 보장이 아니다. 모델의 일관성·의미 판단 성능 전체를 검증한 수치도 아니다. API 키·세션 토큰은 이 기록에 포함하지 않았다.

## 검증과 기존 문제

- 프롬프트 생성·권한·세션 복구 API 테스트 15개 통과.
- 프론트 API 계약·홈 콘텐츠 테스트 26개 통과.
- 서비스 진입·이전/다음·복구 브라우저 테스트 10개 통과. 프롬프트 입력·난이도·생성 전 동의 화면을 390/768/1440px에서 확인했다.
- 방문자 격리 브라우저 검증 중 기존 미러 TTS 대기 및 진행 중 새로고침 테스트 2개는 음성 시작 대기에서 시간 초과했다. 해당 두 실패는 변경 전 코드로 재현 여부를 확인하지 않았으므로 기존 문제로 단정하지 않는다. 생성 응답이 방문자 초기화 후 도착하는 격리 테스트는 통과했다.
- 프로덕션 빌드 통과: `/private/tmp/mirror-prompt-final-20261018`. 기존 `dist/assets` 비우기에서 ENOTEMPTY가 발생해 기존 산출물을 삭제하지 않고 별도 출력 경로로 확인했다.
- 기존 `test_workplace_generates_all_three_turns_without_waiting_for_scoring`은 세 번째 답변에서 종료되지 않아 실패했다. `git show HEAD:poc/backend/app/api/sessions.py`를 임시 경로에서 로드한 변경 전 endpoint로도 같은 실패를 재현했다. 이번 생성 변경과 분리해 남겼으며 전시 종료 규칙은 수정하지 않았다.

## 실행

기존 backend 설정과 데이터베이스로 운영하려면 개발자 온보딩 안내대로 서버를 재시작한다. 이번 검증용 앱은 `http://127.0.0.1:5175/?service=workplace`에서 열 수 있다. 시작 버튼 후 자유 입력을 사용한다. NFC·미러의 자동 전시 흐름은 이번 변경 대상이 아니다.

## 첨부 레퍼런스에 맞춘 첫 화면 구조 (후속 변경)

- 서비스 선택만 보이던 일반 웹 진입 화면을 상단 내비게이션 + 중앙 프롬프트 입력 + 아래 기존 설명 콘텐츠로 변경했다.
- 면접·직업훈련·직장대화 설명과 예시를 삭제하지 않았다. 모드 버튼은 입력창 아래에 두고, 모드를 바꿔도 입력한 프롬프트를 유지한다.
- 입력창의 제출 버튼 → 난이도 → 동의 → 기존 실시간 생성 API로 연결한다. 아래 설명의 연습 버튼은 위 입력창으로 돌아가 초점을 준다.
- 기존 백업 `backups/prompt-first-20261018-162941`은 보존했다. 이번 후속 변경은 서버 생성 로직과 DB를 변경하지 않는다.
- 390/768/1440px에서 입력 유지, 모드 변경, 소개 내용 보존, 난이도 왕복 및 동의 화면을 확인했다. 해당 브라우저 테스트와 API 계약·콘텐츠 단위 테스트 합계 27개 통과. 빌드 출력 `/private/tmp/mirror-landing-20261018` 성공.
- 이전 서비스 선택 카드 화면을 전제한 다른 브라우저 테스트 전체는 이번에 실행하지 않았다.

## 직업훈련 제거 및 첫 화면 문구 정리 (최신 요청)

- 직업훈련 선택·소개·예시, 카페/상담 직무 카탈로그, 전용 이미지·영상·브랜드 이미지와 시나리오 원본을 삭제했다. 면접·직장대화 설명은 유지한다.
- 첫 입력창의 모드·글자 수 표시, MIRROR-TING 부연 문구, 서비스 소개 앵커 링크를 삭제했다.
- API는 새 `training` 요청을 거절한다. 기존 DB의 훈련 시나리오도 공개 목록·직접 조회·새 세션에서 제공하지 않는다. 서버 시작 시 기존 seed 정책에 따라 은퇴시키며 기존 세션·보고서 기록은 삭제하지 않는다.
- 입력한 직장대화는 `goal_based` 상태로 진행하며, 직업훈련 모드에 의존하지 않는다. 면접의 실시간 생성 구조도 유지한다.
- API 회귀 15개 및 프론트/브라우저 검증 37개 통과. 390/768/1440px에서 제거 문구·모드 버튼과 입력·동의 흐름 확인. 빌드 출력 `/private/tmp/mirror-no-training-20261018` 성공.
- 기존 백업은 그대로 보존한다. 예전 직업훈련 기능을 전제한 전체 레거시 테스트를 이번에 모두 갱신하거나 실행한 것은 아니다.
