# ② 하프미러 × 적외선 검증 절차서

> **미해결 리스크 하나를 닫기 위한 문서.** 발주서(`docs/hardware-order-55.md`)의 부스 구성은 하프미러 아크릴 뒤에 디스플레이인데, Kinect 뎁스는 근적외선 능동 조명이다. **이 둘이 같이 되는지 아무도 안 쟀다.**
> 근거 표기: **[사실]**=장비 사양·물성 · **[추론]**=물리에서 유도, 실측 아님 · **[미확인]**=재봐야 앎.
> 작성 2026-07-29.

---

## 0. 왜 이 문서가 필요한가

발주서에 **키넥트가 없다.** 부스 BOM의 카메라 항목은 "웹캠 1080p · 미러 상단 중앙"뿐이다. 즉:

1. 하프미러 뒤에서 뎁스가 동작하는지 **검증 계획이 존재하지 않는다**
2. 키넥트 거치·배선·전원이 리그 설계에 **반영되어 있지 않다**

리그가 완성된 뒤에 이걸 발견하면 골조를 다시 짜야 한다. **아크릴 샘플이 손에 들어오는 즉시 §2를 돌려야 한다.**

---

## 1. 무엇이 문제인가

### 1.1 장비 [사실]

Azure Kinect DK의 뎁스는 **ToF(Time-of-Flight)** 방식이고, **850nm 근적외선**을 능동 조사한 뒤 되돌아온 빛의 위상차로 거리를 잰다. 즉 **자기가 쏜 빛이 왕복해야** 값이 나온다. 수동 카메라(웹캠)와 결정적으로 다른 점이다.

### 1.2 예상되는 실패 모드 두 가지 [추론]

> 아래는 물리에서 유도한 것이고 **실측이 아니다.** 실제 필름·코팅 종류에 따라 다르므로 §2로 확인해야 한다.

**⚠️ 실패 모드 A — 왕복 감쇠**

하프미러는 빛의 일부만 통과시킨다. 능동 조명이 나갈 때 한 번, 반사광이 돌아올 때 또 한 번 깎인다.

```
투과율 T라면 왕복 신호 = T × T = T²
T = 0.30 (가시광 30% 투과 제품)  →  왕복 9%
```

ToF는 신호 대 잡음비가 곧 거리 정밀도라, 신호가 10분의 1이 되면 **뎁스 노이즈 급증 → 픽셀 드롭아웃 → 포인트 클라우드 붕괴**로 이어진다. 표면 측정(`surface.py`)은 최소 200점을 요구하므로 여기서 먼저 죽는다.

**❗ 실패 모드 B — 자기 반사 (더 위험)**

조명과 센서가 **같은 유리 뒤에** 있으면, 나가던 IR의 일부가 아크릴 안쪽 면에서 곧바로 센서로 되튄다. ToF 입장에서 이건 **거리 0에 있는 초강력 반사체**다. 결과는 근거리 포화 — 전체 프레임이 무효화되거나 거리값이 통째로 어긋난다.

이건 감쇠와 달리 **노출을 올려서 해결되지 않는다.** 오히려 악화된다.

### 1.3 알루미늄 증착의 특수성 [추론]

국내 유통 하프미러 아크릴은 대개 **알루미늄 증착**이다. 알루미늄은 가시광에서 근적외선까지 반사율이 높고, 850nm에서 가시광보다 **떨어지지 않는다**. 즉 "눈에는 반투명한데 IR은 잘 통과하겠지"라는 기대는 성립하지 않을 가능성이 높다.

유전체(dielectric) 코팅 제품은 파장 선택성이 있어 결과가 다를 수 있다. **업체에 코팅 방식을 물어봐야 한다** — §3 견적 템플릿에 추가했다.

## 2. 검증 절차 — 아크릴 샘플 도착 즉시, 30분

### 준비물

- 하프미러 아크릴 샘플 (3T·5T 각각. **재단 전 자투리로 충분** — 손바닥만 해도 된다)
- Kinect DK + 실행 PC
- 줄자

### 실행

레포에 이미 있는 도구를 쓴다. 새로 만들 것 없다.

```bash
.venv/Scripts/python -m app.kinect.viewer
```

뎁스 영상 + 스켈레톤 오버레이가 뜬다. `[q]`로 종료.

### 측정 4단계

| 단계 | 조건 | 확인 |
|---|---|---|
| **0. 기준선** | 아크릴 없음. 사람이 1.2m에 정면으로 섬 | fps, 관측 관절 수, 거리값을 **줄자 실측과 대조**. 이게 정답지다 |
| **1. 감쇠** | 아크릴을 **렌즈 전면에 밀착**. 같은 자세 | 뎁스가 나오는가? 드롭아웃 비율? 거리값이 0단계와 일치하는가? |
| **2. 자기 반사** | 아크릴을 렌즈에서 **2~5cm 띄움** (실제 리그와 같은 간격) | ★ **가장 중요.** 근거리 포화가 뜨는가? 화면 전체가 빨갛게(가까움) 물들면 실패 모드 B |
| **3. 실사용** | 아크릴 뒤에 **디스플레이를 켠 상태**로 2단계 반복 | 디스플레이 백라이트가 IR 노이즈를 더하는지 |

### 3T / 5T 각각 반복

발주서가 5T를 권장(3T는 122cm 높이라 휨)하므로 **5T 결과가 실사용 값**이다. 3T는 참고.

### 판정 기준

| 결과 | 판정 |
|---|---|
| 거리 오차 **1cm 이내**, 드롭아웃 **5% 미만**, 관측 관절 수 0단계 대비 **90% 이상** | ✅ 통과 — 미러 뒤 거치 가능 |
| 거리는 나오나 노이즈·드롭아웃 증가 | ⚠️ 조건부 — §4 대안 1(개구부) 검토 |
| 근거리 포화 / 뎁스 전멸 / 거리값 이상 | ❌ **실패 — §4 대안 2 확정** |

### 기록

| 조건 | fps | 관측 관절 | 실제거리 | 측정거리 | 오차 | 드롭아웃 | 비고 |
|---|---|---|---|---|---|---|---|
| 0. 기준선 | | | 120cm | | | | |
| 1. 밀착 5T | | | 120cm | | | | |
| 2. 이격 5T | | | 120cm | | | | |
| 3. 이격+디스플레이 | | | 120cm | | | | |

> 이 표를 채우면 그대로 **심사 답변 근거**가 된다. "미러 뒤에서도 되나요?"에 실측으로 답할 수 있다.

## 3. 견적 시 추가 질문

발주서 §3의 하프미러 견적 템플릿에 **한 줄 추가**:

> 추가로, 해당 하프미러의 **코팅 방식(알루미늄 증착 / 유전체 다층막 등)**과 가능하다면 **근적외선(850nm) 대역 투과율**을 알려주실 수 있을까요? 뒤에 적외선 방식 3D 센서를 두는 구조라 해당 파장의 투과 특성이 중요합니다.

업체가 850nm 수치를 못 주는 게 정상이다(대개 가시광 기준만 관리). **그래서 §2 실측이 필요한 것이고**, 질문 자체는 코팅 방식만 알아도 값어치가 있다.

## 4. 실패 시 대안 — 3안

### 대안 1 — 미러에 개구부 (IR 윈도우)

키넥트 렌즈 위치만 아크릴을 **타원형으로 도려낸다.**

- 장점: 리그 구조 유지, 뎁스 성능 100%
- 단점: 미러 면에 구멍이 보인다. **"검정=거울" 문법이 깨진다** — 헌장 위반 소지
- 완화: 개구부를 화면 최상단 베젤 영역(반사 존 밖, `hardware-order-55.md §4`의 0~18% 구간)에 두고 무광 블랙 링으로 마감. 이 구간은 어차피 아바타·스피커 영역이라 반사를 안 쓴다

### 대안 2 — 미러 밖 상단 노출 거치 ★ 권장

키넥트를 아크릴 **앞쪽 상단**에 별도 브래킷으로 노출 거치.

- 장점: 검증 불필요. 뎁스 성능 100%. 화각도 오히려 유리(위에서 내려다보는 각도가 전신 커버에 좋다)
- 단점: 장비가 보인다
- 완화: **이걸 숨기지 말고 연출로 쓴다.** 무광 블랙 하우징 + "거울이 당신을 본다"는 서사에 오히려 부합. 심사위원에게는 "이게 3D 센서입니다"라고 짚을 수 있는 물리적 증거가 된다 — 기술성 어필에 유리
- **중력 정렬이 이미 구현돼 있어 틸트 각도가 자유롭다** (`geometry.py`) — 이 대안이 성립하는 이유

### 대안 3 — 뎁스 포기, MediaPipe 폴백

현재 전시 경로가 이미 MediaPipe다. 키넥트를 **발표 전용 데모**(별도 화면 `:8002`)로만 운용.

- 장점: 리스크 0
- 단점: 실전에서 뎁스 우위가 사라짐. 다만 **"기술은 있고 이번 부스에는 이렇게 넣었다"**는 설명은 가능

## 5. 결정 순서

```
아크릴 샘플 도착
   ↓
§2 검증 (30분)
   ↓
통과 → 미러 뒤 거치. 리그 설계에 키넥트 마운트 추가
조건부 → 대안 1(개구부) 재검증
실패 → 대안 2(외부 거치) 확정 → 리그 상단 브래킷 설계
   ↓
어느 쪽이든 §6 배선 확정
```

> **§2를 안 돌리고 리그를 완성하면 안 된다.** 대안 1·2 모두 골조 변경이 필요하고, 조립 후에는 되돌리기 비싸다.

## 6. 검증과 별개로 리그에 반영해야 할 것 [미확인 — 발주서에 없음]

키넥트가 부스 설계에 아예 없어서, 검증 결과와 무관하게 확정해야 하는 항목들:

| 항목 | 내용 |
|---|---|
| **거치 높이·각도** | `device.py` 실측에서 유효 거리 하한이 100cm인데 전시 설계가 "미러 앞 1m"라 **정확히 경계선**이다. 리그 완성 후 실제 높이에서 재확인 필요 |
| **화각** | WFOV 기준 1m에서 수직 3.46m 커버. 상단 거치로 아래를 보면 실효 커버가 줄어드니 **기립 관람객 전신이 들어오는지** 실측 |
| **케이블** | USB 3.0 + 전원. 표준 USB 3.0은 3m 내외가 한계라 55" 세로 리그 상단→PC 경로가 길면 **액티브 케이블**이 필요. 발주서 배선 항목에 미반영 |
| **전원** | 부스 요청사항의 전력 용량 산정에 키넥트가 안 들어가 있다 (8월 중 제출 항목) |
| **발열** | LRR이 이미 지적한 항목 — 4일 연속 가동. 키넥트 + RTX 3060 동시 부하 |
| **예비기** | ⚠️ **Azure Kinect DK는 2023년 단종됐다.** 고장 시 즉시 조달이 불가능하다. 4일 전시에서 단일고장점이며, LRR의 "하드웨어 단일고장점" 항목보다 심각하다. → MediaPipe 폴백 경로를 **끝까지 살려두는 것이 유일한 현실적 대비**다 (대안 3이 폴백으로 상시 존재해야 하는 이유) |

## 7. 한 줄 요약

**아크릴 샘플이 오면 30분만 쓰면 닫히는 리스크인데, 안 닫으면 리그를 다시 짜야 한다.** 결과가 어느 쪽이든 대안이 준비돼 있으므로 프로젝트를 위협하지는 않는다 — **모르는 상태로 조립하는 것**만 위험하다.
