# Pose-Fit 앙상블 연결

Carpediem.ipynb의 마지막 추론 셀을 기준으로 연결했다. MediaPipe Heavy에서 이미지 좌표 랜드마크 0, 11, 12, 13, 14, 15, 16, 23, 24를 순서대로 읽고, 3차원 어깨 중심을 빼고 3차원 어깨 폭으로 나눈 27개 값을 사용한다. worldLandmarks를 섞지 않는다. x/y 범위는 -0.05~1.05, 어깨 폭은 0.005 이상이어야 하며 결측·비유한 좌표는 측정에서 제외한다.

RF와 LightGBM의 양성 확률을 1:1 평균한다. 고개 숙임과 상체 앞으로 숙임은 0.45, 나머지는 0.5에서 활성화한다. 독립 이진 분류 6개이므로 여러 라벨이 동시에 활성화될 수 있다. normal은 기록용이며 자동 가점을 만들지 않는다.

배포 모델은 app/ai/assets/posture_ensemble_v1의 ONNX 12개다. 기존 Python/scikit-learn 환경을 유지하기 위해 학습 환경에서 변환했다. 원본 해시는 metadata.json에 기록했다. export_posture_ensemble.py는 신뢰한 joblib 원본만 입력받는 오프라인 도구이며, 서버가 사용자 업로드 pickle을 실행하는 API는 없다. 공식 scikit-learn 문서의 버전 간 pickle 호환 제한을 피하기 위한 구성이다: https://scikit-learn.org/stable/model_persistence.html

## 실행 및 검증

서버 requirements.txt의 onnxruntime를 설치한다. 프론트는 Heavy 랜드마크 파일을 사용한다. 각 프론트의 setup-offline 스크립트로 전시 전에 파일을 받아두며, 파일이 없으면 공식 CDN으로 연결한다. 전시 장비에서는 Heavy의 처리 속도를 확인해야 한다.

변환 도구 환경: Python 3.11, scikit-learn 1.6.1, lightgbm 4.6.0, joblib 1.4.2, skl2onnx 1.20.0, onnxmltools 1.16.0. 변환 시 1,024개 고정 입력에 대해 각 원본 모델의 확률과 비교해 오차 1e-5 이하를 요구한다. golden.json의 16개 참조 입력은 서버 회귀 검사에 사용한다. 이는 변환 일치 검사이며 실제 사용자 정확도 검사는 아니다.

## 점수와 미측정

프론트가 턴별 유효 특징을 pose_ensemble로 전송한다. 요청당 최대 1,500개를 저장하며 이후 표본은 추가하지 않는다. 기록한 표본만 판정하며, 이를 전체 턴의 연속 행동 시간으로 해석하지 않는다. 서버는 유효 표본 15개 및 3초 이상을 요구한다. 모델 경로가 요청됐는데 표본 부족·추론 오류가 나면 과거 기하 규칙으로 대체하여 점수를 만들어내지 않는다.

초기 연결 정책은 유효 표본 중 라벨 활성 비율 45% 이상일 때 해당 턴의 공통 부정 이벤트 하나를 만든다. 분모는 유효 모델 표본이며 미검출 시간을 넣지 않는다. 이 비율 정책은 학습 임계값과 별개이며 현장 보정 대상이다. 점수는 기존 75점 기본값과 라벨별 -4점, 세션 반복 상한을 유지한다. 노트북의 -15점은 시뮬레이션이므로 적용하지 않았다. 팔짱 이벤트를 추가했으며 신규 모델에 없는 흔들림은 이 경로에서 생성하지 않는다.

관찰 API의 팁과 답변 제출의 공통 판단이 같은 모델을 사용한다. 모델을 보내지 않는 이전 클라이언트는 기존 판단 경로를 유지한다. 모델 확률·기준·유효 표본을 점수 근거에 남긴다. 원본 영상은 전송하지 않는다.

학습 노트북은 좌우 반전 증강 후 무작위 분할하고 전체 데이터에 imputer를 먼저 fit한다. 따라서 출력된 F1을 사람별 분리 검증 성능으로 간주할 수 없다. 실제 전시 영상과 별도 인물 데이터로 오탐·성능 검증이 남아 있다.
