### 2.1 일정 역산 — 실질 준비 기간은 8일이 아니라 7일

### 2.2 리허설과 마감이 같은 날인 것의 함정 **[추론-높음]**

리허설 창(10:00~15:00)이 제출 마감(13:00)을 **가로지릅니다.**

```
10:00 ─────── 13:00 ─────── 15:00
   │ 수정 가능 │  수정 불가   │
   └─ 3시간 ──┘
```

- 리허설에서 **레이아웃 깨짐·폰트 깨짐·영상 미재생**을 발견해도, 13:00 이후에는 반영할 수 없습니다.
- "기한일 이후 제출 불가"가 명시되어 있으므로 재업로드 가능성을 전제하면 안 됩니다. **[확정]**

**대응**: 8/2에 최종본을 확정하고, 8/3 10:00 시점에 이미 완성된 PDF를 들고 가서 **검증만** 합니다. 문제 발견 시 수정에 쓸 수 있는 시간은 최대 2.5시간이며, 이는 "글자 크기 조정" 수준의 작업만 가능한 시간입니다.

### 2.4 PPT → PDF 변환에서 손실되는 요소 **[추론-높음]**

PDF는 정적 문서 포맷이므로 다음이 모두 소실되거나 불안정해집니다.

| 요소 | PDF 변환 후 |
|---|---|
| 화면 전환 효과 | 전부 소실 |
| 개체 애니메이션 (등장/강조) | 전부 소실 → **겹쳐서 배치한 개체가 한꺼번에 보임** |
| 삽입 영상 | 재생 불가 (링크로만 남거나 첫 프레임 정지 이미지) |
| GIF | 첫 프레임 정지 |
| 오디오 | 소실 |
| 폰트 | 임베딩 안 하면 대체 폰트로 치환 → **줄바꿈·레이아웃 붕괴** |
| 하이퍼링크 | 대체로 유지되나 뷰어·네트워크 의존 |

**가장 흔한 사고**: 애니메이션으로 순차 등장시키려고 개체를 겹쳐 놓은 슬라이드 → PDF에서 전부 겹쳐 보임 → 판독 불가.

> **규칙: 모든 슬라이드는 "정지 상태에서 그 자체로 읽히도록" 설계한다.** 순차 설명이 필요하면 애니메이션이 아니라 **슬라이드를 분리**합니다.

### 2.5 영상 제출 조건의 이중 함정 **[확정 + 추론]**

> "PDF에 링크된 영상이 있는 경우 함께 제출" **[확정]**

이 문구는 두 가지를 동시에 뜻합니다.

1. 영상 링크를 넣는 것은 **허용**된다. **[추론-높음]**
2. 그러나 링크만으로는 부족하다고 학교가 판단하고 있다 → **재생 실패 가능성을 학교도 전제하고 있다.** **[추론-중간]**

**3중 안전장치 (권장)**

| 층 | 수단 | 목적 |
|---|---|---|
| 1차 | 영상 파일 별도 제출 | 심사장 PC에서 직접 재생 |
| 2차 | PDF 내 링크 | 파일 누락 시 대체 경로 |
| 3차 | **핵심 장면 3~4컷 정지 캡처를 슬라이드에 삽입** | 영상이 전부 실패해도 시연 내용 전달 |

3차가 없으면 영상 재생 실패 시 **완성 가능성 20점의 근거가 통째로 사라집니다.** 이것이 이 문서에서 가장 강조하는 단일 실행 항목입니다.

### 2.6 시간 구조 계산 **[계산]**

```
심사 가능 시간 = 9:30~17:30 (480분) − 점심 60분 = 420분
팀당 실제 슬롯 = 발표 5분 + 질의응답 5분 + 정리·교대 2분 = 12분
최대 수용 팀 수 = 420 ÷ 12 = 35팀
```

- 슬라이드의 "팀당 발표시간 10분"은 **발표+질의응답**을 뜻하며, 교대 2분은 별도입니다.
- 참고: 이전 자료 기준 신청 팀은 33개 **[추론-중간, 변동 가능]** → 35팀 상한에 거의 근접. **여유가 거의 없습니다.**

**함의**: 5분 초과 시 진행상 제지될 가능성이 높습니다. 뒤 팀이 밀리는 구조이기 때문입니다.

**발표 대본 분량 산정**
- 한국어 발표 속도 기준치: 분당 약 300~350자 **[추론-중간 — 일반적으로 통용되는 참고치이며, 개인차가 크므로 반드시 직접 측정할 것]**

- → **슬라이드 실질 6~8장**이 상한

| 작품이 활용성 및 실용성이 있는가 | 실사용 시나리오가 있는가 | 구체적 사용자 1명을 지정해 서술 |
| **개발 작품이 실험 실습에 사용될 수 있는가** | **교내 교보재로 재사용 가능한가** | 오픈소스 공개·모듈화·문서화 계획 명시 |
| 해당 아이디어로 창업이 가능한가 | 수익 모델이 상상 가능한가 | "누가 돈을 내는가" 한 문장 |

**두 번째 질문이 특이 항목입니다. [추론-높음]**

일반적인 공모전 평가표에는 없는 항목이며, 심사위원에 학부장 6명이 포함된 구성과 맞물립니다. 학교 입장에서 출품작은 전시로 끝나는 것이 아니라 **후배 교육 자산**으로 남길 대상입니다.

> **실행**: "본 작품의 소스코드와 데이터 파이프라인은 P.D.Lab 내부 문서로 정리하여 후속 팀이 확장할 수 있도록 한다" 수준의 한 줄이라도 슬라이드에 넣으면 직접 득점 가능성이 있습니다.

#### 3.2.2 "대학홍보 및 외부 경쟁력"

| 원문 질문 | 실제로 묻는 것 |
|---|---|
| EXPO에서 우리 대학에 대한 홍보효과가 높은가 | 부스에서 사람을 세울 수 있는가 (시각적 임팩트) |
| **외부 경진대회 출품 시 경쟁력이 있는가** | **이 작품이 대외 수상 실적으로 이어질 수 있는가** |

**[추론-높음]** 두 번째 질문은 매우 직접적인 힌트입니다. 학교 입장에서 EXPO 출품작은 대외 수상 실적의 파이프라인이며, 이 항목이 그것을 명문화한 것입니다.

> **실행**: **"본 작품은 ○○ 공모전(20xx년 x월 접수)에 출품 예정"**을 슬라이드에 구체적 대회명·시기와 함께 명시합니다. 막연한 "대외 대회 도전 예정"보다 실명이 훨씬 강하게 작용합니다.

#### 3.2.3 감점 위험

- 사용자·수요에 대한 언급 없이 기술 설명만 하는 구성
- "누구나 쓸 수 있습니다" 같은 대상 불특정 서술
- 외부 대회 계획 부재

### 3.3 영역 2 — 기술성 (20점)

#### 3.3.1 두 세부 요소가 서로 반대 방향을 본다

| 세부 요소 | 원문 질문 | 요구하는 것 |
|---|---|---|
| 우수성 및 유용성 | 기술 적용이 적절한가 / **쉽고 편리하게** 작동하는가 / **원활하고 자연스럽게** 구동되는가 | 사용성·안정성 |
| 기술 난이도 | **지속적인 개발이 가능한가** / 기술 수준이 **낮지 않고** 난이도가 적정한가 | 기술 깊이 |

**[추론-높음]** 이 둘을 한 슬라이드에 섞으면 양쪽 모두 놓칩니다. 증명 수단을 분리해야 합니다.

| 증명 대상 | 증명 수단 |
|---|---|
| "쉽고 편리하고 원활하다" | **시연 영상** — 지연·오류·재시도 장면 없이 편집 |
| "기술 수준이 낮지 않다" | **아키텍처 다이어그램 1장** — 구성요소·데이터 흐름 표시 |
| "지속적 개발이 가능하다" | **확장 로드맵** — 다음 단계 기능 2~3개 |

#### 3.3.2 "원활하고 자연스럽게"의 무게 **[추론-중간]**

세 질문 중 두 개가 **작동 품질**에 관한 것입니다. 이는 EXPO 본 전시가 4일간 연속 가동되는 산업전시회라는 맥락과 일치합니다. 즉 "정확도 1~2%p"보다 **"멈추지 않는 것"**이 이 항목에서 더 크게 작용할 가능성이 높습니다.

> **영상 편집 원칙**: 실패 장면·긴 로딩·재시도는 제외합니다. 단, **응답 시간 자체를 왜곡(배속)하면 질의응답에서 잡힙니다.** 느린 구간은 자르되 속도는 유지하고, 질문이 나오면 정직하게 답합니다.

#### 3.3.3 감점 위험

- 영상에 오류 메시지·버벅임이 포함됨
- 아키텍처 없이 "AI를 활용했습니다" 수준의 설명
- 시중 API를 그대로 호출한 것 외에 자체 구현 요소가 보이지 않음

### 3.4 영역 3 — 창의성 (20점) — 가장 위험한 영역

#### 3.4.1 명시적 감점 조항이 존재한다

> **"보편적인 대중화된 소재는 아닌가?"** **[확정]**

이것은 가점 항목이 아니라 **감점 조항**입니다. 평가표에 이런 문장이 직접 들어간 것은 흔치 않으며, **매년 유사 주제가 반복 출품되고 있다는 정황**으로 읽힙니다. **[추론-중간]**

**AI 분야에서 "대중화된 소재"로 분류될 위험이 높은 주제 [추론-중간]**

- LLM 기반 챗봇 / 상담 서비스
- 범용 객체탐지(YOLO로 무언가 인식)
- 얼굴인식 출결·보안 시스템
- 추천 시스템
- AI 면접·이력서 첨삭
- 감정 인식

#### 3.4.2 대응 전략 — 축을 "기술"에서 "문제 정의"로 옮긴다 **[추론-높음]**

2학년 재학 시점의 기술 스택으로 **기술적 신규성**을 주장하면 질의응답에서 방어가 불가능합니다. 전공 심사위원 1~2명이 "기존 연구와 뭐가 다릅니까"를 물으면 답변이 막힙니다.

| 접근 | 방어 가능성 |
|---|---|
| ✗ "새로운 모델 구조를 제안합니다" | 낮음 — 논문 수준 근거 요구됨 |
| ✗ "성능이 기존보다 높습니다" | 낮음 — 비교 실험 요구됨 |
| ○ **"이 문제는 지금까지 이렇게 정의된 적이 없습니다"** | 높음 — 반증하려면 심사위원이 그 분야를 알아야 함 |
| ○ **"이 사용자 집단에 적용한 사례가 없습니다"** | 높음 — 동일 |

**즉, 기존 기술을 쓰더라도 아무도 건드리지 않은 대상·상황·사용자에 적용하면 독창성이 성립합니다.**

참고: 2025년 출품작 중 시각장애인용 스마트 보조기기, 재난 통신망 복구 체험 플랫폼, 장애인 생활 보조 로봇 등이 이 축에 해당합니다. **[추론-중간 — 학교 공지 기반, 세부 내용 미검증]**

#### 3.4.3 "기술동향 및 전망을 잘 파악하고 있는가"

세 번째 질문은 별도 대응이 필요합니다.

> **실행**: 동향 슬라이드 1장. "왜 지금 이 기술인가"에 대해 최근 논문·시장 자료 2~3건을 근거로 제시.
>
> **주의**: 출처는 반드시 실재하는 것만 사용합니다. 외부 심사위원 3인 중 확인 가능한 사람이 있을 수 있으며, 지어낸 출처가 발각되면 창의성뿐 아니라 발표력까지 동시에 무너집니다.
