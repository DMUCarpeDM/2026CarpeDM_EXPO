## 1. 세 목적의 층위 구조

슬라이드의 세 항목은 병렬이 아니라 **수혜 대상이 다른 3개 층위**다.

| # | 명시된 목적 | 실제 수혜자 | 성격 |
|---|---|---|---|
| 1 | 산업전시회 참가 기회 제공 → 창의적 전문인 양성 | 학생 | 교육 |
| 2 | P.D.Lab 제도의 성과 홍보·확산 | 교육제도 | 제도 마케팅 |
| 3 | 산-관-학 협력·특화 교육사업 성과 전시 → 대학 인지도 제고 | 대학(기관) | 기관 홍보 |

**핵심 인식**: 학생은 보통 1번만 보고 준비하지만, 문서 전체의 무게중심은 2·3번에 있다. 출품 심사의 주체는 이 문서를 만든 학교이므로, **1번만 충족한 작품은 선정 경쟁에서 불리하다.**

> 신뢰도: 중간 — 심사 배점표가 공개되지 않은 상태에서 목적문 구조로부터 추론

## 2. 목적 1 — 교육: "산업전시회"라는 조건이 부과하는 제약

### 2.1 문장 구조

> P.D.Lab 학생들이 **전공 지식을 활용하여 연구·개발한 작품**으로 → **국내 최대 규모의 전자·IT 산업전시회 참가 기회 제공** → **실무 지식 + 현장 경험** → **창의적 전문인 양성**

목적어가 작품이 아니라 **사람**이다. 작품 완성도만이 아니라 **학생이 그것을 설명하고 운영하는 능력**까지 평가 범위에 든다.

### 2.2 전제 조건 두 가지

- **"전공 지식을 활용하여"** → 취미 프로젝트·외주물이 아닌 **교과 연계** 요구. 기획서에 "어떤 전공 역량을 쓰는가"를 명시해야 함.
- **"연구·개발"** → 개발(구현)만으로는 절반. **문제 정의 · 선행 조사 · 검증**이 나머지 절반.

### 2.3 KES라는 무대의 이중성

| 유리한 점 | 불리한 점 |
|---|---|
| KES 2026 전시분야에 **AX(AI Transformation)** 명시 → AI 작품은 간판 카테고리 | 같은 홀에 삼성전자·LG전자 등 상용 제품 부스 |
| 산업통상부 주최 B2B 전시회 → 기업 관계자·바이어 직접 노출 | 관람객의 비교 준거가 **상용 제품** |

**→ 완성도 경쟁은 반드시 진다.** 이길 수 있는 축은 대기업이 다루지 않는 **틈새 문제 · 학생 시점의 문제 정의 · 사회적 맥락**.

### 2.4 "실무 지식"과 "현장 경험"은 다른 것

| | 획득 시기 | 내용 |
|---|---|---|
| 실무 지식 | 준비 기간 전체 (~10월) | 요구사항 정의, 일정·예산 관리, 부품 조달, 협업/형상관리, 문서화 |
| 현장 경험 | **전시 4일뿐** | 낯선 사람 대상 설명, 예상 못 한 질문, 실시간 장애 복구, 기업 피드백 |

현장 경험은 **재현 불가능**하며 4일 안에만 발생한다. 따라서 "작품 완성"과 "전시 운영"은 **별도 준비 항목**으로 관리해야 한다.

### 2.5 부스 환경이 강제하는 설계 제약

- **이중 관객**: 일반 관람객·고교생 + 기업 관계자 → **30초 버전 / 3분 버전** 설명 스크립트 각각 필요
- **가동 시간**: 하루 약 7시간 × 4일 연속 → **정확도 1~2%p보다 무장애 가동 시간이 중요**
- **비통제 환경**: 소음(음성인식 치명), 조명 변화(비전 모델 치명), 무선 혼잡(클라우드 API 실패)
- **필수 준비**: 오프라인 폴백 + 사전 녹화 데모 **이중화**

> 신뢰도: 중간 — 일반 전시 운영 원칙과 KES 형식에서 도출. 학교 문서에 명시된 요구사항 아님

## 3. 목적 2 — 제도: 홍보 대상은 작품이 아니라 P.D.Lab

### 3.1 P.D.Lab의 실체

- **P.D.Lab = Project Development Lab (작품개발동아리)**
- 공식 정의: **팀티칭 기반 도제식 교육**을 통해 전공 프로젝트를 수행하는 프로그램
- 등급 3단계: **Rookie-Star / Pre-Star / Star**
- 지원: STAR 학기당 작품제작비 200만 원 + 5호관 전용 연구실 / Pre-STAR 100만 원 *(금액은 학생처 확인 권장)*
- 등급 기준: **최근 3년간** 졸업작품전 및 교내외 경진대회 성과

### 3.2 문장의 진짜 목적어

> 우리 대학 고유의 학생주도 창의융합 프로젝트식 교육단위인 **P.D.Lab의 성과**를 대내외에 홍보·확산

홍보 대상은 **제도**이고, 작품은 "이 제도가 작동한다"는 **증거물**이다.

**→ 작품이 훌륭해도 P.D.Lab 방식으로 만들어졌다는 게 드러나지 않으면 목적 2를 충족하지 못한다.** 기획서와 부스에서 **제작 과정 자체를 서사로 노출**하는 것이 유리.

### 3.3 세 수식어의 실제 의미

#### "학생주도" — 교수 배제가 아니라 도제 구조

- 지도교수가 학과별로 지정되며 관리운영비 지원
- "학생주도"는 **주제 선정과 실행의 주체가 학생**이라는 뜻이지 교수 부재가 아님
- 실질적 핵심은 **선배 → 후배 기술 전수**. 매년 새 팀이 0에서 시작하지 않고 **누적 자산을 물려받음**
  - 예: EL 동아리의 자전거 관련 프로젝트 연간 계승 (ABLE → ARIBY → …)

> **함의**: 2학년이 할 일은 독창적 주제를 혼자 발굴하는 것이 아니라, **누적 자산이 있는 동아리에 들어가 계보를 잇는 것**

#### "창의융합" — 학부 간 연합이 아니라 기술 요소의 융합

- P.D.Lab은 학부·학과 단위로 조직 (기계 / 로봇자동화 / 전기전자통신 / 컴퓨터 / 생활환경 / 경영)
- 타 학과 학생의 입부는 가능하나, **학과 간 연합팀 사례는 확인되지 않음**
- 실제 출품작 패턴: **한 팀 안에서 하드웨어 + AI 결합**
  - AI 비전인식 분리수거 시스템 / 스마트 글러브 + AI 산업안전 플랫폼 등

> **함의**: 학과 단독 팀으로 충분. 다만 **물리적 시연물이 있는 형태**가 이 단어에 더 부합하고 부스 효과도 큼

#### "프로젝트식" — 학교가 제시한 서사 템플릿이 존재

P.D.Lab 학술대회 발표 요구 항목 = 사실상 학교의 표준 템플릿:

1. 전공 기반 연구(개발)의 **배경 및 목적**
2. 작품(연구) **내용과 방법**
3. 개발 과정에서의 **주요 과제와 해결 방안**
4. **결과 및 성과**
5. **학습 성과 및 향후 활용·확장 방안**

주목할 두 항목:
- **3번**: 실패와 극복을 명시적으로 요구 → 매끄러운 성공담보다 **막힌 지점과 돌파 과정**이 평가 대상
- **5번**: 작품을 종결형이 아니라 **계속 이어질 것**으로 제시 → 선배→후배 계승 구조와 맞물림

### 3.4 등급 순환 구조 (가장 실용적인 발견)

```
EXPO·경진대회 성과
      ↓
PD Lab STAR / Pre-STAR 선정
      ↓
제작비 200만/100만 + 전용 연구실(STAR)
      ↓
다음 해 더 나은 작품
      ↓
     (반복)
```

**등급이 "최근 3년간" 누적 성과 기준**이라는 점이 핵심. 한 해 성과가 3년간 영향을 미친다.

**→ 신생 팀이 첫해에 16개 안에 드는 것은 구조적으로 불리. 이미 STAR/Pre-STAR인 동아리 합류가 압도적으로 유리.**

## 4. 목적 3 — 기관: 재정지원사업 성과 전시

> 주요 **산-관-학 연계 협력사업 및 대학 특화 교육사업 성과 전시**를 통해 대학의 우수성을 홍보하고 대학 인지도와 이미지 제고

- **PD Lab+는 동양미래대 2주기 혁신지원사업의 대표사례**로 학교가 대외 홍보에 사용
- 즉 P.D.Lab은 단순 동아리 제도가 아니라 **정부 재정지원사업의 성과 지표**
- 목적 2와 3은 사실상 하나의 흐름

**→ 함의**: 작품을 학교 재정지원사업(LINC 3.0, HiVE, 부트캠프 등)과 연결 가능한 형태 — **산업체 연계 · 사회문제 해결 · 지역 협력** — 로 프레이밍하면 선정·시상에서 유리할 개연성.

> 신뢰도: 중간~낮음 — 슬라이드에 직접 명시된 바 없고, 항목 배치와 학교 사업 구조에서 추론. 근거 기사는 2023년 시점이라 현재 사업 주기는 다를 수 있음

## 5. 종합 — 작품 설계 체크리스트

### 5.1 목적별 충족 여부 자가진단

| 목적 | 확인 질문 |

| 1 | 30초 안에 비전문가가 "뭘 해결하는지" 이해하는가? |
| 1 | 4일 × 7시간 연속 가동 시 죽지 않는가? 네트워크 없이도 시연되는가? |

| 2 | 이 작품이 **P.D.Lab 방식**(도제·계승·팀)으로 만들어졌음이 드러나는가? |
| 2 | 5단 서사(배경→방법→난관과 해결→성과→확장)로 설명되는가? |
| 2 | 하드웨어/물리적 시연 요소가 있는가? |
| 3 | 산업체·사회문제·지역과 연결되는 지점이 있는가? |

### 5.2 주요 트레이드오프

| 선택지 | 얻는 것 | 잃는 것 |
|---|---|---|
| 클라우드 API 기반 | 짧은 구현 기간, 높은 성능 | 현장 네트워크 의존, 지연, 실패 시 무대응 |
| 온디바이스/로컬 추론 | 안정성, 낮은 지연, 데모 신뢰도 | 준비 비용, 성능 상한 |
| 기술 난도 높은 작품 | 전문가 평가 유리 | 일반 관람객에게 전달 안 됨 |
| 시연 직관성 높은 작품 | 부스 체류 시간·반응 좋음 | "쉬워 보인다"는 저평가 위험 |
| 신생 팀 창설 | 주도권, 온전한 기여 | 누적 자산 없음, 선정 확률 낮음 |
| 기존 STAR 팀 합류 | 제작비·공간·기술 즉시 활용 | 주도권 제한, 기존 주제에 종속 |

**권장 조합**: 로컬 추론 기본 + 클라우드는 선택적 강화 / 직관적 시연을 표면에 두되 기술적 깊이는 패널·문서로 뒷받침

> 신뢰도: 중간 — 전시 맥락의 일반 원칙. 특정 문서 근거 아님

## 6. 2학년 관점 실행 전략

### 6.1 시점 구조

- 3년제, 2026년 7월 = 2-1 수료 시점
- **2026 EXPO (제44회) = 2학년 2학기 중**
- **2027 EXPO (제45회) = 3학년 2학기 중**
- → **기회는 두 번, 두 번째가 졸업 학년**

### 6.2 권장 전략: 2026 합류·관찰 → 2027 주도

| 전략 | 얻는 것 | 잃는 것 |
|---|---|---|
| 2026 참가 시도 | 현장 경험 선취, 2027 재활용 노하우, 탈락해도 손실 적음 | 2-2 학기 부담, 심화 과목 미이수 상태의 기술 상한 |
| 2027 집중 | 전공 심화 이수 후 도전, 졸업작품과 연결 | 첫 참가가 곧 마지막 — 리허설 없음 |

**근거**: 현장 경험은 전시 4일에만 발생하고 재현 불가. 2027년에 처음 부스에 서는 것과 두 번째로 서는 것의 차이가 크다.

### 6.3 현재 이수 상태로 가능한 범위

교육과정상 1학년 배정 과목 기준:

- **1-1**: 파이썬프로그래밍, 웹프로그래밍기초, 프로그래밍기초, 인공지능개론, 컴퓨터공학기초, UI/UX기획
- **1-2**: 인공신경망, 데이터베이스, 자바프로그래밍, 데이터분석입문, 오픈소스소프트웨어, 생성형AI활용

| 작품 유형 | 현재 가능성 |
