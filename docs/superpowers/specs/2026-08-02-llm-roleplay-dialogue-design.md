# LLM 주도 역할극 대화 설계

## 목표

질문 순서와 대사를 정하는 FSM 템플릿을 제거한다. 첫 대사만 선택한 에피소드의 기존 대사로 고정하고, 그 뒤부터 GPT-4o가 시나리오와 상대 AI 페르소나를 바탕으로 역할극을 이어 간다.

## 유지하는 서버 안전장치

- 전시 흐름이 무한히 길어지지 않도록 5분 체험은 최대 6턴, 10분 체험은 최대 11턴까지만 허용한다.
- AI 호출 실패, API 키 미설정, 네트워크 오류, 형식이 맞지 않는 응답이면 다음 턴을 만들지 않고 명확한 연결 오류를 반환한다.
- 응답·자세·음성 분석과 결과 리포트는 기존대로 유지한다. 분석 점수는 대사의 진행 순서를 결정하지 않는다.

## AI 입력

매 턴 GPT-4o에 다음 정보를 함께 전달한다.

- 시나리오: 제목, 상황 설명, 에피소드의 배경과 학습 목표
- 상대 AI 페르소나: 역할, 성격, 말투, 난이도별 태도
- 난이도: 기본·압박·초압박 모드에서 사용할 대화 온도
- 대화 이력: 처음부터 현재까지 상대 발화와 사용자 발화
- 현재 턴 수와 남은 턴 수: 대화를 자연스럽게 마무리할 수 있게 하는 정보

AI는 상대 역할로서 자연스러운 한국어 한 문장만 돌려준다. 고객은 고객처럼, 상사는 상사처럼 말해야 하며 사용자 역할의 행동·사과·약속을 대신 말하면 안 된다.

## 제거 대상

- `TemplateDialogueProvider`
- 체크리스트 누락 기반 후속 질문 선택
- 압박·심화 질문 템플릿 풀
- 에피소드 순서, 목적 ID, 질문 유형으로 다음 대사를 선택하는 FSM 진행 코드
- 위 템플릿 선택을 검증하는 단위 테스트

`Episode` 데이터는 선택 화면과 AI 프롬프트의 시나리오 정보로 계속 사용한다. `Turn.question_type`은 결과 화면 호환을 위해 `ai_roleplay`로 저장한다.

## 요청 흐름

1. 세션 생성 시 선택한 에피소드의 `initial_question`을 첫 대사로 저장한다. 이 단계에서는 GPT-4o를 호출하지 않는다.
2. 사용자가 답하면 서버가 대화 이력과 분석 신호를 저장한다.
3. 최대 턴 수에 도달하지 않았다면 GPT-4o가 다음 역할극 대사를 생성한다.
4. 최대 턴 수에 도달하면 서버는 정상 종료 응답을 반환한다.
5. GPT-4o 호출이 실패하면 서버는 오류를 반환하고 프론트는 “AI 연결을 확인해 주세요”를 표시한다.

## 검증 기준

- 첫 대사는 기존 에피소드 대사로 저장되고, 다음 대사부터는 템플릿 질문 풀 없이 GPT-4o 호출 결과로 저장된다.
- 프롬프트에 시나리오·페르소나·난이도·전체 대화 이력이 들어간다.
- 첫 대사 이후에도 상대 역할이 사용자 역할처럼 말하지 않는다.
- 5분 체험은 6턴, 10분 체험은 11턴 뒤 정상 종료한다.
- GPT-4o 실패 시 템플릿 대사가 나오지 않고 명확한 오류가 반환된다.
