# 표정 모델 학습·검증 기준

> 학습 설계 참고 문서입니다. 최신 운영 기준인 0.5초 기록·구간 연결과 전체 합의는 [2026-09-11 최신 합의 통합본](2026-09-11-4fit-latest-agreements.md)을 따릅니다. 아래의 미선정 사항과 시제품 구현 상태를 혼동하지 않습니다.

## 현재 상태와 범위

RAF-AU와 RAF-DB 신청 메일 발송 완료. 원본 데이터는 아직 받지 않았다. 이 문서는 합의된 표정 모델 설계와 수령 후 점검 절차이며, 학습 완료 보고서가 아니다. 기존 모델과 코드는 변경하지 않는다. 일자별 일정은 만들지 않는다.

## 확정한 출력

| 저장 이름 | 화면 이름 | 기준 |
| --- | --- | --- |
| smile | 미소 | 입꼬리가 위로 올라감 |
| brow_furrow | 눈썹 찌푸림 | 눈썹이 내려가고 미간 쪽으로 모임 |
| brow_raise | 눈썹 올림 | 눈썹 안쪽 또는 전체가 올라감 |
| eyes_wide | 눈 크게 뜸 | 윗눈꺼풀이 올라가 눈이 크게 열린 모습 |
| neutral | 무표정 | 눈썹·눈·입에 뚜렷한 표정 움직임이 없는 상태 |

입술 누름은 제외한다. 표정에서 감정·태도·의도를 단정하지 않는다. 모델은 점수를 출력하지 않으며, 가감점은 별도 시나리오 규칙의 책임이다. 표정에 대한 실시간 지적이나 팁바 알림은 만들지 않는다.

## 데이터 기록 규칙

사진 한 장을 한 행으로 기록한다. 필수 정보는 이미지 식별자, 출처 데이터, 원본 상대경로, 다섯 라벨, 라벨 근거, 검토 상태다. 인물 식별자는 원본에서 제공되거나 확인 가능한 경우에만 기록한다.

각 라벨은 1(있음), 0(없음), 빈칸(판단 불가 또는 미확인)으로 기록한다. 미확인 항목은 그 항목의 학습과 평가에서 제외한다. 다섯 항목 모두 미확인이면 학습에서 제외한다.

여러 움직임은 동시에 1일 수 있다. neutral=1인 확정 행에는 다른 네 라벨이 모두 0이어야 한다. 특정 움직임이 확인되어 1이면 neutral=0이다. 네 움직임이 모두 0이라는 이유만으로 neutral=1을 자동 생성하지 않는다. 다른 표정이 보이는 경우 neutral=0과 함께 기타 표정 메모를 남긴다. 얼굴 미검출·가림·흐림은 무표정이 아니다.

원래 눈이나 눈썹 형태만으로 움직임을 추정하지 않는다. 판단 근거가 부족하면 빈칸으로 둔다. AI의 임시 라벨을 사람 검토 없이 평가용 정답으로 확정하지 않는다.

## 원본 라벨 활용

RAF-AU의 AU12는 미소, AU4는 눈썹 찌푸림, AU1·AU2는 눈썹 올림, AU5는 눈 크게 뜸의 대응 후보로 사용한다. AU는 얼굴 움직임 단위다. 실제 배포본의 열 이름, 좌우 구분, 결측값, 값의 뜻을 설명서와 대조한 뒤 변환한다. 원본 전체는 공식 소개상 26종 AU이며, 다른 연구에서 선택한 일부 AU 목록과 혼동하지 않는다.

눈썹 올림은 AU1 또는 AU2 중 하나라도 확인된 양성이면 1이다. 둘 다 확인된 음성이면 0이며, 양성이 없고 하나라도 미확인이면 빈칸이다.

RAF-DB의 Neutral 라벨은 무표정 후보로 사용하되 우리 기준에 맞는지 검토한다. Happiness를 미소로, Anger를 찌푸림으로 자동 변환하지 않는다. 다른 네 항목은 별도 확인 없이 0으로 채우지 않는다.

## 학습 구조

얼굴 사진 → 얼굴 영역 추출 및 크기 통일 → 사전학습 이미지 모델의 전이학습 → 다섯 항목별 출력.

다중 라벨 분류를 사용한다. 각 항목을 독립적으로 학습하며, 미확인 항목은 손실 계산에서 제외한다. 다섯 값의 합이 100%가 될 필요는 없다. 모델의 0~1 출력은 검증 전까지 실제 정답 확률로 보장하지 않는다.

출력 기준값은 검증용 데이터에서 항목별로 선택한 뒤 고정한다. 무표정과 다른 표정이 동시에 기준을 넘으면 무표정 확정을 보류한다. 모든 항목이 기준 미만이어도 무표정으로 자동 처리하지 않는다. 판단 유보 상태는 표정 라벨과 별도로 반환한다.

구체적인 사전학습 모델, 입력 크기, 학습 횟수는 아직 선택하지 않았다. 수령 데이터와 실행 환경을 확인해 선택할 구현 설정이며, 이미 확정되거나 검증된 값으로 취급하지 않는다.

## 학습·검증·시험 데이터 분리

공식 분할을 우선 확인한다. 학습용은 가중치 학습, 검증용은 모델 선택과 기준값 조정, 최종 시험용은 선택이 끝난 모델의 최종 확인에만 사용한다.

두 데이터 사이의 동일 이미지와 유사 복사본을 점검한다. 확인 가능한 같은 인물과 중복 사진 묶음은 분할을 넘나들지 않게 한다. 인물 정보가 부족하면 인물 중복이 완전히 제거됐다고 주장하지 않고 한계를 기록한다. 분할 변경 시 공식 결과와 직접 비교 가능한지 명시한다. 이미지 변형은 분할 후 학습용에만 적용한다.

무표정은 RAF-DB에서만, 다른 표정은 RAF-AU에서만 제공되어 출처 자체가 정답의 단서가 되는지 점검한다. 두 출처의 일부 사진을 동일한 다섯 기준으로 검토해 보완하고, 출처별 결과도 따로 확인한다.

## 수령 후 점검 순서

1. 이용 승인 범위와 Colab 업로드·팀 내부 접근·추가 라벨링 허용 여부를 확인한다.
2. 원본 설명서, 이미지 수, 라벨 열, 결측값을 확인한다. 원본은 보존하고 변환 결과를 별도로 만든다.
3. 라벨별 있음·없음·미확인 수를 출처별로 센다. 미수령 상태에서 예상 수량을 실제 수량처럼 채우지 않는다.
4. 각 라벨의 양성·음성·애매한 사진을 검토해 기준을 맞춘 뒤 중복 점검과 분할을 진행한다.
5. 학습 후 항목별 성능, 출처별 성능, 오분류 사진을 검토한다.

## 검증 기준

- 데이터 검사: 중복 식별자, 잘못된 경로, 읽히지 않는 사진, 허용되지 않은 라벨 값, 무표정과 다른 양성의 충돌을 보고한다.
- 결측 처리 검사: 미확인 항목의 값을 바꿔도 해당 항목의 학습 손실에 영향을 주지 않아야 한다.
- 성능 보고: 항목별 정밀도(맞다고 한 것 중 실제 정답 비율), 재현율(실제 해당 사진을 찾아낸 비율), F1(두 지표의 균형), 평가 사진 수를 함께 기록한다. 평가 가능한 양성·음성이 부족하면 신뢰할 수 있는 성능으로 주장하지 않는다.
- 오류 점검: 말하면서 입을 벌린 사진을 미소로, 원래 큰 눈을 눈 크게 뜸으로, 가린 얼굴을 무표정으로 처리하는지 확인한다.
- 최종 시험용 사진으로 기준값을 조정하지 않는다. 검증 결과가 없으므로 정확도 목표 달성이나 서비스 적용 가능성을 아직 선언하지 않는다.
