# Response·Posture AI 개선 설계

## 목표

전시용 Mirror-Ting에서 Response-Fit과 Posture-Fit 점수를 더 일정하게 만들기 위한 데이터 수집·검증 방식을 정리한 문서임. 실제 전시 참가자 데이터는 저장하지 않음. 팀 내부에서 만든 동작 데이터와 AI 합성 응답 데이터만 사용함.

## 이번 범위

- 포함: Response-Fit, Posture-Fit
- 제외: Eye-Fit, Voice-Fit, 전시 참여자 원본 음성·영상·전사·점수 저장
- 실행 환경: 학습과 실험은 Google Colab, 전시는 로컬 PC
- PoC 서버에 올릴 파일 형식과 최종 모델 종류는 실험 결과를 보고 나중에 정함

## 작업 분리

| 담당 | 하는 일 | 사용 데이터 | 우선 방법 |
| --- | --- | --- | --- |
| 팀원 A | 응답 점수 보정 | 합성·팀 내부 응답 200~1,000개 | 기존 규칙 점수와 문장 임베딩을 입력으로 쓰는 가벼운 회귀 모델 비교 |
| 팀원 B | 자세 점수 보정 | 팀 내부 동작 50~200개 | MediaPipe 집계값과 기존 점수 공식을 비교해 가중치·임계값을 보정 |

## 공통 데이터 원칙

1. 모든 샘플은 0~100점 정답 점수와 한 줄 이유를 가짐.
2. 데이터 생성 방식은 `synthetic` 또는 `internal`로 기록함.
3. 학습 70%, 보정 15%, 최종 테스트 15%로 처음부터 나눔.
4. 최종 테스트 데이터는 점수 공식·모델·임계값을 고를 때 사용하지 않음.
5. 점수가 확실하지 않거나 측정 품질이 낮으면 높은 점수를 만들지 않고 `측정 보류`로 처리함.
6. 전문가 검수 데이터가 아니므로, 결과는 팀 내부 기준의 전시 품질 개선용으로만 해석함.

## 공통 평가 기준

- 주 지표: 정답 점수와 예측 점수의 평균 절대 오차(MAE)
- 보조 지표: 낮은 점수 사례를 높은 점수로 잘못 주는 비율, 근거 문구가 입력과 맞는지 여부
- 전시 적용 전 조건: 기존 PoC 점수보다 최종 테스트 MAE가 낮아야 함. 같거나 나쁘면 기존 규칙을 유지함.

## 결과물

- 팀원별 Colab 노트북
- 학습·보정·테스트로 나눈 데이터 목록
- 기존 점수와 개선 점수를 비교한 표
- 실패 사례 10개와 개선 방향
- PoC 서버 반영 후보와 폴백 방식 제안

## 위험과 대응

| 위험 | 대응 |
| --- | --- |
| AI 합성 답변만 많아 실제 표현이 부족함 | 같은 뜻을 여러 말투·길이·오류 형태로 생성하고 팀이 일부 직접 작성함 |
| 같은 사람이 만든 동작이 학습·테스트에 함께 들어감 | 사람 단위로 데이터를 나눔 |
| 데이터가 적어 모델이 외움 | 복잡한 딥러닝 모델 대신 단순 회귀·보정부터 비교함 |
| 자세가 개인차를 벌점으로 만듦 | 신체 특징이 아닌 변화량·측정 품질 중심으로 보고, 불확실하면 측정 보류함 |
