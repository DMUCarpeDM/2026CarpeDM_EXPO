# 듀얼 모드 UX 기획서 — 반응형 웹 + 스마트 미러 모드

> 2026 동양미래EXPO · 4-Fit 미러팅
> 구조: **하나의 앱, 두 개의 문법.** 평소엔 반응형 웹(폰~데스크톱), 미러 모드로 진입하면 스마트 미러 전용 UI.
> 미러 전제: 세로 1080×1920 하프미러(반투명 거울 + 디스플레이), 터치 가능.
> 목표: 웹에서는 **어디서든 접근 가능한 학습 도구**, 미러에서는 **거울이 말을 거는 몰입 체험**.

---

## 0. 모드 아키텍처 — 하나의 앱, 두 개의 문법

로직(세션 FSM · 분석 · API · 훅)은 전부 공유하고, **표현 계층만 모드에 따라 갈라진다.**

```
                    ┌─ 공유 코어 ─────────────────────────┐
                    │ 세션 스토어 · API 클라이언트 · STT/TTS │
                    │ useNonverbal(MediaPipe) · 레코더      │
                    └──────────────┬──────────────────────┘
              ┌────────────────────┴────────────────────┐
   [웹 모드 — 반응형]                          [미러 모드]
   폰 · 태블릿 · 데스크톱                       세로 1080×1920 하프미러
   문서형 레이아웃, 스크롤 OK                    무대형 레이아웃, 스크롤 금지
   개인 학습 · 심사 · 개발 확인                  전시 체험 · 부스 시연
   QR로 받은 상세 리포트 열람 ◄────────연결────── 리포트 QR 발급
```

### 모드 정의

| | 웹 모드 (기본) | 미러 모드 |
|---|---|---|
| 진입 | 그냥 접속 | `/kiosk` 진입 시 활성화 (기존 `mirroting-kiosk` 플래그 확장) |
| 해제 | — | 운영자 숨은 제스처 → "웹 모드로 복귀" |
| 대상 기기 | 폰(≥360px) ~ 데스크톱 | 세로 1080×1920 고정 (가로 폴백 여지만 확보) |
| 지속성 | — | localStorage 저장. 새로고침·리포트 방치 복귀에도 미러 유지 |
| 표현 | 문서·카드·스크롤 | 검정 배경·존 레이아웃·글로우 (§2~5) |

### 구현 방침
- 미러 모드 활성 시 `<html>`에 `.mirror-mode` 클래스 + 미러 토큰 오버라이드(§5).
- 표현 차이가 작은 화면(분석 대기 등)은 CSS 분기로, 차이가 큰 화면(역할극·온보딩·리포트)은 뷰 컴포넌트 분기(`RoleplayMirrorView` 등)로. **분기 기준: CSS로 어색해지면 뷰를 나눈다.**
- 라우트는 공유한다. 같은 `/roleplay/:id`가 모드에 따라 다른 뷰를 렌더. → 딥링크·QR·개발 흐름이 단순해짐.

### 왜 이 구조인가
1. **QR 연계가 이 구조를 요구한다** — 미러 리포트에서 "자세한 리포트는 폰으로" QR을 찍으면 같은 앱의 웹 모드가 열린다. 웹 모드의 모바일 반응형이 없으면 미러 체험의 마지막 고리가 끊긴다.
2. **심사·개발·시연 유연성** — 심사위원 노트북, 팀원 폰, 전시 미러가 전부 같은 배포본. 미러 하드웨어 없이도 개발·검증 가능.
3. **PRD 정합** — 기획서(prd.json)도 "전시 키오스크"와 "개인 학습(모바일 우선)"을 별도 트랙으로 정의하고 있다.

## 1. 웹 모드 — 반응형 정비

현재 웹 UI는 `max-width: 880px` 데스크톱 문서 기준이라, 폰에서는 레이아웃이 깨지거나 비좁다. 미러 QR의 착지점이 폰이므로 **모바일이 웹 모드의 1순위 뷰포트**다.

### 브레이크포인트 방침 (모바일 퍼스트)

| 구간 | 대상 | 주요 변화 |
|---|---|---|
| ~640px (기본) | 폰 — QR 착지, 개인 학습 | 1열 스택. 터치 타깃 ≥44px. 리포트 차트 가로 스크롤 없이 축소 대응 |
| 640~1024px | 태블릿 | 카드 2열 허용. 역할극은 카메라 상단·채팅 하단 세로 배치 |
| 1024px~ | 데스크톱 (현행) | 현행 유지 (카메라 좌 · 채팅 우) |

### 화면별 반응형 체크리스트
- **온보딩**: 캐릭터 그리드 3열→1열 스택, segmented 버튼 줄바꿈 허용, 코드 입력 키패드 폰 크기 대응.
- **역할극(폰)**: 좌우 2컬럼 → 세로 스택(카메라 위 · 채팅 아래). 폰 자체 학습 시나리오(PRD "개인 학습 모바일 우선")가 이걸로 열린다. 응답 바는 하단 고정(sticky).
- **리포트(폰) — 최우선**: QR 착지점. 레이더·타임라인·트렌드 차트의 SVG viewBox 축소 검증, 표 형태 지표는 카드 스택으로 재배열, 첨삭 텍스트 줄길이 조정. *미러 체험자가 실제로 다시 보는 유일한 화면이므로 품질 기준을 리포트에 집중한다.*
- **공통**: `viewport` 메타 확인, 폰트 상대 단위 정리, footer 내비 폰 대응.

웹 모드는 "잘 작동하는 반응형 문서"면 충분하다. 몰입 연출 비용은 전부 미러 모드에 쓴다.

## 2. 미러 모드 — 몰입 설계 원칙 5가지

핵심 통찰: **하프미러에서는 사용자의 얼굴이 이미 화면 한가운데 있다.**
UI가 할 일은 그 반사를 가리지 않으면서, 반사 주변에 "직장이라는 상황"을 둘러 세우는 것.

| 웹의 문법 | 거울의 문법 |
|---|---|
| 중앙 문서, 세로 스크롤 | 스크롤 없음. 화면 = 무대, 상태가 전환된다 |
| 카드/보더/서피스로 영역 구분 | 검정 = 거울. 면(面)을 최소화하고 빛으로 그린다 |
| 체크박스·`<details>`·텍스트 인풋 | 큰 터치 카드 1~2택, 음성 우선 |
| 채팅 버블 스크롤 | 현재 턴 하나만. "대화 상대가 눈앞에 있다" |
| 0.75~0.95rem 본문 | 1m 거리 가독 기준 (본문 ≥28px) |
| 카메라 영상 패널이 UI 중심 | 반사가 주인공. 카메라는 숨은 센서 |

### 원칙 1 — 검정은 투명이다
하프미러에서 검은 픽셀(#000)은 빛을 내지 않으므로 그냥 거울이 된다.
- 미러 모드 배경은 **순수 `#000`**. 웹 토큰의 surface/border 위계는 미러에서 대부분 버린다.
- 카드·패널 같은 "면"을 채우지 말고, **글로우·라인·타이포그래피**로만 그린다. (면을 채우면 그 부분 거울이 사라진다 = 반사를 가리는 벽)
- 액센트는 하프미러 투과율(~30-50%)을 감안해 **휘도를 1.5~2배 올린 미러 전용 토큰**으로.

### 원칙 2 — 중앙은 사람의 자리다
세로 1080×1920에서 체험자의 얼굴·상체 반사는 화면 세로 20~65% 구간에 맺힌다.
- 이 **"반사 존"에는 상시 UI를 두지 않는다.** 코칭 토스트 같은 순간 오버레이만 허용.

```
┌─────────────────┐ 0%
│  상대 존재 밴드   │      아바타·이름·말할 때 파형 글로우
├─────────────────┤ ~18%
│                 │
│    반사 존       │      비움. 체험자의 얼굴/상체.
│  (사용자 자신)    │      가장자리 프레임 글로우로만 상태 표현
│                 │
├─────────────────┤ ~65%
│  자막 밴드       │      현재 질문 1~2줄 / 내 답변 인식 자막
├─────────────────┤ ~80%
│  컨트롤 밴드     │      마이크 대형 버튼 + 전달. 손 닿는 높이(80~130cm)
└─────────────────┘ 100%
```

### 원칙 3 — 읽게 하지 말고 듣게 하라
TTS가 이미 있다. 미러에서는 **음성이 1차 채널, 텍스트는 자막**이다.
- 온보딩 설명문·동의 문구도 거울이 읽어준다. 화면 텍스트는 요점만.
- 한 화면에 문장 3개 이상 금지. 읽어야 진행되는 화면은 몰입 실패로 간주.

### 원칙 4 — 자의식을 자극하지 마라
거울 앞에서 사람은 이미 자기를 의식한다. 실시간 점수판을 더하면 "감시당하는" 느낌이 되어 발화가 위축된다.
- 실시간 게이지 3종(시선/자세/음량)은 미러에서 **기본 숨김**. PRD대로 세션당 1~3회 코칭 토스트만. (웹 모드에서는 현행 유지 — 자기 방에서 혼자 연습할 땐 유용하다)
- 타이머는 숫자 카운트다운 대신 **화면 테두리를 도는 얇은 빛의 링**이 줄어드는 앰비언트 표현. 마지막 30초에만 숫자 등장.
- "영상은 전송되지 않습니다" 신뢰 문구는 유지하되, 하단 구석에 작게.

### 원칙 5 — 전환은 장면(場面)이다
에피소드가 바뀌는 것은 페이지 이동이 아니라 **장면 전환**이다.
- 화면 전체가 잠깐 거울로 돌아갔다가(페이드 투 블랙 = 페이드 투 미러) 다음 상황이 떠오른다.
- 이 1.5초의 "거울만 남는 순간"이 리듬을 만들고, 하프미러의 매체 특성 자체가 연출이 된다.

## 3. 반사 vs 카메라 패널 — 결정 가이드

**권고: 반사 우선(reflection-first), 카메라 영상은 기본 숨김.**

근거:
1. 하프미러 위에 카메라 영상을 띄우면 **반사와 영상이 이중상**으로 보인다. 카메라 위치(상단) 때문에 시차가 생기고, 미러링 여부에 따라 좌우가 어긋나 어지럽다.
2. 카메라는 이미 **센서로서의 역할**(MediaPipe 시선·자세)을 다하고 있다. 보일 필요가 없다.
3. "내가 화면에 나온다"는 CCTV 감각은 원칙 4와 충돌한다.

단, 폴백으로 **고스트 캠 모드**를 운영자 설정에 둔다:
- 전시장 조명이 밝아 반사가 약하게 맺히는 경우 대비.
- 좌우반전 + 저채도·저휘도(투명도 ~35%) 영상을 반사 존 배경에 은은하게 깔아 "디지털 반사"를 흉내낸다. 선명한 비디오 패널이 아니라 유령 같은 잔상.
- 설치일에 스위치 하나로 결정. → 하드웨어 결정을 설치 당일까지 미룰 수 있는 보험.

**부가 통찰 — 카메라 위치와 Eye-Fit의 정렬:** 카메라는 미러 상단에 달릴 것이므로, 상대(캐릭터) 아바타를 상단 밴드에 두면 체험자가 "상대를 보는" 행동이 곧 "카메라를 정면으로 보는" 행동이 된다. 몰입 연출과 Eye-Fit 측정 정확도가 같은 방향을 가리킨다.

## 4. 미러 모드 체험 흐름 (화면별)

### 4.0 대기 — "다가가면 깨어나는 거울"
- 화면 대부분이 순수 검정(=거울). 로고와 "다가와 보세요" 한 줄만 낮은 휘도로 숨쉬듯 페이드.
- **사람 감지 자동 웨이크**: MediaPipe가 이미 있으므로, 얼굴이 일정 크기 이상으로 감지되면 거울이 "깨어난다" — 프레임 글로우 점등 + 인사말 TTS. *(부스 흡인력의 핵심 장치)*
- 웨이크 후 대형 터치 CTA 1개: "출근하기".

### 4.1 온보딩 — 3탭이면 출근한다
- **스텝 1 (설정)**: "오늘 하루, ㈜클라우드밋의 신입이 됩니다" TTS + 대형 카드 2택 (5분 핵심 / 10분 전체). 난이도는 카드 하단 토글 칩. → 1탭
- **스텝 2 (동의)**: 개인정보 3줄 요약을 거울이 읽어주고, 대형 버튼 "확인했어요, 동의합니다". 체크박스 없음(버튼 = 동의). → 1탭
- **스텝 3 (출근)**: "출근하기" → 1탭
- 캐릭터 3인 소개는 별도 화면 없이 **브리핑·장면 전환에서 등장할 때** 한다. 만나며 알게 되는 편이 서사적이다.
- 체험 코드 이어하기: 첫 화면 구석의 작은 진입점 + 대형 숫자 키패드 UI.

### 4.2 브리핑 + 캘리브레이션 — 의식(ritual)으로
- "거울 속 자신과 눈을 맞춰주세요" — 반사 존 가장자리에 얼굴 위치 가이드 링이 떠오르고, 정면 응시 몇 초가 곧 캘리브레이션 완료. **측정 준비가 아니라 '마음의 준비'라는 의식**으로 프레이밍. (백그라운드 캘리브레이션 구조는 현행 재사용)
- 상황 브리핑은 TTS 내레이션 + 요점 칩 3개만. 완료되면 장면 전환으로 첫 상대 등장.

### 4.3 역할극 — 채팅앱에서 "면담"으로 (최대 재설계 대상)
- §2 존 레이아웃 적용. 채팅 히스토리 제거, **현재 턴만** 표시. (지난 대화는 리포트 타임라인이 담당)
- 상대가 말할 때: 상단 밴드 아바타에 음성 파형 글로우. 프레임은 낮은 휘도로 — "들을 차례".
- 내가 말할 때: 프레임 글로우가 호흡하듯 밝아짐 — "내 차례". 인식 자막이 자막 밴드에 실시간 표기.
- 마이크 버튼: 지름 ≥120px, 컨트롤 밴드 중앙. 텍스트 입력은 미러에서 제거(웹 모드에는 유지).
- 압박 질문: **프레임 글로우 색 온도가 차갑게 변하는** 연출 (텍스트 라벨은 보조).
- 코칭 토스트: 반사 존 하단 가장자리에 1~3회, 4초 내 자동 소멸.

### 4.4 분석 대기 — 기대를 만드는 시간
- "퇴근하는 중… 오늘 하루를 정리하고 있어요" 서사적 카피 + 4-Fit 아이콘 순차 점등.
- **이 시간에 체험 코드를 먼저 발급·표시**해 리포트 화면 체류 시간을 줄인다.

### 4.5 리포트 — 미러는 "시상식", 상세는 폰으로
- **미러 리포트 = 스크롤 없는 2막**:
  - 1막(결과): 총점 링 카운트업 + 등급 + 상위 백분위 + "오늘의 한 문장" (TTS가 읽어준다).
  - 2막(4-Fit): 레이더 차트 + 지표별 한 줄 코멘트 4개. 탭하면 다음.
- 마지막에 **QR + 체험 코드** 대형 표시: "자세한 첨삭 리포트는 폰으로 가져가세요". → QR이 여는 것이 곧 **웹 모드 모바일 리포트**(§1). 상세함을 버리지 않으면서 미러 회전율 확보.
- 30초 방치 시 대기 화면 복귀(기존 kiosk 플래그 로직 활용) + "다음 분 출근하세요".

### 4.6 운영자 경로
- footer 내비는 미러 모드에서 완전 제거. 화면 모서리 롱프레스(3초) 제스처로 운영자 패널(초기화 / 고스트 캠 토글 / 웹 모드 복귀) 진입.

## 5. 미러 디자인 토큰 (웹 토큰 위 오버라이드)

```css
.mirror-mode {
  --bg: #000;                    /* 순수 검정 = 거울 */
  --accent-lum: #7d99ff;         /* 하프미러 투과 보정 고휘도 액센트 */
  --frame-glow: rgba(125,153,255,.35);
  --text-mirror: #f2f5ff;        /* 본문도 휘도 상향 */

  /* 1m 거리 타이포 스케일 */
  --fs-caption: 24px;            /* 최소 허용 */
  --fs-body: 30px;
  --fs-subtitle: 40px;           /* 자막 밴드 */
  --fs-title: 56px;
  --fs-display: 84px;            /* 점수·인사 */

  /* 터치 (공용 키오스크 기준) */
  --touch-min: 88px;             /* 최소 타깃 */
  --touch-primary: 120px;        /* 마이크 등 주 버튼 */
}
```

- 애니메이션은 **휘도 변화(글로우) 중심**, 위치 이동 최소화 — 하프미러에서 움직이는 밝은 물체는 반사와 겹쳐 어지럽다.
- 전 화면 공통 "프레임 글로우" 컴포넌트가 시스템 상태 언어를 담당: 대기(느린 숨), 듣는 중(차분), 말할 차례(밝은 호흡), 압박(차가움), 완료(따뜻함).

## 6. 구현 로드맵

| 단계 | 내용 | 비고 |
|---|---|---|
| **P0 — 모드 뼈대 + 웹 반응형** | 미러 모드 분기 체계(`.mirror-mode`) · 웹 모바일 반응형(리포트 최우선 → 온보딩 → 역할극 세로 스택) · 미러 토큰 | QR 연계의 전제. 미러 하드웨어 없이 진행 가능 |
| **P1 — 미러 핵심 화면** | 역할극 미러 뷰(존 레이아웃, 현재 턴만, 대형 마이크) · 온보딩 3탭화 · 미러 리포트 2막 + QR · 대기 화면 | 이것만으로 "웹을 세운 것"에서 벗어남 |
| **P2 — 몰입 연출** | 프레임 글로우 상태 언어 · 장면 전환(페이드 투 미러) · 앰비언트 타이머 링 · 캘리브레이션 의식화 · TTS 내레이션 온보딩 | 몰입의 질을 결정 |
| **P3 — 전시 마법** | 사람 감지 자동 웨이크 · 고스트 캠 모드 · 운영자 숨은 제스처 · 관람객용 보조 화면(선택) | 부스 흡인력 |

## 7. 리스크와 완화

| 리스크 | 완화 |
|---|---|
| 하프미러 투과율로 UI가 안 보임 | 고휘도 토큰 + 설치일 현장 휘도 캘리브레이션 항목화 |
| 전시장 밝아서 반사가 약함 | 고스트 캠 폴백 (§3) |
| QR 착지 실패 (전시장 네트워크) | 로컬 IP/핫스팟 URL 사전 검증 + QR 옆에 체험 코드 병기 (코드만으로도 나중에 조회 가능) |
| 전시장 소음으로 STT 저하 | 기존 Vosk 서버 폴백 유지 + 지향성 마이크 하드웨어 검토(팀 공유 사항) |
| 터치 패널이 미러 유리와 분리된 경우 오조작 | 터치 타깃 88px+ / 하단 밴드 집중 배치로 흡수 |
| 세로 해상도 확보 실패(가로 TV만 수급) | 존 레이아웃을 flex 비율 기반으로 짜서 가로 폴백 여지 확보 (단, 세로 우선) |
| 모드 분기로 인한 코드 중복 | "CSS로 어색해지면 뷰를 나눈다" 기준 고수. 로직·훅은 공유 강제 |
