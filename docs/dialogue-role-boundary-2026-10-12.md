# 시뮬레이션 상대역의 평가자 이탈 수정

## 원인

상대역 생성 프롬프트에 답변 품질(last_case), 목표/체크리스트의 취지, 진행 번호, 연습 설명, 재질문 횟수, 판단 피드백 JSON이 전달되고 있었다. 연속 장면에서는 다른 인물이 나눈 대화와 사용자 답을 잘라 저장한 carry까지 현재 상대의 기억처럼 제공했다. 생성 실패 시 최종 대체 문장이 평가 목표와 사용자 원문을 그대로 읽는 경로도 있었다.

## 적용 방향

1. **상대역의 지식 범위 제한.** 상대의 이름·관계·말투·개인적 의도, 회사/사용자 직무, 현재 장면의 상황·용건·시각, 같은 인물과 같은 장면에서 직접 나눈 최근 8개 대화만 제공한다. 전체 계획, 점수, 평가 목표, 단계 번호, 다른 인물의 대화, carry는 제공하지 않는다.
2. **역할 전환 요청은 발화로 취급.** 사용자 기록을 JSON으로 인용한다. 평가자 전환·시스템 지침 공개·개발자 사칭·종료 지시는 장면 안에서 상대가 한 말일 뿐 새 제어 명령으로 취급하지 않는다. 평가 리포트나 점수를 새 업무로 받아들이지 않고 원래 용건으로 돌아온다.
3. **상대의 성격과 현재 용건 함께 유지.** 친밀감이나 압박은 표현 방식에 반영한다. 성격 설명을 근거로 새 업무·문서·식사·장소 이동을 만들어 장면을 옮기지 않는다. 이미 답한 질문을 되풀이하기보다 구체적인 약속에 반응한다.
4. **출력과 재사용 이력 검사.** 평가자 선언·답변 채점·모범 답변 판정·과정 안내 등 명백한 이탈 발화는 기존 문장 검증에서 거부한다. 연속 대화는 추가 모델 호출 없이 검증된 장면 대사/인물 리액션으로 대체한다. 이탈했던 과거 AI 발화도 다시 모델에 넣지 않는다. 업무상 인사평가 자료나 고객 만족도 점수처럼 일반 업무 대화는 대표 회귀 사례로 허용 여부를 검사한다.
5. **실패 경로도 같은 원칙 적용.** 대체 문장에서 평가 목표와 사용자 원문을 제거한다. 새 장면 상대가 다른 사람에게 한 말을 들었다고 주장하지 않도록 carry 브리지를 현재 용건으로 바꾼다.

OpenAI와 Gemini는 동일한 상대역 컨텍스트 생성 함수를 사용한다. Ollama는 Gemini 제공자의 공통 대화 경로를 상속한다. 점수 계산, 진행 제어, 결과 리포트의 내부 데이터는 유지한다. 면접의 기존 짧은 관측 반응은 내부 규칙명·수치 대신 직접 보고 들을 수 있는 설명만 받는다. 준비된 첫 대사와 주요 면접 질문은 그대로 사용한다.

## 검증

- 관련 회귀 검사 **84개 통과**: 제공자별 출력 거부/대체, 대화 기록 인용, 인물·장면 분리, 정상 업무 발화, 평가·진행 정보 제외, 기존 인터랙션/채점/복합 입력 흐름.
- 현재 설정의 `gemini-3.5-flash-lite`에 합성 입력으로 **단일 상황 8개 + 3턴 연속 대화 2개(응답 6개)**를 실제 호출했다. 최종 기록에서 평가자 역할로 채점하거나 평가 과정을 설명하는 발화는 관찰되지 않았다. 이 검사는 실제 사용자 세션이나 카메라 데이터를 전송하지 않는다.
- 초기 실응답에서 평가 리포트를 업무로 받아들이거나 없는 문의처/잡무를 만드는 사례를 발견해 지식 범위와 용건 유지 규칙을 보강했다.
- 원시 응답: `.omo/evidence/role-boundary-20261012/live-results.json`, `live-chain-results.json`.

이는 소규모 실응답 확인이며 모든 입력에서 이탈이 사라진다는 보장은 아니다. 출력 검사는 명백한 표현을 대상으로 한 제한적 규칙이다. 세부 업무 명칭의 추측, 부자연스러운 반복 등은 별도 품질 관찰 대상이며 이 검증은 일반적인 대화 정확도 평가가 아니다.
