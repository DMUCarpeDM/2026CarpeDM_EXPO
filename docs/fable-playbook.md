# Fable 플레이북 — 미러형 디스플레이 집중, 중간심사(8/1) 완성 작전

> 사용법: 각 역할의 프롬프트 블록을 **통째로 복사**해서 Claude Code 새 세션에 붙여넣는다.
> 모든 프롬프트는 맥락을 자체 포함하므로 이전 대화 없이 바로 실행된다.
> 심사 기준 매핑: 작품성 / 기술성 / 창의성 / 발표력 / 완성가능성

## 0. 하루 작전 지도

```
아침         ① 미러 무대 목수 (기반 — 반드시 단독 선행)
             │
오전~점심    ② 면담 연출가 (프론트)  ∥  ③ 대화 지능 엔지니어 (백엔드)
             │                          │
오후         ⑤ 시상식 연출가 (프론트)  ∥  ④ 지각 AI 엔지니어 (백엔드+프론트 훅)
             │
늦은 오후    ⑥ 빛의 디자이너  ∥  ⑦ 깨어나는 거울
             │
저녁         ⑧ 검증관 (전체 통합 검증 — 반드시 단독)
             │
밤           ⑨ 피치 스토리텔러 (코드 무관 — 아무 때나 병렬 가능)
```

- **∥ = 병렬 가능**: 서로 다른 파일을 만지도록 설계됨. 워크트리 격리 세션으로 돌리면 충돌 없음.
- ①이 만드는 미러 모드 뼈대 위에 ②⑤⑥⑦이 올라가므로 ①은 반드시 먼저, 단독으로.
- ②와 ③은 API 계약(`next_turn.reaction_text`)으로만 만나므로 병렬 안전.
- 각 세션 끝에 커밋까지 시키고, 사람은 머지 순서만 관리한다 (① → ③ → ② → ④ → ⑤ → ⑥ → ⑦).

**Fable이 못 하는 것 (사람 몫)**: 하프미러 하드웨어 제작·조달, 전시 PC에 Ollama 설치(`ollama pull exaone3.5:2.4b`), 실기기 리허설, 발표 연습. 이건 8/1 전에 팀 일정으로 잡을 것.

## ③ 대화 지능 엔지니어 (Dialogue Intelligence Engineer)
**심사 기준**: 기술성·창의성 | **선행 조건**: 없음 (②와 병렬 가능, 백엔드만)

```
[공통 컨텍스트]

너의 역할: 대화 지능 엔지니어. 현재 대화 엔진(backend/app/services/dialogue/)은
"질문→답→질문" 구조라 챗봇처럼 느껴진다. AI가 사용자의 답변에 '반응'하게 만들어
사람 간 대화의 감각을 재현한다. 전부 API 키 없이.

임무:
1. 리액션 비트 엔진 (템플릿 기반, 핵심):
   - 답변 신호는 이미 있는 것을 재사용: matched_checklist_ids(체크리스트 커버),
     답변 길이(음절), 위험/권장 표현(response_fit의 사전), 개시 지연.
   - 캐릭터별 톤 테이블을 시드에 추가: 상사=건조·간결("좋아. 그런데—"),
     선배=다정("오, 그 부분 잘 짚었어요. 그럼—"), 동료=캐주얼("헐 맞아요. 근데—").
   - 신호 × 톤 → 리액션 한 문장 선택 (커버 잘함/누락/너무 짧음/위험 표현 사용 등
     케이스별 3개 이상 변형으로 반복 체험 시 같은 문장 반복 방지).
2. API 확장: QuestionSpec과 Turn에 reaction_text(nullable) 추가. 다음 질문
   생성 시 직전 답변에 대한 리액션을 함께 반환 → 프론트 계약은
   next_turn.reaction_text (null 허용). 스키마·마이그레이션(SQLite) 처리.
3. Ollama 리액션 개인화: 기존 OllamaDialogueProvider 패턴 그대로 —
   리액션도 로컬 LLM이 사용자 답변을 직접 언급하며 생성하되, 타임아웃·형식 검증
   실패 시 템플릿 리액션으로 폴백. 시스템 프롬프트는 캐릭터 톤 반영.
4. 하루 프레이밍: 세션 진행을 가상 시각으로 노출한다. 에피소드마다 가상 시각
   (예: 09:00 출근 인사 → 11:30 → 14:00 → 16:30 → 17:50)을 시드에 부여하고
   턴/세션 API에 virtual_time 필드로 내려준다. 프론트가 "데모 5분"이 아니라
   "회사의 하루"로 보여줄 수 있게 하는 데이터 기반이다.
5. pytest: 리액션 선택 로직(케이스별), Ollama 폴백(연결 실패 시 템플릿 유지),
   virtual_time 매핑을 커버하는 테스트 작성·통과.

제약: 프론트 코드는 수정하지 않는다 (다른 세션이 작업 중 — API 계약만 지킬 것).
기존 세션 FSM·턴 예산 로직을 깨뜨리지 말 것.

검증: uvicorn 띄우고 curl 또는 pytest로 세션 생성→응답 제출→reaction_text 포함
확인. 전체 pytest 통과. 커밋.
```

## ④ 지각 AI 엔지니어 (Perception AI Engineer)
**심사 기준**: 기술성 | **선행 조건**: ③ 머지 후 권장 (⑤와 병렬 가능)

```
[공통 컨텍스트]

너의 역할: 지각 AI 엔지니어. 이미 로드된 모델들의 미사용 출력을 꺼내
측정 깊이를 늘린다. 새 모델 로드는 금지 — 오판 리스크와 로딩 시간만 늘린다.
이 프로젝트는 이미 실기기 오판 문제를 겪어 정면 기준 캘리브레이션을 도입했다.
모든 새 지표는 캘리브레이션 기준의 상대값 + 보수적 임계값으로 설계하라.

임무:
1. 표정 신호 확장 (frontend/src/features/roleplay/useNonverbal.ts):
   Face Landmarker blendshape에서 이미 미소(mouthSmile)를 수집 중이다. 추가로
   mouthPress(입술 압축=긴장), browDown(찡그림)을 프레임 집계하고, "미소 타이밍"
   (질문 유형이 pressure일 때의 미소 vs 인사 상황의 미소)을 구분할 수 있도록
   턴 단위 집계에 포함하라.
2. 무의식 습관 감지: Pose Landmarker가 이미 주는 손목 랜드마크로
   손-얼굴 터치(손목이 얼굴 근처에 머문 시간)와 팔짱 근사(양 손목 교차 자세)를
   감지해 턴 집계에 추가. 임계값은 보수적으로 — 확실할 때만 잡는다.
3. 음성 긴장도 (backend/app/ai/voice_fit.py): 기존 자기상관 F0 추적을 확장해
   주기 변동성(jitter 근사)을 계산, "목소리 떨림" 지표로 추가. numpy만 사용.
   기존 관례대로 합성 신호 대조 테스트로 검증한다.
4. 파이프라인 연결: nonverbal payload 스키마 확장(프론트→백엔드),
