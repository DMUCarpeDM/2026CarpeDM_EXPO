# Mirror-Ting 시연 영상 촬영 대본 (2026-07-28)

8/4 출품작 선정심사용 시연 영상 촬영 순서. 총 러닝타임 **약 3분 30초~4분** 기준.
모든 화면 표시값(시선·자세·표정·추론 ms·분석 로그)은 실측이므로, 촬영 중 어떤 각도로 찍어도 연출 흔적이 없다.

## 촬영 전 체크리스트 (5분)

| # | 확인 | 방법 |
| --- | --- | --- |
| 1 | **녹화 프로그램이 카메라를 점유하지 않게** | OBS는 **디스플레이 캡처만** 사용. 웹캠 소스를 추가하면 브라우저와 카메라를 두고 경쟁해 앱이 `다른 프로그램이 카메라 사용 중` 오류를 띄운다 |

## 시연 동선 (장면별)

### S1. 홈 — 10초
- **조작**: 홈 화면에서 잠깐 멈춤 → "AI와 연습하기"
- **내레이션**: "Mirror-Ting은 업무 대화를 AI와 역할극으로 연습하고, 응답·목소리·시선·자세 4가지를 분석해 주는 서비스입니다."

### S2. 설정 3단계 — 20초
- **조작**: 상대 **상사** → 시나리오 **"출시 범위 조정 — 팀장에게 진행 상황 보고"** → 난이도 **기본 모드**
- **내레이션**: "상대와 상황, 난이도를 고르면 그에 맞는 페르소나가 만들어집니다."
- 포인트: 3단계 카드 UI가 빠르게 지나가도 충분히 예쁘게 찍힌다. 머뭇거리지 말 것.

### S3. 미리보기 → 동의 → 시작 — 10초
- **조작**: 동의 체크 → 연습 시작 (권한은 사전 허용돼 있어 바로 통과)

### S4. 상황 브리핑 팝업 — 7~10초 (자동)
- **화면**: "14:30. 개발·디자인 팀과 확인을 마쳤다. 팀장이 출시 범위를 줄일지, 일정을 미룰지 판단하려고 한다." + 답변 포인트 3가지
- **내레이션**: "연습에 들어가기 전, 상황을 먼저 브리핑해 줍니다. 글 양에 따라 5~10초 뒤 자동으로 시작됩니다."
- 포인트: 진행 바가 줄어드는 것까지 보여주고 자동 전환을 기다린다 (스킵 버튼 누르지 말 것 — 자동 전환이 더 세련돼 보임).

### S5. 거울 분석 시작 — 15초 ★ 핵심 증명 컷
- **화면**: 내 모습 대형 + 얼굴 메시(초록)·상체 스켈레톤(흰색/파랑) + 칩 4종(시선·자세·표정·추론 ms) + 우측 ANALYSIS LOG
- **행동**: 첫 2초는 **정면 응시** (개인 기준 캘리브레이션 — 로그에 "캘리브레이션 완료"가 뜬다)
- 그 다음 **일부러 고개를 옆으로 3초 돌렸다가 복귀** → 칩이 `시선 이탈` → `시선 정면`으로 바뀌고 로그에 기록되는 걸 클로즈업
- **내레이션**: "카메라 영상은 어디에도 전송되지 않고, 브라우저 안에서 MediaPipe가 초당 12번 얼굴 478개·상체 33개 지점을 분석합니다. 지금 보시는 시선·자세·표정 값은 전부 실시간 실측입니다."

### S6. AI 질문 — 10초
- **화면**: AI 팀장 PiP가 speaking 영상으로 바뀌며 TTS로 질문을 읽는다
- **조작**: "상대 크게" 버튼(또는 PiP 클릭)으로 팀장을 크게 한 번 보여주고, 다시 내 분석 화면으로 복귀
- **내레이션**: "질문은 로컬 LLM(EXAONE 2.4B)이 상황과 제 답변에 맞춰 실시간으로 만듭니다. 인터넷 없이 전부 이 PC 안에서 돌아갑니다."

### S7. 음성 답변 — 20초 ★ 마이크 증명 컷
- **행동**: 아래 모범 답변을 자연스럽게 말한다 (체크 요소 4개를 모두 포함하도록 설계됨):

> "결론부터 말씀드리면, 일정을 미루기보다 **출시 범위를 줄이는 안**을 추천드립니다.
> 원인은 결제 모듈 검증이 이틀 지연된 것 하나입니다.
> 조치로 오늘 개발팀과 우선순위를 다시 정리했고, 핵심 기능은 예정대로 나갑니다.
> 재발 방지를 위해 다음 출시부터는 검증 단계를 일주일 앞당기겠습니다."

- **화면 포인트**: 말하는 동안 입력창 옆 **파형 막대가 목소리에 맞춰 움직임** + 받아쓰기가 입력창에 쌓임 → 말 멈추고 3초 뒤 **자동 전송**
- **내레이션**: "말이 끝나면 3초 뒤 자동으로 전달됩니다. 음성 인식이 안 되는 오프라인 환경에서는 서버의 Whisper가 이어받습니다."

### S8. 판정 + 팀장 반응 — 10초
- **화면**: ANALYSIS LOG에 `응답 판정: 핵심 요소 충실 — 훌륭한 답변 (커버리지 N%)` + 팀장 PiP가 **끄덕이는 영상**으로 반응 → 다음 질문
- **내레이션**: "답변 직후 핵심 요소 커버리지가 채점되고, AI 팀장이 그에 맞게 반응합니다."

### S9. (선택) 대비 시연 — 15초
- 두 번째 질문에 **일부러 짧게** "네… 그게, 확인해보겠습니다." 정도로만 답한다
- → 판정이 `답변이 짧아요`/`핵심 요소 일부 누락`으로 바뀌는 대비를 보여주면 채점이 진짜임이 한층 선명해진다
- 시간이 부족하면 생략 가능. 단, 심사 질의 대비로 한 컷 찍어두면 유용.

### S10. 종료 — 10초
- **조작**: 남은 턴을 진행해 자연 종료(권장 — 5분 모드는 짧다), 급하면 "연습 종료" → 확인 다이얼로그 → 종료
- **화면**: 분석 진행(4-Fit 계산) 로딩

### S11. 결과 리포트 — 30초
- **화면**: 종합 점수 + 4-Fit(Response/Voice/Eye/Posture) 점수 카드 → 강점/개선점 → 오늘의 한 문장
- **내레이션**: "응답 내용, 목소리, 시선, 자세를 각각 채점하고, 다음 연습에서 뭘 고치면 되는지 문장으로 알려줍니다."

### S12. 피드백 → 비교 → 공유 — 20초
- **화면**: 상세 피드백 → 이전 연습과 비교 → 공유(QR)
- **내레이션**: "연습을 반복하면 성장 곡선을 비교해 볼 수 있습니다."

## 타이밍 실측 (2026-07-28 풀 리허설 기준)

실제 백엔드로 5턴 전체를 완주해 검증했다 (설정 → 브리핑 → 5턴 대화 → 4-Fit 리포트).

| 구간 | 실측 | 촬영 팁 |
| --- | --- | --- |
| 시작 → 첫 질문 | 3~6초 | 세션 생성 + 첫 질문 생성 |
| **답변 제출 → 다음 질문** | **15~20초** | 로컬 LLM(EXAONE, CPU)이 반응·다음 질문을 만드는 시간. 파란 점 3개(typing) 애니메이션이 계속 움직이므로 화면은 죽어 보이지 않지만, **편집에서 컷하기 좋은 구간** |
| 종료 → 리포트 완성 | 10~30초 | 4-Fit 분석 진행 표시 있음 |

- 이 PC의 RTX 3060은 Ollama의 GPU 탐지 단계가 네이티브 크래시(0xc0000005)로 실패해 **CPU로 동작한다** (ctranslate2 4.8.1 크래시와 같은 유형의 시스템 특성). 드라이버·Ollama 재설치는 심사 전에 시도하지 말 것 — 현재 상태가 안정적이다.
- 리허설 산출물: 세션 #4 (모범 답변 위주, 종합 82점) — 비교 화면에 남아 있어도 자연스럽다.
