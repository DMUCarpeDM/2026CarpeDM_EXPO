# 면접·직업훈련 구현 기준

2026-09-12. 9월 11일 합의안을 바탕으로 진행·종료, 공통 판단, 점수·모순, 팁·역할 대사 순서로 적용한다. 아래 수치는 전시 테스트를 위한 초기값이며 검증된 평가 기준은 아니다.

## 1. 진행과 종료

`POST /api/sessions`의 `service_mode`는 `interview`, `training`, `workplace` 중 하나다. 생략하면 기존 직장 대화와 호환된다. 5/10분 선택은 시나리오 선택 범위이며 강제 종료 타이머가 아니다.

면접 시나리오는 `world_setting.interaction.interview_questions`에 주요 질문 문자열 6~12개를 준비한다. 질문이 없거나 범위를 벗어나면 시작 요청을 422로 거절한다. 준비된 질문을 순서대로 사용하며 주요 질문의 답변만 진행 수에 포함한다. 현재는 별도 꼬리 질문을 생성하지 않는다.

훈련은 선택한 장면의 체크리스트를 목표로 삼는다. 선택 장면이 없으면 시나리오의 장면 전체가 대상이다. 키워드 기반 목표 확인을 누적하고, 목표를 모두 충족하면 종료한다. 목표별 최초 답변 이후 재질문은 최대 2회다. 재질문은 목표를 유지하면서 쉽게 표현한다. 끝내 충족하지 못한 목표는 미완료로 남기고 다음으로 넘어간다. 모든 목표를 시도하면 종료한다.

생성·응답·복구 API의 `interaction`에 총 목표 수, 현재 위치, 완료·미완료 ID와 종료 사유를 제공한다. 종료 사유는 `questions_completed`, `goals_met`, `goals_exhausted`, `analysis_unavailable`, `manual`이다. 수동 종료도 남은 목표를 보존한다. 진행 상태는 기존 세션 JSON에 보관하므로 이번 단계는 DB 테이블 변경이 없다.

기존 세션에는 이전 턴 수 제한을 유지한다. 새 면접을 열려면 먼저 질문 배열을 시나리오 데이터에 등록해야 한다.

## 2. 공통 판단 결과

답변 응답의 `turn_signals.judgment`와 세션 내부 `rapport.judgments`를 사용한다. 판단마다 버전, 턴 ID, 영역, 규칙, 긍정·부정, 근거, 안내 문구가 있다. 동일 턴을 다시 저장하면 교체한다. 목표 진행도 같은 `met_goals`를 소비한다.

자세는 보정 완료, 15프레임 이상, 측정·응답 시간 모두 3초 이상일 때만 판단한다. 초기 기준은 고개 숙임·앞으로 숙임 비율 45%, 어깨 기울기 12도, 흔들림 0.12, 손이 얼굴 근처에 머문 누적 시간 3초다. 집계값이므로 연속 행동 시간으로 표현하지 않는다. 새 표정 모델과 팔짱 판정은 연결 전까지 제외한다. 측정값이 없는 영역은 판단 보류이며, 문제가 없다는 이유만으로 긍정 이벤트를 만들지 않는다.

미저장 동의에서는 분석 후 내부 공통 판단의 답변 인용도 함께 파기한다. 공통 판단은 답변 제출 시 생성·보관하며 새 점수 산식에서 사용한다.

## 3. 점수와 모순

새 세션은 `interaction-score-v1`이다. 영역마다 75점에서 시작하며 측정된 영역만 산술 평균한다. 영역 가점은 최대 15점, 감점은 최대 30점이다. 목표 충족은 목표당 +3점, 질문에 직접 답한 인용은 +3점, 현재 요청한 목표 누락은 목표당 -6점이다. 자세·음성 문제는 규칙당 -4점이며 같은 규칙은 세션당 최대 3번 반영한다. 목표별 충족·누락은 각각 한 번만 반영한다.

목표 확인은 1단계의 키워드 근사에서 의미 판단으로 전환했다. 답변 제출 시 GPT-4o가 현재 질문·목표·대화 기록을 보고 충족·누락과 모순의 근거를 JSON으로 추출한다. 서버가 목표 ID와 실제 원문 인용을 검증한다. 단어가 겹친다는 이유로 목표를 달성 처리하지 않는다. 추가 API 요청은 최대 8초, 실패 시 의미 판단과 응답 점수를 보류하며 자세 관찰과 대화는 유지한다. E5 예시 유형 비교와 신규 표정·자세 학습 모델은 이번 점수 엔진 연결과 별도의 영역 분석 작업이다.

명확한 모순은 이전·현재 원문 인용, 변경 설명 없음, 모델 확신값 0.9 이상을 모두 요구한다. 확신값은 통계적 정확도가 아니므로 실제 대화로 오탐 검증이 필요하다. 같은 사실 항목은 한 번만 -4점, 종합 감점은 최대 12점이다. 최근 발언 최대 12,000자 범위이므로 이력 전체 검출을 보장하지 않는다.

음성은 원본 오디오 3초 이상 실측만 쓴다. 초기 말속도 범위는 면접 2.5~6.5음절/초, 훈련·직장 대화 2.5~7.0음절/초다. 범위 안이면 +3점, 밖이면 -4점이다. 1.2초 이상 발화 중 쉼이 3번 이상이면 -4점이다. 억양, Chrome 시간 추정, Whisper 간투어 추정은 채점하지 않는다. 개인 기준 성량과 새 표정 모델은 측정 연결 전까지 보류한다.

최종 보고서에 적용 이벤트, 규칙, 근거와 모순 차감을 남긴다. 전 영역 미측정이면 API 점수는 null, 화면에는 '미측정'으로 표시한다. 기존 DB의 NOT NULL 컬럼 호환을 위해 내부에는 0과 별도 엔진 `interaction-no-score`를 저장하며 관리자 점수 평균·백분위에서 분리한다. 기존 세션은 이전 엔진을 유지한다.

## 4. 팁과 역할 대사

MVP 연습 화면은 `POST /api/sessions/{id}/turns/{turnId}/observation`을 5초마다 호출한다. 세션 접근 토큰이 필요하며 답변 중인 턴만 허용한다. 이 API는 측정값을 해석할 뿐 DB에 폴링 결과를 누적하거나 LLM을 호출하지 않는다. 답변 제출 때 같은 규칙으로 최종 근거를 저장한다.

우선순위는 모순 확인 → 현재 목표 누락 → 빠른 말하기 → 손·얼굴 → 고개 숙임 → 좌우 기울기 → 앞으로 숙임 → 흔들림이다. 팁은 한 번에 하나, 6초 표시, 다음 팁까지 최소 20초다. 같은 턴의 동일 근거는 재표시하지 않는다. 요청 제한 시간은 4초이며 일시정지·AI 발화·턴 변경 때 진행 중인 요청과 늦게 도착한 결과를 버린다.

Chrome 실시간 전사의 말속도는 경과 10초·한글 40음절 이상에서 8.5음절/초를 넘을 때만 안내한다. 경과 시간 기반 추정이므로 실측 점수에는 쓰지 않는다. 실시간 성량·침묵 지적은 보정된 측정 경로가 없어 아직 연결하지 않았다. 녹음 종료 후 실제 오디오의 속도·멈춤은 3단계 점수에서 별도로 분석한다.

답변 후에는 같은 공통 근거 중 하나를 현재 페르소나의 프롬프트에 전달한다. 표정·감정·성격 지적은 금지한다. 같은 규칙의 역할 지적은 한 턴 간격을 두며, 이미 재질문을 소진한 목표는 다음 대사에서 다시 강요하지 않는다. 면접은 피드백 한마디와 준비된 주요 질문을 분리해 주요 질문을 임의 변경하지 않는다.

명확한 모순은 실제 앞뒤 인용을 넣은 확인 질문을 한 번 추가한다. 확인 질문은 주요 질문 수나 목표 재시도 수에 포함하지 않는다. 마지막 주요 질문에서 모순이 나와도 확인 답변까지 받은 후 종료한다. 감점 복구·취소는 구현하지 않았다. 대사 생성 API 실패 시 준비된 목표 질문을 사용하고 `dialogue_status=fallback`으로 기록한다.

'연습 종료' 버튼은 이제 실제 종료 API를 호출하고 제출된 답변으로 결과를 만든다. 아직 제출하지 않은 입력은 결과에 포함하지 않는다.

### 검증 범위와 후속 확인

자동 검증은 인용 검증·중복·점수 상한·미측정·목표 진행·면접 확인 질문·API 오류와 Chrome의 팁 표시·일시정지·수동 종료를 다룬다. 외부 LLM 응답은 모의 응답, 브라우저 카메라·마이크는 가상 장치로 검증했다. 전시 장비에서 실제 목소리·자세의 오탐과 한국어 LLM 판단을 추가 확인해야 한다.

새 면접 시나리오의 6~12개 질문 등록, E5 예시 비교, 신규 표정·자세 모델, 마이크 기준 성량 연결은 별도 준비 작업이다. 기존 로그인·DB 구조나 보관 기간을 이번에 새로 구현한 것은 아니다.

의미 분석 장애로 재시도까지 소진한 목표는 사용자 미달인 `unmet`과 구분해 `unverified`로 남긴다. 이 경우 종료 사유는 `analysis_unavailable`이며 장애를 감점하지 않는다.
