# 시나리오 품질 검증 프로토콜 — 상호 플레이테스트 & 예비 human agreement

> 상태: 확정(2026-07-31) · 작성 2026-07-31
> 관련 스펙: S-B2B-007 (임시 ID) · 연관: S-B2B-107(직무별 시나리오), S-B2B-117(judge 3겹), [점수 표기 방침](score-display-policy.md), [AI 아키텍처](ai-architecture.md)
> 적용 시점: 시나리오 작성 착수(2026-08-04) 이후, 각 시나리오의 초안이 플레이 가능해진 시점부터

---

## 1. 목적

두 가지를 한 번의 세션 설계로 얻는다.

1. **대화 품질 검증** — "AI 응대가 부자연스러운 지점"을 체계적으로 수집해 시나리오·대화 엔진을 고친다.
2. **채점 신뢰도의 예비 근거** — 같은 세션 녹취를 사람 여럿이 채점해 Krippendorff's alpha를 산출, [점수 표기 방침](score-display-policy.md)의 전환 조건(α ≥ 0.667 잠정 기준) 판단 재료를 만든다.

## 2. 상호 플레이테스트 절차

### 구성

- **2인 1조** — 플레이어(수강생 역) 1명 + 기록자 1명. 회차마다 역할을 교대한다.
- **직무별 시나리오 각 2회** — 3직무(카페 크루·고객센터·사무행정) × 2회 = 조당 최소 6회. 1회차는 "성실한 답변", 2회차는 "미숙·회피형 답변"으로 플레이해 감정 상태 전이의 양 극단을 모두 건드린다.
- 플레이는 실제 수강생 조건과 동일하게(음성 입력, 미러 화면) 진행한다. 녹취(음성+전사)는 agreement 채점 세션에 재사용하므로 반드시 남긴다.

### 기록 양식 — "부자연 지점 로그"

기록자는 플레이 중 아래 표를 실시간으로 채운다. 한 줄 = 부자연 지점 하나.

| 시각 | 시나리오 | 턴 | AI 발화(요지) | 부자연 사유 | 심각도 | 조치 |
|---|---|---|---|---|---|---|
| 14:02 | 카페 크루-컴플레인 | 3 | "고객님의 말씀에 유감입니다" | 번역투, 크루 화법 아님 | 중 | 템플릿 문구 교체 |
| 14:05 | 카페 크루-컴플레인 | 5 | 사과 후 갑자기 평온 톤 | 감정 전이 급락(격앙→평온 직행) | 상 | 전이 규칙에 완화(eased) 경유 강제 |

**부자연 사유 분류(택1 + 자유 서술):**

- `화법` — 직무·인물에 안 맞는 말투(번역투, 과공손, 반말 등)
- `맥락` — 직전 턴과 안 이어지는 응답, 했던 말 반복
- `감정` — 감정 상태와 발화 톤의 불일치, 전이가 급격하거나 안 일어남
- `세계관` — 카페 온도 설정(메뉴·인물·절차) 위반
- `평가` — 명백히 좋은/나쁜 답변인데 판정 케이스가 어긋남

**심각도 정의:**

| 심각도 | 기준 |
|---|---|
| **상** | 몰입이 깨진다 — 데모·수강생 앞에서 나오면 안 되는 수준 |
| **중** | 어색하지만 흐름은 이어진다 |
| **하** | 눈치채는 사람만 눈치채는 수준 |

## 3. 수정 반영 기준

- **상**: 다음 플레이테스트 전까지 수정. 수정 없이는 해당 시나리오를 "데모 가능"으로 표시하지 않는다.
- **중**: 같은 지점이 **2회 이상 다른 조에서 재현**되면 수정 대상으로 승격. 1회 발생은 백로그.
- **하**: 백로그. 여유 시 일괄 처리.
- 모든 수정은 재플레이 1회로 재현 소멸을 확인한 뒤 닫는다. 로그 원본은 삭제하지 않고 조치 열에 결과를 남긴다.

## 4. 예비 human agreement 채점 세션 연계

### 절차

1. 플레이테스트에서 녹취한 세션 중 **직무별 대표 세션**을 고른다(잘한 회차·미숙한 회차가 섞이도록).
2. **팀원 2인 + 지인 1인**(제작에 관여하지 않은 외부 시선)이 **같은 녹취를 같은 루브릭으로 독립 채점**한다. 채점 중 상호 논의 금지 — 논의하면 alpha가 오염된다.
3. 루브릭은 시스템 judge가 쓰는 것과 동일한 항목·척도를 사용한다([AI 아키텍처](ai-architecture.md) §4). 사람과 시스템이 다른 자로 재면 비교가 성립하지 않는다.
4. 채점 결과로 Krippendorff's alpha를 산출한다 — 사람 간 alpha가 먼저다. 사람끼리 일치하지 않는 루브릭 항목은 시스템 채점을 논하기 전에 루브릭부터 고친다.

### 산출 스크립트 사용 안내

`poc/backend/scripts/measure_agreement.py` **(작성 예정 — 현재 저장소에 없음, S-B2B-117의 일부로 신규 작성)**

의도된 사용법:

```bash
cd poc/backend
./.venv/bin/python scripts/measure_agreement.py ratings.csv
# Windows 전시 PC: PYTHONUTF8=1 환경변수 필요 (WINDOWS-SETUP.md 참조)
```

- 입력 `ratings.csv`: 행 = 채점 대상(세션×루브릭 항목), 열 = 채점자(rater1, rater2, rater3), 값 = 항목 점수. 결측 허용.
- 출력: 전체 alpha + 루브릭 항목별 alpha. 항목별 값이 낮은 곳이 루브릭 수선 지점이다.
- 판정 기준: [점수 표기 방침](score-display-policy.md) §5 — α ≥ 0.667 잠정 채택, α ≥ 0.800 신뢰(Krippendorff 관례).

### 결과의 사용처

- 사람 간 alpha가 기준을 넘으면 → 같은 세션에 대한 시스템 judge 점수를 사람 채점과 비교하는 다음 단계로 간다.
- 발표에서는 "예비 측정"임을 명시한다 — 표본이 작으므로 수치를 과장하지 않는다.
