# ADR — NFC 리더 선정(ACR122U ×2) 및 미러 컨셉 UI 확정(C-22)

> 관련 스펙: S-B2B-006 (임시 ID) · 연관: S-B2B-103(NFC issue/resolve), S-B2B-104(발급 키오스크), S-B2B-105(미러 NFC 시작), S-B2B-106(NFC 폴백), [PRD v1](prd-v1.md)

## 결정 1 — NFC 리더: ACR122U 2대

### 상태

**확정.**

### 맥락

B2B 흐름의 물리 접점은 두 곳이다: **발급 키오스크**(카드 발급·등록)와 **미러**(카드 태그로 세션 시작). 전시·운영 환경은 Windows PC이고, 백엔드는 Python(FastAPI)이다. 리더는 이 환경에서 드라이버 문제 없이, 추가 하드웨어 작업 없이 붙어야 한다.

### 결정

**ACR122U 2대**로 확정한다 — 발급 키오스크 1대 + 미러 1대.

### 근거

| 축 | ACR122U |
|---|---|
| 드라이버 | Windows **PC/SC 표준 드라이버** — 별도 드라이버 작업 없이 인식 |
| 라이브러리 | **pyscard 성숙** — Python 백엔드에서 UID 읽기까지의 경로가 검증돼 있다 |
| 수급 | **국내 수급 용이, 3만원대** — 파손·분실 시 당일 대체 가능 |
| 배선 | **USB 단일 케이블** — 전원·데이터 일체, 부스 배선 단순 |

### 기각 대안 — PN532

- PN532는 라즈베리파이 등 **임베디드용 모듈**이다. Windows 전시 PC 구성에서는 USB 변환·드라이버 확보·케이싱(노출 기판 보호) 추가 작업이 필요하다.
- 가격 이점이 있더라도, 추가 작업 하나하나가 완성 가능성을 깎는다. 기각.

### 폴백

- 리더 미인식·태그 실패 시 **4자리 코드 수동 입력**(S-B2B-106)으로 동일 흐름을 이어간다. NFC는 편의 계층이지 단일 장애점이 아니다.

## 운영 절차 — 카드 수명주기

카드에는 **개인정보를 기록하지 않는다.** 카드 UID(무의미 식별자)만 서버에서 수강생 계정과 매핑한다. 카드 자체를 습득해도 읽히는 것은 UID뿐이다.

### 등록 (발급)

1. 수강생이 발급 키오스크에서 초대코드로 본인·코호트 확인, PIPA 동의([동의 문구](consent-copy.md)) 완료.
2. 새 카드를 리더에 태그 → UID 판독 → issue API(S-B2B-103)로 **UID ↔ 수강생 계정 바인딩** 등록.
3. 이미 다른 계정에 바인딩된 UID는 등록을 거부한다(중복 발급 방지).

### 재발급

1. 교육 담당자(또는 키오스크 재발급 메뉴)에서 기존 카드의 바인딩을 **비활성화**.
2. 새 카드를 등록 절차대로 바인딩. 계정·세션 이력은 그대로 유지된다(카드는 열쇠일 뿐, 데이터의 그릇이 아니다).

### 분실 처리

1. 신고 즉시 해당 UID 바인딩을 **비활성화** — 이후 그 카드를 태그해도 세션이 열리지 않는다.
2. 분실 카드에는 개인정보가 없으므로 데이터 유출은 없다. 다만 비활성화 전까지는 타인이 대리 세션을 열 수 있으므로, 신고 경로(교육 담당자)를 안내물에 명시한다.
3. 재발급 절차로 새 카드 지급.

## 결정 2 — C-22: 미러 실물 하드웨어 vs 컨셉 UI

### 상태

**확정 — 미러 컨셉 UI 채택, 실물 하프미러 보류.**

### 맥락

"미러" 은유는 제품 정체성의 핵심이다. 이를 실물 하프미러(반투과 거울 + 디스플레이 합착)로 구현할지, 화면 연출(컨셉 UI)로 구현할지가 C-22 결정 항목이었다.

### 결정

**미러 컨셉 UI로 확정한다** — 풀스크린 다크 배경 + 카메라 셀프뷰 오버레이로 "거울 앞에 선 나"를 연출한다. 실물 하프미러는 보류하며, v1 범위에서 제외한다([PRD v1](prd-v1.md) Won't 항목).

### 근거

1. **완성 가능성 20점 보호.** 하프미러+디스플레이 합착은 반사율 튜닝·터치 간섭·설치·운반 리스크가 크다. 실패 시 대체가 없는 단일 하드웨어 리스크를 v1에 지지 않는다.
2. **은유 전달에 실물이 필수가 아니다.** 다크 배경 화면에 비친 셀프뷰는 그 자체로 거울이다. 관람객·수강생이 얻는 경험("내 모습을 보며 연습한다")은 컨셉 UI로 충분히 성립한다.
3. **소프트웨어 자산은 온전히 이식된다.** 컨셉 UI는 기존 mvp 화면 체계 위의 연출 계층이라, 하드웨어 일정과 소프트웨어 일정이 분리된다.

### 보류된 대안 — 실물 하프미러

- 폐기가 아니라 **보류**다. 상설 설치(대학 센터·본사 교육장) 단계에서 내구·휘도 요건과 함께 재검토한다. 재검토 시 이 ADR을 개정한다.
