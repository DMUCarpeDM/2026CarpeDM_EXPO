# Mirror-Ting × Lovable 구조 적용 검토

현재 서비스: `_workspace/mirror-qa-20261009/mvp`. 확인 결과 구조 변경이 가능하다. 이 문서는 화면 선정 및 적용 설계이며 실행 중인 React 화면을 변경한 것은 아니다.

## 유지 범위

- `HomePage.jsx`의 타이틀 문구, 설명, `HeroTypingWord`의 단어·주기·접근성 처리.
- `prompt-home.css`의 Hero 그라데이션 정의와 브랜드 색상.
- `HomeFooter`, 기존 이미지 파일, 서비스 설명 내용과 기존 컴포넌트 디자인 토큰.
- 폰트 패밀리는 유지하되 Lovable의 글자 크기·행간·위계·최대 폭을 참고한다. 디자인 시스템 전체를 교체하면 유지 조건과 충돌하므로 색상·컴포넌트와 레이아웃·타이포그래피를 분리한다.

## 메인 페이지 적용

중앙 Hero → 기존 메인 비주얼 → 설명/예시 2열 섹션 → 기존 4-Fit 이미지·설명 → 하단 프롬프트 CTA → 기존 푸터 순서. Lovable의 고객 수·고객사·후기 같은 미러팅에 근거 없는 콘텐츠는 옮기지 않는다. 현재 4-Fit의 500svh 고정 스크롤 구조는 일반적인 2열 설명 섹션으로 바꿔 전체 페이지 리듬을 맞출 수 있다. 타이핑 효과와 Hero 배경은 보존한다.

## 실제 기능과 연결

현재 `ServiceEntryShell`은 프롬프트 제출 후 `simulation-chat`으로 이동한다. `SimulationChatPage`에는 준비 대화, 조건 확인, 동의와 시작, 실제 연습 단계가 이미 있다. Lovable editor의 화면 분할만 적용하고 이 상태 흐름과 API는 유지한다. 데스크톱은 대화 + 설정/상황 패널, 모바일은 대화 중심에 설정 패널을 별도로 여는 구조다. 코드 탭·데이터베이스·게시·배포 기능은 미러팅에 불필요하다.

로그인 처리는 `AccountPage`의 기존 인증 API를 사용한다. 현재 로그인 성공 콜백은 `setAccount`이며 전용 대시보드로 이동하지 않으므로 로그인 성공 후 홈 전환과 계정별 표시를 별도로 연결해야 한다. 기록은 `ResultsHistoryPage`의 실제 데이터를 사용한다. Lovable 샘플 프로젝트나 샘플 결과를 사용자 기록으로 넣지 않는다.

## 구현 경계와 검증

선정한 HTML 11개를 `pages/`에 보관했다. HTML은 독립 실행 앱이 아니며 `/media`, `/assets` 등의 자산은 기존 클론 미리보기 서버에서 제공한다. `selection.json`에 원본 작업본 경로와 미리보기 URL을 기록했다. React 구현에서는 이 HTML 전체를 삽입하지 않고 현재 컴포넌트에 레이아웃을 이식한다.

현재 `SimulationChatPage.jsx`와 관련 백엔드에는 기존 미커밋 수정이 있으므로 그대로 보존했다. 실제 이식 시 기존 준비 대화·연습 시작·오류·동의 흐름을 회귀 검사하고, 390/768/1440px에서 중앙 정렬·컬럼 전환·가로 넘침을 확인해야 한다. 스마트 미러 키오스크 전용 분기는 웹 레이아웃 변경에서 제외한다.

Lazyweb 탐색은 HTTP 429 제한으로 실패했다. 신규 Growth Report는 생성되지 않았다. 판단에는 기존 수집 화면과 현재 소스 코드를 사용했다.
