# 10/7 Voice·Expression 연결 판단

이 작업은 `88e3d0c`의 통합 결과에서 이어지는 로컬 브랜치 `codex/expo-oct7-measurement-status`다. 계산·가감점·동의·보관 정책을 바꾸지 않고, 현재 제공할 수 있는 결과와 보류 이유를 화면에 표시한다.

## Voice는 이미 연결되어 있다

새 세션에는 `voice-measure-v2`가 설정된다. 답변 WAV와 마이크 보정·입력 설정을 확인한 뒤 측정값을 `rapport.voice_measurements`에 답변별로 저장하고, 최종 보고서의 `speech_stats.voice_analysis`로 전달한다. UI `VoiceMeasurements`는 크기·속도·멈춤과 높낮이·발성 불규칙성 참고값 및 항목별 측정 불가 이유를 표시한다. 재처리는 같은 답변을 교체하며 미저장·보관 기한의 전사 파기는 기존 정책을 따른다.

`docs/voice-engine-implementation-2026-09-22.md`는 검증된 감점 기준이 없으면 음성 점수를 null로 두도록 명시한다. `interaction_scoring.audio_events()`도 v2 측정값을 점수 사건으로 만들지 않는다. 점수 연결 누락으로 해석하거나 이전 임계값·기본 75점을 되살리면 이 정책을 위반한다.

오늘 수정은 유효 측정 항목이 하나도 없는 결과에 “측정 기록 제공”과 “크기·속도·멈춤을 기록했어요”를 표시하던 문구를 바로잡는다. 부분 성공은 유효 항목을 유지하고, 나머지는 기존 사유·null 상태를 유지한다. 기존 세션의 점수는 변경하지 않는다.

## Expression을 오늘 점수로 연결할 수 없는 이유

구형 `nonverbal.score_expression()`은 blendshape 집계와 임시 밴드를 사용한다. 현재 공통 판단 `judgments.evaluate()`는 표정을 측정 영역으로 등록하거나 표정 사건을 만들지 않는다. `interaction_report.prepare()`는 공통 판단에서 점수가 없는 구형 행을 제거하므로 새 체험의 표정 점수는 null이다.

최신 합의 `docs/superpowers/specs/2026-09-11-4fit-latest-agreements.md`와 표정 학습 설계는 다음 조건을 요구한다.

- 검증된 미소·눈썹 찌푸림·눈썹 올림·눈 크게 뜸·무표정의 다섯 출력. 감정·태도·의도 추정과 입술 누름은 제외한다.
- 라벨별 검증 기준값과 미확인 상태. 다른 움직임이 없다고 무표정으로 채우지 않는다.
- 0.5초 연속 감지, 0.5초 미만 끊김 연결, 미검출·가림의 구간 분리. 연결된 미감지 시간을 지속시간으로 합산하지 않는다.
- 실제 모델 출력→시간 구간→보고서 관찰 연결, 시나리오 가감점·유효 측정량의 별도 확정과 현장 검증. 실시간 표정 지적은 만들지 않는다.

현재 답변 페이로드의 blendshape 비율과 2초 timeline은 이 다섯 출력·시간 계약을 충족하지 않는다. 프로젝트 `app/ai/assets`에는 자세 ensemble 자산이 있고 승인된 새 표정 모델은 확인되지 않았다. 임시 표정 점수나 진정성·긴장 해석을 복원해 네 영역 완성으로 설명하지 않는다. 오늘은 API summary에 정확한 보류 이유를 추가하고 미측정 카드에 이 문구를 표시한다. 새 분석·영상 저장·외부 전송은 추가하지 않는다.

## E5 확인과 오늘 가능한 다음 단계

프로젝트 문서와 설정이 가리키는 `poc/backend/models/response_e5_v1/final/`을 작업 checkout, 기존 GitHub checkout, 기존 Downloads checkout에서 확인했다. 세 경로 모두 없다. 다른 모델·개인 폴더를 검색하거나 다운로드하지 않았다. 팀 담당자가 최종 가중치와 해당 버전·검증 근거를 제공해야 한다.

현재 직장 공통 Response 판단은 `response_judgment.analyze()`의 OpenAI 근거 분석을 사용한다. E5를 준비하는 것만으로 이 API의 키·호출 준비를 대체하지 못한다. E5 예시 매칭과 새 표정 모델 연결은 별도 경로다.

오늘 가능한 인수는 승인된 실제 녹음으로 마이크 보정→WAV 업로드→각 항목 측정 상태→보고서 null 점수·사유→키오스크 출력 보존을 확인하는 것이다. 실제 사람·소음·마이크·유료 호출 검사는 이 로컬 작업에서 수행하지 않는다. Voice 점수 활성화와 새 Expression 모델·점수 정책 도입은 검증 근거와 팀의 실제 결정이 필요하다.

## 이번 변경의 집중 검증

backend `test_voice_api_v2.py`, `test_interaction_scoring.py`, `test_expression.py`, `test_judgments.py`의 30개가 통과했다. 마이크 보정 권한·입력 변경·원문 파기·기존 점수 계약을 포함한다. UI 보고서·공유 unit 10개, Chrome 가상 오디오 브라우저 2개와 production build가 통과했다. 브라우저에서 유효 측정→미측정/불확실한 전사→녹음 없음의 표시와 표정 보류 사유를 확인했다.

최초 unit·브라우저 혼합 Node 프로세스는 결과 없이 멈춰 해당 검사 프로세스만 종료했다. 이를 통과로 세지 않는다. unit과 브라우저 파일을 각각 실행한 위 결과를 최종 증거로 사용한다. 이전 609개 backend·190개 UI 전체 결과는 `88e3d0c`의 증거이며 이번 변경 후 전체를 다시 실행했다는 뜻이 아니다.
